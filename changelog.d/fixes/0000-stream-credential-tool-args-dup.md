- **fix(streaming):** a streamed tool call no longer re-sends argument text the client already received. The credential masker holds back a trailing window (512 bytes) so a credential split across frames can still be recognised, and flushes what is left when the stream ends. That flush frame is a clone of the last frame that streamed, and it appended the residual to the clone's existing `tool_calls` instead of replacing them — so the client got the bulk of the arguments twice: once when they streamed, once more inside the closing frame. Any client that reassembles deltas by concatenation (the OpenAI streaming contract) therefore saw invalid JSON and could not run the tool. Short arguments that fit inside one window were unaffected, which is why small tool calls looked fine. Reported as #18012.
