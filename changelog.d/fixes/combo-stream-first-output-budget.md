- **fix(combo):** a streaming target that opens the response and then produces nothing no longer holds the whole combo. The per-target budget now bounds the time to the first output frame instead of the time to response headers, so a silent upstream is abandoned and the combo falls over to its next model; token generation that has started still streams to completion untouched. Output is judged with the same predicate TTFT uses, so this gateway's own keepalive frames (`response.in_progress`, `event: progress`) never count as an answer. A stream that closes without output, or loses a hedge race, goes back with its body unread, so empty-turn checks and the client see the same bytes as before. A target that declares a longer budget (connection `timeoutMs`, then the registry's per-model `timeoutMs`, then its provider-level `timeoutMs`, e.g. Codex xhigh or GLM) gets that much time for its first output; a declared value never shortens the wait. An explicit combo `targetTimeoutMs` still overrides all of them.
