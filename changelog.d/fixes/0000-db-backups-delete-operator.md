- **fix(security):** pruning stored backups now requires an operator credential, exactly like restoring one. `DELETE /api/db-backups` (cleanup — keep the latest N / drop older than D days) accepted any `manage`-scoped API key, so a machine credential handed to automation could delete every restore point but one; `PATCH /api/db-backups` (retention settings) is gated too, because the values it persists are what the automatic pruning applies after every backup — a `keepLatest: 1` saved by a machine credential would have emptied the backup directory on the next snapshot. Both handlers now go through the same `requireOperatorCredential()` boundary as the restores: a signed-in dashboard session, the local CLI credential or an instance with login disabled pass; API keys of any scope and `oma_` access tokens get `403` with the retention settings and the stored backups untouched; a missing credential stays `401`. Listing (`GET`) and creating a manual backup (`PUT`) keep ordinary management auth ([#16899](https://github.com/diegosouzapw/OmniRoute/pull/16899) is the precedent).
