- **fix(streams):** the active-stream watchdog no longer enforces one global wall-clock cap borrowed from whichever provider registers the longest budget. It was a fixed 21 minutes, derived from the Codex models' 20-minute `timeoutMs`, and it applied to every target — including providers that declare no budget at all, whose healthy long answers were cut mid-stream with no terminal event. Each request is now bounded by a budget its own target declared: a connection-level `timeoutMs` override or the registry's per-model `timeoutMs`, plus the same one-minute margin, clamped to the timer range. `STREAM_ACTIVE_TIMEOUT_MS` remains an operator override — a positive value forces one global cap, `0` disables the watchdog (now the default).
  - **Trade-off, stated so nobody has to rediscover it:** a target that declares no budget now has no total-lifetime bound. The byte-stall watchdog still reaps a stream that goes silent, and the first-content watchdog still reaps one that never produces real output, but a stream that keeps emitting lifecycle or heartbeat bytes forever without a terminal event is bounded only by the client — the shape #12913 added the global cap for. An operator who needs that bound back sets `STREAM_ACTIVE_TIMEOUT_MS` to a positive value, which then applies to every target.
