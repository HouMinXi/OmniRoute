- **fix(streams):** the active-stream watchdog no longer cuts off a target whose own declared budget is longer than the global 21-minute cap (`STREAM_ACTIVE_TIMEOUT_MS`, default 1260000). GLM declares a 50-minute provider-level `timeoutMs`, and a connection can declare its own, but both were killed at 21 minutes mid-answer with no terminal event. The cap a request gets is now the larger of the global value and its target's declared budget (connection, then per-model, then provider-level) plus the one-minute margin, clamped to the timer range. A declared budget can only raise the cap; targets that declare nothing keep the 21-minute bound #12913 added for endless streams, and `STREAM_ACTIVE_TIMEOUT_MS=0` still disables the watchdog for every target.
