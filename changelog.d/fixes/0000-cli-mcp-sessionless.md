- **fix(cli):** MCP-backed CLI commands (`mcp call`, `combo suggest`, `compression`, `oneproxy`, `resilience`, `skills`) no longer require a `Mcp-Session-Id` after `initialize`, so they keep working against a stateless Streamable HTTP handler: they send `notifications/initialized`, attach the session header only when the server issued one, and `DELETE` the session (tolerating 405) only after the response has been fully read. `tools/call` is never retried, so a slow or failing tool is no longer run twice. `mcp call` now uses the shared client and therefore honours an explicit `--timeout`, else `OMNIROUTE_HTTP_TIMEOUT_MS`, else 30 s, each covering a request until its response starts (a `--stream` body is not cut off); `--timeout 0` means no client-side deadline (whereas `OMNIROUTE_HTTP_TIMEOUT_MS=0` keeps the shared CLI rule and means 30 s), values above 2147483647 ms are clamped to that limit instead of aborting after 1 ms, and anything that is not a plain non-negative integer (blank, surrounding whitespace, leading zeros such as `00`, signs, units, decimals) prints a warning and falls back; it also honours `--base-url`, `--context` and `--api-key`. Session `DELETE` uses a fixed 3 s timeout; a tool result with `isError` now prints `MCP error: <text>` to stderr and exits 1 (previously stdout, exit 0); `--scope` was never used and now prints a deprecation warning. HTTP failures read `MCP <method> failed: HTTP <status> — <body>` and keep `err.status` (the compression REST fallback on 404/501 is unchanged); JSON-RPC errors keep `err.code`. No `MCP-Protocol-Version` header is sent, and the unused `X-MCP-Scopes` header is removed. Refs #17131.
