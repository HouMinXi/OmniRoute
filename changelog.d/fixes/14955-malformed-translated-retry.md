- **fix(sse):** a non-streaming `502` built after the upstream already answered HTTP 200 with a body that translated into no usable output (`upstream_empty_response`, `upstream_response_failed`, `upstream_fake_success`, all typed `upstream_response_error`) is no longer replayed on the same account by the single-model pre-output transport retry. That retry exists for connection resets before any response; here the upstream call was already made, so the replay only paid for the same verdict twice. Genuine pre-output 502/503/504/507 transport failures keep their one same-account retry.
