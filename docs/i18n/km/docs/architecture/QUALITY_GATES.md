## សារពើភ័ណ្ឌ Gate និងប្រូហ្វាល់ប្រតិបត្តិការ

### ការទទួលយកបេក្ខភាព

Workflow CI និង Quality Gates នីមួយៗបញ្ចេញសេចក្ដីសម្រេចដែលមានស្ថិរភាព៖ `Gate / CI` និង
`Gate / Quality`។ គោលការណ៍ទទួលយកដែលមានកំណែរបស់វា រាយបញ្ជី job ខាងដើមនីមួយៗ
ថាជា required ឬ advisory។ job ដែលជា required និងអាចអនុវត្តបាន ត្រូវតែជោគជ័យ៖ លទ្ធផល
ដែលបាត់ cancelled, skipped, pending និង unknown មិនអាចបញ្ជាក់ PASS បានទេ។ ការចាត់ថ្នាក់
docs-only ឬ catalog-only ដែលមានសុពលភាព អាចធ្វើឱ្យ code lane មិនអាចអនុវត្តបាន;
draft PR មិនមែនជាបេក្ខភាពដែលត្រូវបានទទួលយកទេ។ ស្លាក `hotfix` មិនលើកលែងតម្រូវការភស្តុតាងឡើយ។

Workflow ទាំងពីរគ្របដណ្ដប់លើ PR និង push ទៅកាន់ branch main/release, manual dispatch និង
merge-group event។ Push, dispatch និង merge-group ដំណើរការជម្រើសពេញលេញ។ Fork
និង merge group ប្រើ hosted runner សម្រាប់ job ដែលតាមធម្មតាជ្រើសរើស self-hosted
runner; ត្រូវតែផ្ទៀងផ្ទាត់ថាមាន hosted capacity គ្រប់គ្រាន់ មុនពេល rollout។

JSON receipt នីមួយៗកំណត់អត្តសញ្ញាណ SHA ដែលបាន check out, workflow run និង attempt។
CLI បដិសេធនៅពេល checkout/event SHA មិនត្រូវគ្នា។ ការធ្វើតេស្ត workflow ភ្ជាប់សមាជិកភាពគោលការណ៍
ទៅនឹងបញ្ជី `needs` របស់ verdict job ដូច្នេះ lane ថ្មី ឬ lane ដែលបានដកចេញ មិនអាចបាត់ដោយស្ងាត់ៗបានទេ។
Receipt គ្របដណ្ដប់តែ workflow របស់វាប៉ុណ្ណោះ មិនគ្របដណ្ដប់លើ publication, deployment ឬផ្នែកខាងក្នុង
របស់ advisory scanner ដែលមានស្រាប់ទេ។ ការធ្វើឱ្យឈ្មោះ check ទាំងពីរសកម្មក្នុង branch rule គឺជា
ការផ្លាស់ប្ដូរផ្នែករដ្ឋបាលដាច់ដោយឡែក; ការបន្ថែម job ទាំងនេះមិនការពារ branch ដោយខ្លួនឯងទេ។

### សារពើភ័ណ្ឌ Static scan

សារពើភ័ណ្ឌ npm-alias ដែលមានកំណែ និងសមាជិកភាព static-scan ស្ថិតនៅក្នុង
`config/quality/gate-manifest.json`។ ដំណើរការ `npm run check:gate-manifest` ដើម្បីផ្ទៀងផ្ទាត់
ឈ្មោះ script និង command ពិតប្រាកដធៀបនឹង `package.json`; ការបន្ថែម ការដកចេញ និង
ការប្រែប្រួល command នឹងធ្វើឱ្យទាំង local hook និង change-classification job នៅក្នុង CI បរាជ័យ។
alias មិនមែនជា workflow job, matrix instance ឬ test case ទេ៖ ចំនួនទាំងនេះមិនត្រូវបានបង្ហាញ
ថាអាចប្រើជំនួសគ្នាបានឡើយ។

ប្រើ `npm run quality:scan -- --list` ឬ `npm run quality:scan:fast -- --list`
ដើម្បីពិនិត្យ alias ដែលបានជ្រើសរើស ដោយមិនប្រតិបត្តិពួកវា។ runner ហៅ npm entrypoint
ដូច្នេះ runtime របស់វា (រួមទាំង Bun នៅកន្លែងដែលបានកំណត់រចនាសម្ព័ន្ធ) ត្រូវបានរក្សាទុក។
manifest កត់ត្រា alias ដែលនៅក្រៅប្រូហ្វាល់ទាំងនោះថាត្រូវបានហៅដោយឡែក ហើយ
maintenance command ត្រូវបានហាមឃាត់ក្នុងប្រូហ្វាល់ scan ដែលជា read-only។

ប្រូហ្វាល់ទាំងនេះគ្របដណ្ដប់តែ static scan ប៉ុណ្ណោះ។ ពួកវាមិនបញ្ជាក់ product test,
coverage, packaging, external check ឬការទទួលយក release ពេញលេញរបស់បេក្ខភាពឡើយ។
ការទទួលយក workflow ប្រើ `config/quality/admission-policy.json` ដែលបានភ្ជាប់ និង
`scripts/quality/admission-verdict.mjs`។ ប្រូហ្វាល់ release-observer នៅតែដាច់ដោយឡែក;
សូមពិនិត្យ check និង receipt ដែលអាចអនុវត្តបានរបស់ពួកវាដោយឯករាជ្យ។ សារពើភ័ណ្ឌ
ជាអត្ថបទខាងក្រោមគឺជាឯកសារយោង មិនមែនជាភស្តុតាងថា gate បានដំណើរការពិតប្រាកដទេ។

Script ស្ថិតនៅក្រោម `scripts/check/` (policy gate) និង `scripts/quality/` (ratchet engine)។
ប្រភពសច្ចៈរបស់ CI គឺ `.github/workflows/ci.yml`។

### ផ្លូវលឿនសម្រាប់ Release PR (`quality.yml`)

`.github/workflows/quality.yml` បំពេញបន្ថែម CI លើ main/release PR, protected-branch
push, dispatch និង merge group។ PR ប្រើ fast check ដែលច្រោះតាម path។ duplicate build ដែលបាន
បិទជាអចិន្ត្រៃយ៍ត្រូវបានដកចេញ; build/package/boot check ពិតប្រាកដនៅតែមានក្នុង CI។

| Job                                              | វិសាលភាព                                                                                                                                                                                                         | ការទប់ស្កាត់         |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| `Docs Gates (fast-path)`                         | Docs/code PR; API docs refs និង docs-all                                                                                                                                                                         | បាទ/ចាស              |
| `Fast Quality Gates`                             | Code PR; static check, typecheck, dashboard typecheck, impacted unit test                                                                                                                                        | បាទ/ចាស              |
| `Forgotten sibling tests`                        | Code PR; module ដែលបានផ្លាស់ប្ដូរ ត្រូវបានតាមដានទៅកាន់ static consumer និង candidate sibling test; barrel និង dynamic-import path ត្រូវបានរាយការណ៍ជា advisory diagnostic ជាមួយនឹង referenced allowlist exception | **Advisory**         |
| `Vitest (fast-path)`                             | Code PR; fast vitest suite                                                                                                                                                                                       | បាទ/ចាស              |
| `Unit Tests fast-path`                           | Code PR; 4-shard unit suite                                                                                                                                                                                      | បាទ/ចាស              |
| `No new ESLint warnings`                         | Code PR; lint guard ដែលយល់ដឹងអំពី suppression                                                                                                                                                                    | បាទ/ចាស រួមទាំង fork |
| `Merge integrity (changelog + generated skills)` | PR ដែលមិនមែនជា draft; changelog និង generated skill sync                                                                                                                                                         | បាទ/ចាស រួមទាំង fork |

#### របាយការណ៍ Forgotten sibling tests

`npm run check:forgotten-sibling-tests` ប្រើ import resolver ដែលនៅពីក្រោយ test-impact map ឡើងវិញ។
សម្រាប់ production module នីមួយៗដែលបានផ្លាស់ប្ដូរ វារាយការណ៍ខ្សែទំនាក់ទំនង
`changed module/symbol -> static consumer -> candidate sibling test` ដែលមានលក្ខណៈ deterministic នៅពេល candidate

## បន្ទាត់គោល Ratchet (`quality-baseline.json`)

ម៉ាស៊ីន ratchet (`scripts/quality/check-quality-ratchet.mjs`) អាន `quality-baseline.json`
ហើយប្រៀបធៀបវាជាមួយ `quality-metrics.json` ដែលទើបតែបានប្រមូល។ Metric ណាមួយដែលថយចុះ
លើសពី epsilon របស់វា នឹងធ្វើឱ្យ build បរាជ័យ។

Metrics ដែលកំពុងត្រូវបានតាមដាន៖

| Metric                | ទិសដៅ  | អត្ថន័យ                                     |
| --------------------- | ------ | ------------------------------------------- |
| `eslintWarnings`      | `down` | ចំនួនការព្រមាន ESLint មិនត្រូវកើនឡើងទេ      |
| `coverage.statements` | `up`   | Coverage របស់ statement មិនត្រូវធ្លាក់ចុះទេ |
| `coverage.lines`      | `up`   | Coverage របស់បន្ទាត់មិនត្រូវធ្លាក់ចុះទេ     |
| `coverage.functions`  | `up`   | Coverage របស់ function មិនត្រូវធ្លាក់ចុះទេ  |
| `coverage.branches`   | `up`   | Coverage របស់ branch មិនត្រូវធ្លាក់ចុះទេ    |

ដើម្បីធ្វើបច្ចុប្បន្នភាពបន្ទាត់គោល បន្ទាប់ពីមានការកែលម្អពិតប្រាកដ៖

metric ដោយមិនធ្វើបច្ចុប្បន្នភាពបន្ទាត់គោល នឹងត្រូវបានរកឃើញដោយ `--require-tighten` (ដំណាក់កាល 6A.5,
