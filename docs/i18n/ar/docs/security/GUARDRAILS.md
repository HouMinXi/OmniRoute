تفرض الحواجز (Guardrails) السلامة والسياسة وتحويلات المحتوى عند الحدود
بين OmniRoute ومقدمي الخدمة المصدر. يمكن لكل حاجز فحص (ورفض أو تحويل أو إضافة تعليق اختياريًا) حمولات الطلبات (`preCall`)
واستجابات المصدر (`postCall`).

النظام **مفتوح عند الفشل (fail-open)**: إذا ألقى حاجز خطأ أثناء التنفيذ، فإن السجل
يسجل الخطأ ويستمر مع الحاجز التالي بدلاً من إفشال الطلب.
المنع هو قرار صريح (`block: true`)، وليس حادثًا أبدًا.

## ضوابط الحماية المضمّنة

يحمّل السجل تلقائيًا ستة ضوابط حماية حسب ترتيب الأولوية عند الاستيراد
(راجع `registry.ts` → `registerDefaultGuardrails()`):

| الأولوية | الاسم               | المرحلة (المراحل) | الملف                 |
| -------- | ------------------- | ----------------- | --------------------- |
| `5`      | `vision-bridge`     | `preCall`         | `visionBridge.ts`     |
| `6`      | `audio-bridge`      | `preCall`         | `audioBridge.ts`      |
| `7`      | `video-bridge`      | `preCall`         | `videoBridge.ts`      |
| `10`     | `pii-masker`        | `pre` + `post`    | `piiMasker.ts`        |
| `20`     | `prompt-injection`  | `preCall`         | `promptInjection.ts`  |
| `95`     | `credential-masker` | `pre` + `post`    | `credentialMasker.ts` |

تُشغَّل أرقام الأولوية الأقل **أولًا**.

### جسر الرؤية (`visionBridge.ts`) — جسر الأنماط PR-1

يعترض الطلبات التي تحتوي على صور والموجّهة إلى **نماذج لا تدعم الرؤية**، ثم إما
يعيد توجيه الطلب بالكامل إلى نموذج يدعم الرؤية، أو يستبدل أجزاء الصور
بأوصاف نصية ينتجها نموذج رؤية قابل للتهيئة قبل
الاستدعاء إلى الجهة المنبع. يتيح ذلك لموفري النماذج النصية فقط معالجة
الحمولات متعددة الأنماط بشفافية.

التدفق:

1. التخطي إذا كان النموذج المستهدف يدعم الرؤية بالفعل (ما لم يظهر في
   قائمة الجسر الإلزامي `isVisionBridgeForcedModel`).
2. استخراج أجزاء الصور عبر `extractImageParts(messages)`
   (`visionBridgeHelpers.ts`)، التي تفوّض المهمة إلى **كاشف الوسائط
   الموحّد** `detectMediaParts()` في `open-sse/utils/mediaParts.ts` — وهو
   مصدر الحقيقة الوحيد المشترك مع مرشح توافق التركيبات.
   يقتصر الاستخراج، باستخدام قائمة سماح، على أجزاء المستوى الأعلى ذات الأشكال
   التي تستطيع `replaceImageParts` إعادة إدراجها (عقد الاستخراج↔الاستبدال): صيغة OpenAI
   `image_url`، ومصدر Anthropic المشفّر بـ base64 ذي `source.type:"base64"`، وعنوان URL
   الخاص بـ Anthropic ذي `source.type:"url"`، وصيغة Responses API المسماة `input_image`. أما التطابقات المتداخلة
   والأشكال الدلالية فقط فهي مخصصة لمرشح التركيبات ولا تُستخرج مطلقًا.
   يتم التخطي إذا لم يُعثر على أي منها.
3. تحديد تهيئة وقت التشغيل عبر `resolveVisionBridgeRuntimeSettings()`
   (`src/shared/constants/modalityBridgeDefaults.ts`): تكون الأولوية لمفاتيح إعدادات `modalityBridge*`
   الجديدة؛ بينما تبقى مفاتيح `visionBridge*` القديمة **خيارًا احتياطيًا لدورة
   واحدة** (نافذة التراجع). يتم التخطي قبل أي اجتياز للوسائط عندما يكون
   الجسر معطّلًا.
4. يحدد منتقي الوضع (`modalityBridgeVisionMode`، راجع الجدول أدناه)
   إعادة التوجيه مقابل الوصف. تُرجع إعادة التوجيه `modifiedPayload` مع تبديل `model`
   فقط، بالإضافة إلى بيانات وصفية `{ rerouted, fromModel, toModel, imagesKept }`.
5. مسار الوصف: يحدّ عدد الصور عند `maxImages`، وينشئ المطالبة المدركة للمهمة،
   ويراجع ذاكرة التخزين المؤقت للأوصاف، ويستدعي نموذج الرؤية **بالتوازي**
   (`Promise.allSettled`)، ويدرج أجزاء نصية من الشكل `[الصورة N]: <الوصف>` في
   مواضعها. ينتج عن فشل الوصف `null` ويُحتفظ بجزء الصورة الأصلي
   **دون تغيير** (#4012) — باستثناء مسار وصف التركيبات عندما تفشل
   جميع عمليات الوصف، حيث تتلقى الجهة المنبع التي تأكد أنها لا تدعم الرؤية عنصرًا نائبًا
   `(غير متاح — لا يوجد موفر يدعم الرؤية متصل)` بدلًا منه (#8430).
6. إرجاع `modifiedPayload` مع البيانات الوصفية (`imagesProcessed`، و`descriptions`،
   و`processingTimeMs`، و`visionModel`).

#### منتقي الوضع (`modalityBridgeVisionMode`)

| الوضع      | الافتراضي | السلوك                                                                                                                                                                                                                                                    |
| ---------- | --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`     | ✔         | الاستدلال القديم دون تغيير (#6640/#7204): تُعاد توجيه النماذج غير المركبة/نماذج `auto/` إلى أفضل نموذج رؤية، ما لم يكن النموذج الأصلي يمتلك بيانات اعتماد قابلة للاستخدام (وعندها يُستخدم الوصف)؛ أما الأهداف المركبة فتستخدم الوصف دائمًا.               |
| `describe` |           | استخدام الوصف دائمًا — تُتخطى كتلة إعادة التوجيه بالكامل؛ ويجيب النموذج الذي اختاره المستخدم دائمًا.                                                                                                                                                      |
| `reroute`  |           | فرض إعادة التوجيه: يُتجاوز حاجز الاحتفاظ بالنموذج ذي بيانات الاعتماد. يظل حاجز بيانات اعتماد **هدف** إعادة التوجيه مطبقًا — فعندما لا يتوفر هدف رؤية قابل للاستخدام، ينتقل الطلب إلى الوصف حتى لا تصل الصور الخام أبدًا إلى واجهة خلفية نصية فقط (#8430). |

تنهي الأوضاع الإلزامية المسار مبكرًا **قبل** تشغيل استدلال الوضع التلقائي؛ ويكون سلوك `auto`
مطابقًا بايتًا ببايت لضابط الحماية السابق لـ PR-1.

#### نطاق مفتاح API (`visionBridgeKeyScope.ts`)

عندما يقيّد مفتاح API الخاص بالمتصل `allowedConnections` أو مجموعات الحصص
(`allowedQuotas`) أو النماذج (`allowedModels` / `blockedModels` /
`modelAccessMode: "restricted"` / `disableNonPublicModels`)، لا يختار الجسر
لنماذج إعادة التوجيه والوصف سوى النماذج التي يسمح المفتاح باستخدامها، وعبر الاتصالات التي يسمح المفتاح
باستخدامها. بعد ذلك يمر استدعاء الوصف دائمًا عبر الحلقة الذاتية لـ OmniRoute مع
ترويسة `x-omniroute-self-loop-key-id`، بحيث يعيد طلب الدردشة المستقبِل
فرض سياسة الاتصال والنموذج الخاصة بذلك المفتاح. لا يعتمد `enforceApiKeyPolicy()`
تلك الترويسة إلا مع رمز الحامل الخاص بالحلقة الذاتية، ولذلك لا يمكنها إلا
تضييق الوصول، ويُرفض أي معرّف لا يمكن حله.

إذا لم يكن أي نموذج رؤية مسموحًا به للمفتاح، يتنحى مسار الوصف جانبًا
ويمر الطلب دون تغيير، وهو سلوك الفتح عند الفشل نفسه المستخدم عند تعطيل
ضابط الحماية (البيانات الوصفية `{ skipped: true, reason: "no_permitted_vision_model" }`).
تتصرف الطلبات التي لا تحتوي على مفتاح، والمفاتيح التي لا تتضمن هذه القيود، بالطريقة نفسها تمامًا
كما كانت من قبل.

#### مطالبة الوصف المدركة للمهمة (`modalityBridgeVisionTaskAware`)

القيمة الافتراضية **true**. تُلحق `composeVisionPrompt()` ‏(`visionBridgeHelpers.ts`)
نص **آخر رسالة للمستخدم** (مقتطعًا إلى 500 حرف) بموجّه الوصف الأساسي،
ما يوجّه الوصف نحو ما طلبه المستخدم فعليًا (نمط codex-vision-proxy)، ويطلب
من نموذج الرؤية نسخ النص المرئي. عند تعطيل العلامة — أو في حال عدم وجود نص
للمستخدم — يُستخدم الموجّه الأساسي من دون تغيير.

يطلب طلب حلقة الوصف الذاتية المتوافق مع OpenAI نفسه (`callVisionModelSingle()`
في `visionBridgeHelpers.ts`) دائمًا `image_url.detail: "high"` —
دون شروط، ولكل مستدعٍ/موفّر، ومن دون الاعتماد على أي إشارة من العميل.
يؤدي أخذ العينات منخفضة التفاصيل إلى تدهور دقة OCR تحديدًا في مهمة نسخ النص
التي يطلبها هذا الموجّه، ولذلك يطلب استدعاء الوصف نفسه دائمًا تفاصيل عالية،
بصرف النظر عن مستوى التفاصيل الذي استخدمه الطلب الوارد الأصلي. يؤثر هذا
فقط في متن طلب الوصف الداخلي؛ ولا يغيّر كيفية تمرير OmniRoute لقيمة
`image_url.detail` الخاصة بالمستدعي ضمن الطلب الأساسي — إذ تُطبَّق تلك
القيمة الافتراضية بصورة منفصلة، ولعملاء OpenCode المكتشفين فقط، في
`defaultImageDetail()` ‏(`open-sse/handlers/chatCore/upstreamBody.ts`). لا يحتوي
فرع تنسيق Anthropic السلكي من حلقة الوصف الذاتية على حقل `detail`، ولذلك
لا يتأثر بأيٍّ من القيمتين الافتراضيتين.

#### الحد الأقصى لمخرجات الوصف (`modalityBridgeVisionMaxChars`)

| المفتاح                        | القيمة الافتراضية | النطاق           |
| ------------------------------ | ----------------- | ---------------- |
| `modalityBridgeVisionMaxChars` | `0`               | `0` أو 100–50000 |

تعني `0` (القيمة الافتراضية) **عدم وجود حد أقصى** — إذ يُمرَّر الوصف الذي
تعيده `callVisionModel()` من دون تعديل، حفاظًا على السلوك الحالي.
تؤدي أي قيمة ضمن النطاق 100–50000 إلى اقتطاع الوصف مع إضافة اللاحقة
`…` قبل إدراجه مجددًا بالصيغة `[Image N]: <description>`
(`VisionBridgeGuardrail.preCall()` في `src/lib/guardrails/visionBridge.ts`).
ارفع هذه القيمة لمهام OCR كثيفة التفاصيل التي يحتاج فيها النموذج اللاحق إلى
النص الكامل؛ واخفضها للحد من استخدام الرموز مع نماذج الرؤية كثيرة الإسهاب.
يوجد حقل لوحة المعلومات ضمن لوحة Advanced في تبويب Vision
(`modality-bridge-max-chars` في `ModalityBridgeVisionTab.tsx`)، ويضبط أي
قيمة بين 1 و99 صعودًا إلى الحد الأدنى 100، مع إبقاء القيمة الصريحة `0`
دون تغيير — إذ إن `0` قيمة Zod صالحة بحد ذاتها
(`z.union([z.literal(0), z.number().int().min(100).max(50000)])`)، وليست
مجرد القيمة الافتراضية «غير المعيّنة».

#### ذاكرة الوصف المؤقتة (`modalityBridge/bridgeCache.ts`)

ذاكرة تخزين مؤقت داخل الذاكرة من نوع LRU + TTL لمخرجات الوصف، مشتركة على
مستوى العملية بأكملها.
المفتاح = `sha256(imageRef + composedPrompt + configuredBridgeModel)` مع
تأطير يعتمد بادئة الطول (من دون تصادمات عند حدود الحقول). مكوّن النموذج هو
نموذج الجسر **المُهيّأ**، وليس النموذج الذي أجاب فعليًا —
فقد تستخدم `callVisionModel` نموذجًا احتياطيًا داخليًا، وسيؤدي إنشاء مفتاح
لكل محاولة إلى تجزئة ذاكرة التخزين المؤقت. لا تُخزَّن عمليات الوصف الفاشلة
مؤقتًا أبدًا. الإعدادات:

| المفتاح                         | القيمة الافتراضية | النطاق  |
| ------------------------------- | ----------------- | ------- |
| `modalityBridgeCacheEnabled`    | `true`            | —       |
| `modalityBridgeCacheTtlMinutes` | `60`              | 1–1440  |
| `modalityBridgeCacheMaxEntries` | `200`             | 10–5000 |

#### تسوية الصور البعيدة (الوصف الذاتي/جلب base64)

عندما يجلب الجسر صورة **بعيدة** بنفسه — سواء لاستدعاء الوصف الذاتي الخاص
بـ Anthropic أو لتحويل base64 بتنسيق claude السلكي
(`ensureBase64ImagesForClaudeWire`)، وكلاهما عبر
`fetchRemoteImageAsDataUri()` في `visionBridgeHelpers.ts` — يُمرَّر معرّف
URI الناتج للبيانات عبر `normalizeDataUri()`
(`open-sse/utils/imageNormalize.ts`) قبل تضمينه في طلب نموذج الرؤية.
تُصغَّر الصور فائقة الحجم إلى **حافة طويلة بطول 2048px** (بما يطابق حد تغيير
الحجم الذي تطبقه OpenAI/Anthropic بالفعل على جانب الخادم)، ما يقلل حجم
بيانات الرفع وزمن الاستجابة من دون تغيير ما يراه نموذج الرؤية. يستخدم تغيير
الحجم `sharp`، المحمَّل عبر استيراد ديناميكي: على منصة يفشل فيها تحميل ملفه
الثنائي الأصلي، **لا تُطلق** `normalizeDataUri()` **أي استثناء مطلقًا** —
بل تعود إلى تمرير البايتات الأصلية كما هي، بحيث يظل مسار الوصف/تحويل base64
عاملًا دائمًا. كما تُمرَّر البايتات التي لا تمثل صورة (أي عملية جلب لم تُرجع
صورة قابلة لفك الترميز) من دون تغيير. يقتصر نطاق هذه التسوية على الصور التي
يجلبها الجسر لاستدعائه الذاتي — ولا تُطبَّق أبدًا على حمولة التمرير المباشر
الخام الخاصة بالمستدعي، بما يتوافق مع مبدأ عدم التعديل إلا عند الاشتراك
الصريح (القاعدة الصارمة رقم 20).

#### مخطط الإعدادات + الترحيل

تُتحقَّق مفاتيح `modalityBridge*` الجديدة باستخدام Zod في
`updateSettingsSchema`
(`src/shared/validation/settingsSchemas.ts`): وهي
`modalityBridgeVisionEnabled`،
`modalityBridgeVisionMode`، و`modalityBridgeVisionModel`،
و`modalityBridgeVisionTaskAware`، و`modalityBridgeVisionPrompt`،
و`modalityBridgeVisionTimeout`، و`modalityBridgeVisionMaxImages`،
و`modalityBridgeVisionMaxChars`، وثلاثية `modalityBridgeCache*`،
ومجموعة `modalityBridgeAudio*` التي يستخدمها Audio Bridge. ينسخ الترحيل
`141_modality_bridge_settings.sql` قيم `visionBridge*` القديمة الحالية إلى
المفاتيح الجديدة المطابقة (بشكل متكرر آمن، ومن دون الكتابة فوق أي قيمة
`modalityBridge*` عيّنها المشغّل)؛ وتظل المفاتيح القديمة مقبولة بوصفها
خيارًا احتياطيًا للقراءة خلال دورة إصدار واحدة.

#### ترويسة الشفافية + الإحصاءات

تحمل الاستجابات المحوّلة بواسطة الوصف الترويسة
`x-omniroute-modality-bridge: image->text;model=<visionModel>;parts=<n>`
(تنشئها `buildModalityBridgeHeader()` في `modalityBridge/bridgeStats.ts`،
وتضيفها `withModalityBridgeHeader()` في `src/sse/handlers/chatHelpers.ts`).
لا تحصل الطلبات المعاد توجيهها على **أي** ترويسة — إذ لم تُعدَّل الحمولة،
ويظهر تبديل النموذج بالفعل في حقل `model` ضمن متن الاستجابة.

يعيد `GET /api/modality-bridge/stats` (بمصادقة إدارية، وبالمستوى نفسه الذي يستخدمه
`GET /api/settings`) العدادات الموجودة في الذاكرة لكل وسيط
`{ attempts, successes, bridged, cacheHits, failures, totalLatencyMs,
latencySamples, averageLatencyMs, lastUsedAt }` لكل من `vision` و`audio` و
`video`. يستخدم `averageLatencyMs` قيمة `latencySamples` مقامًا له، وليس جميع
المحاولات؛ ولا تُنشئ العملية التي لا تحتوي على توقيت عينةً وهميةً مدتها صفر
ميلي ثانية. يظل `bridged` الاسم المستعار المتوافق مع الإصدارات السابقة للتحويلات
الناجحة؛ ولا تزيد المحاولات الفاشلة قيمته.
تُصفَّر العدادات عند إعادة تشغيل العملية حسب التصميم
(للقياس عن بُعد، وليس للمحاسبة).

#### تهيئة لوحة المعلومات

صفحة لوحة المعلومات المخصصة هي
`/dashboard/settings/modality-bridge`. وتحافظ علامات التبويب `Vision` و`Audio`
و`Video`، التي يمكن الوصول إليها عبر عنوان URL، على معاملات الاستعلام أثناء
تبديل قيمة `tab`.
تعرض علامة تبويب Vision التمكين، والوضع، واختيار النموذج (بما في ذلك الخيار
الافتراضي التلقائي)، وصياغة المطالبات المدركة للمهام، وحدودًا متقدمة للمهلة
والصور وطول الوصف وذاكرة التخزين المؤقت، وعدادات وقت التشغيل، وطلبًا تجريبيًا
محميًا. علامة تبويب Audio فعالة أيضًا: فهي تعرض التمكين، ومنتقي نماذج خاصًا
بتحويل الكلام إلى نص فقط مع خيار Auto، وحدود المهلة والحد الأقصى لمدة المقطع،
وعدادات الصوت، واختبارًا تجريبيًا لـ `input_audio`. علامة تبويب Video وظيفية:
فهي تعرض حالة وقت تشغيل FFmpeg/ffprobe — وهي واحدة من أربع حالات صريحة لواجهة
المستخدم (`unknown` أثناء تنفيذ الفحص أو إذا تعذر إكماله، و`restricted` على
مضيف لوحة معلومات غير استرجاعي حيث يُتخطى الفحص من جهة العميل، و`unavailable`
بعد إجراء الفحص والتأكد من عدم توفره، أو `available` مع إصداري FFmpeg/ffprobe)
— وتحفظ حدود التمكين والنموذج والإطارات والفيديو والمهلة، وترشح منتقي النماذج
بحيث يقتصر على النماذج الداعمة للرؤية، وتعرض عدادات الفيديو.

أصبحت بطاقة Vision Bridge السابقة ضمن إعدادات الذكاء الاصطناعي رابط توافق إلى
الصفحة الجديدة؛ ولم تعد تحتوي على نسخة ثانية من النموذج. كما يربط قسم Media Providers
سيري عمل Image-to-Text وSpeech-to-Text بعلامتي تبويب Modality Bridge المقابلتين
من دون إزالة ساحة تجربة Speech-to-Text الحالية.

**تجاوز قبول الحلقة الذاتية:** عندما يُوجَّه استدعاء الوصف عبر الحلقة الذاتية
`/v1` الخاصة بـ OmniRoute (نموذج موفر غير قياسي)، يرسل الطلب الفرعي
`x-omniroute-admission-bypass: internal` وتُجرى مصادقته باستخدام بيانات اعتماد
الحلقة الذاتية المحلولة — القيمة المحلية الحارسة `sk_omniroute` في الوضع المحلي،
أو مفتاح البيئة `OMNIROUTE_API_KEY` / `ROUTER_API_KEY` الذي يهيئه المشغّل
(#1350)، لكي تظل عمليات النشر التي تستخدم `REQUIRE_API_KEY=true` قادرة على
تنفيذ استدعاء الوصف. لا يُقبل التجاوز إلا مع بيانات الاعتماد المطابقة تمامًا،
وبالتالي لا يمكن للعملاء الخارجيين استخدام الترويسة لتخطي القبول.

توجد القيم الافتراضية القديمة في `src/shared/constants/visionBridgeDefaults.ts`؛
بينما توجد القيم الافتراضية الجديدة للوضع والإدراك بالمهمة وذاكرة التخزين المؤقت،
إضافةً إلى محلّل الإعدادات، في
`src/shared/constants/modalityBridgeDefaults.ts`. يوفّر حاجز الحماية خيار المُنشئ
`deps` لكي تتمكن الاختبارات من حقن تنفيذات وهمية لكل من `getSettings` و
`callVisionModel`.

### جسر الصوت (`audioBridge.ts`) — Modality Bridge PR-3

يعترض طلبات المحادثة المحتوية على صوت قبل وصولها إلى هدف غير معروف بقبوله
إدخالًا صوتيًا. ولا يعيد توجيه طلب المحادثة مطلقًا: إذ تُنسخ الأجزاء الصوتية إلى
نص عبر نقطة النهاية الحالية متعددة الأجزاء والمتوافقة مع OpenAI، ثم يتابع نموذج
المحادثة المختار باستخدام النصوص المنسوخة.

التدفق:

1. حلّ `supportsAudio` عبر `getResolvedModelCapabilities()`. تكون الأولوية
   لبيانات التعريف الصريحة في سجل الموفر، ثم بيانات النموذج الثابتة، ثم
   `modalities_input` المتزامنة. تكون قائمة الإدخال المعلنة التي لا تحتوي على
   `audio` مساويةً لـ `false`؛ وفي حال عدم وجود أي دليل على الإمكانية، تظل
   القيمة `null`. تفعّل كل من `false` و`null` الجسر المحافظ، بينما تتجاوزه
   القيمة `true`.
2. حلّ إعدادات `modalityBridgeAudio*` واستخراج الأجزاء الصوتية القابلة للوَصل
   والموجودة في المستوى الأعلى من كل رسالة عبر الكاشف المشترك
   `detectMediaParts()`. أشكال النقل المدعومة هي `input_audio` و`audio_url`
   وفق OpenAI، و`source.media_type: "audio/*"`. يُكتشف الصوت المتداخل لأغراض
   التوجيه، لكنه لا يُزال عبر مسار الوصل. يقتصر العمل على
   `modalityBridgeAudioMaxClips`؛ وتظل الأجزاء اللاحقة دون تغيير.
3. الالتزام بقيمة `provider/model` مهيأة، أو السماح لـ
   `selectAudioBridgeModel()` باستعراض `AUDIO_TRANSCRIPTION_PROVIDERS` بترتيب
   الكتالوج الثابت واختيار أول نموذج تتوفر له بيانات اعتماد موفر نشطة وصالحة
   للاستخدام.
4. يحوّل `callAudioTranscription()` الصوت المشفّر بصيغة base64 أو data-URI إلى
   `file` متعدد الأجزاء، أو ينزّل `audio_url` بعيدًا عبر حاجز الاتصالات الصادرة
   العامة فقط، مع تثبيت DNS وحد أقصى قدره 25 ميغابايت. ثم يرسل الملف والنموذج
   المحدد بطلب POST إلى الحلقة الذاتية المحلية `/v1/audio/transcriptions`،
   مع المصادقة باستخدام `resolveSelfLoopBearer()`. ينفذ مسار النسخ الحالي البحث
   المعتاد عن بيانات الاعتماد، والتعامل مع فترات التهدئة وحدود المعدل، والتوزيع
   على الموفر.
5. تستبدل الاستدعاءات الناجحة أجزاءها بـ `[Audio N]: <transcript>`. تُشغّل
   الاستدعاءات باستخدام `Promise.allSettled`: يحافظ فشلٌ منفرد على جزء الصوت
   الأصلي ذاك (عقد #4012). إذا فشلت جميع الاستدعاءات وثبت أن الهدف
   `supportsAudio === false`، تصبح الأجزاء
   `[Audio N]: (unavailable — no STT provider connected)` (عقد #8430). أما
   بالنسبة إلى هدف مجهول (`null`)، فتظل النتيجة دون تغيير عند فشل جميع
   الاستدعاءات. ويتلقى الهدف الذي ثبت أنه نصي فقط ولا يملك بيانات اعتماد STT
   صالحة للاستخدام العنصر النائب الصريح نفسه من دون إجراء استدعاء شبكي.

تستخدم النصوص المنسوخة بنجاح ذاكرة التخزين المؤقت LRU/TTL الخاصة بـ Modality
Bridge على مستوى العملية. يجمع المفتاح بين مرجع الصوت، وتسمية العملية الثابتة
`audio-transcription`، ونموذج STT المحدد؛ ولا تُخزّن حالات الفشل مؤقتًا مطلقًا.
تحدّث محاولات الصوت العدادات المشتركة `bridged` و`cacheHits` و`failures` و
`lastUsedAt`.
تحمل الاستجابات المحوّلة
`x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>`؛ ولا
تتلقى الطلبات التي لم تتغير مقطع Audio Bridge.

إعدادات وقت التشغيل مدعومة بقاعدة بيانات ويجري التحقق منها باستخدام Zod:

| المفتاح                       | القيمة الافتراضية | النطاق              |
| ----------------------------- | ----------------- | ------------------- |
| `modalityBridgeAudioEnabled`  | `true`            | —                   |
| `modalityBridgeAudioModel`    | `""`              | تلقائي أو معرّف STT |
| `modalityBridgeAudioTimeout`  | `60000`           | 1000–300000         |
| `modalityBridgeAudioMaxClips` | `3`               | 1–10                |

تظل ذاكرة التخزين المؤقت المشتركة خاضعة للتحكم بواسطة `modalityBridgeCacheEnabled`،
و`modalityBridgeCacheTtlMinutes`، و`modalityBridgeCacheMaxEntries`.

### جسر الفيديو (`videoBridge.ts`، `videoBridgePipeline.ts`)

يعترض أجزاء الفيديو ذات المستوى الأعلى في `messages` الخاصة بـ Chat Completions وفي
`input` الخاصة بـ Responses API قبل استدعاء هدف لا يُعرف أنه يدعم الفيديو أصليًا.
الأشكال المدعومة هي `input_video`، و`video_url`، و`video_source`، وعناوين URL التي تستخدم HTTPS،
ومعرّفات URI للبيانات بالصيغة `data:video/*;base64,...`. لا تُعامل أسماء الملفات المجردة في النص
على أنها فيديو.

يتولى `VideoBridgeGuardrail.preCall` (`videoBridge.ts`) اجتياز الطلب،
والتحقق من الإمكانات/السياسة، والتجميع لكل طلب، وحمولة الاستجابة.
أما العمل الخاص بكل فيديو — جلبه، وذاكرة التخزين المؤقت للنتيجة الكاملة، ووصف تسلسل الإطارات
(الذي يدمج أي نص مفرغ للصوت يصرّح به المستدعي)، ومقاييس/إيقاف/تنظيف كل محاولة —
فهو مخفي خلف `processVideoPart` في
`videoBridgePipeline.ts`، والذي يُستدعى مرة واحدة لكل جزء فيديو داخل حلقة `preCall`.
تعرّف تلك الوحدة أيضًا حدود المنافذ الصريحة `VideoMediaBrokerPort`
(لجلب البايتات واستخراج الإطارات المأخوذة كعينات)، و`VideoAudioTranscriptionPort`
(لدمج نص مفرغ للصوت يصرّح به المستدعي مع التعليقات التوضيحية للإطارات المأخوذة كعينات)، و
`VideoDrilldownPort` (حدّ استمرارية التخزين للتعمق في الإطارات؛ ولم يُربط بعد
بـ `processVideoPart` — إذ إن مسار `/api/modality-bridge/video/drilldown`
المنفصل وحده هو الذي يكتب إدخالات التعمق حاليًا).

لا يستورد مسار الطلب العام `/v1` أي عملية فرعية ولا يستدعيها مطلقًا. تُنزّل
مقاطع الفيديو البعيدة ضمن حد قدره 50 MiB؛ أما مقاطع الفيديو المضمنة بترميز base64 فلها
حد أقصى متحفظ يبلغ 36 MiB للحجم المفكوك لكل فيديو، بحيث يمكن أن يظل غلاف
النموذج/الرسائل/التأطير ضمن حد قبول طلبات JSON العامة البالغ 50 MiB. يجري التحقق من
الطول المضمن وتقديرات الحجم المفكوك قبل التخصيص. يُشترط استخدام HTTPS
في عنوان URL البعيد الأولي وفي كل عملية إعادة توجيه، باستخدام حاجز الاتصالات الصادرة
القائم والمقتصر على العناوين العامة مع تثبيت DNS. بعد ذلك تعبر البايتات حد الوسيط الداخلي المحدد
`POST /api/modality-bridge/video/extract`. هذا المسار موسوم بكل من
`LOCAL_ONLY` و`SPAWN_CAPABLE`، ولا يقبل إلا طلبًا موثقًا لكل عملية
وعبر عنوان استرجاع محلي موثوق، ولا يقبل مطلقًا عنوان URL أو مسار نظام ملفات أو ملفًا تنفيذيًا
أو قائمة وسائط. يفرض مسار حجم جسم API وقارئ الجسم التزايدي في المعالج
كلٌ منهما بشكل مستقل حدًا أقصى قدره 50 MiB لمدخلات الوسيط. تعالج قائمته محدودة السعة
عملية استخراج واحدة في كل مرة، وتسمح بأربع مهام معلقة، وتضع حدًا أقصى للمدخلات المعلقة
قدره 100 MiB.

داخل الوسيط، يقرأ `ffprobe` ملفًا محليًا خاصًا؛ وتستبعد قائمة السماح الثابتة
للتنسيقات تنسيقات قوائم التشغيل والبيانات الوصفية. بالنسبة إلى حاويات عائلة MOV المسموح بها،
تظل مراجع بيانات MOV الخارجية معطلة افتراضيًا، ولا يفعّلها
الأمر الثابت. يستخدم كل من `ffprobe` و`ffmpeg`
قائمة بيضاء للبروتوكولات تقتصر على `file`، وخيط تنفيذ واحدًا، ومصفوفات وسائط ثابتة، ومن دون shell،
مع حل مواقع الملفات التنفيذية من `PATH`. لا تُعد تدفقات صور الغلاف المرفقة
مرشحة قابلة للتشغيل. يجب أن تستوفي جميع التدفقات القابلة للتشغيل الحدود، ويُفضّل
تدفق افتراضي صريح قبل الرجوع الحتمي إلى التدفق ذي الفهرس الأدنى.
تقتصر مقاطع الفيديو على 600 ثانية، و8,192 بكسل لكل بُعد،
و33,554,432 بكسل في المصدر. يأخذ FFmpeg عينات من 1–16 إطار JPEG عند نقاط المنتصف،
ويصغّر الحافة الطويلة إلى 1,024 بكسل كحد أقصى من دون تكبير المدخلات الأصغر،
ولا يتلقى عنوان URL مطلقًا. تكون سياسة أخذ العينات `uniform` افتراضيًا. تنفّذ سياستا
`scene_aware` الاختيارية و`segment_aware` التجريبية تمريرة FFmpeg ثابتة إضافية واحدة
على التدفق المحلي الذي جرى التحقق منه مسبقًا، وتختاران طوابع زمنية محدودة للمشاهد من
`showinfo`، وتعودان بشكل حتمي إلى نقاط المنتصف المنتظمة نفسها عند فشل الكاشف،
أو انتهاء المهلة، أو وجود مخرجات مشوهة، أو فراغ مجموعة المرشحين. يخصص وضع مراعاة المقاطع
عينات نقاط المنتصف بالتناسب مع فواصل المشاهد التي تم التحقق منها؛ ويأتي أدناه تفصيل أدلة
مراعاة المقاطع وسلوك الرجوع الاحتياطي. يُطبّق الحد الأقصى الصارم البالغ 16 إطارًا
بعد الاختيار في كل سياسة. عندما تكون ميزانية طلب يراعي المشاهد إطارًا واحدًا فقط،
فإنه يستخدم نقطة المنتصف المنتظمة لنافذة الفيديو الكامل أو نافذة التركيز النشطة
ويبلّغ عن `policyEffective: uniform`: إذ لا يمكن لإطار مشهد واحد محدد
الحفاظ على كلا الطرفين الزمنيين. يجوز للمستدعي اختياريًا توفير
نافذة تركيز محدودة (`start`/`end` بالثواني)؛ تُقيّد الحدود بمدة الوسائط،
وتُرفض النوافذ المعكوسة أو غير المحدودة، وتُنفّذ جميع سياسات أخذ العينات
داخل الفاصل المطبع فقط. تُضمّن النافذة الناتجة في البيانات الوصفية لأخذ العينات
وفي بادئة الوصف غير الموثوقة، بحيث تستطيع النماذج اللاحقة التمييز بين مقتطف مركّز
والخط الزمني الكامل.

تركيز التعليقات التوضيحية الدلالي هو إعداد منفصل وصريح. يحافظ وضع التحليل الافتراضي `full`
على موجّه الإطارات الحالي ولا يمرر نص الطلب مطلقًا إلى نموذج التعليقات التوضيحية.
في وضع `focused`، لا يقرأ الجسر إلا أحدث `text`/`input_text` غير فارغ
كتبه المستخدم من حاوية Chat أو Responses نفسها، ويطبّعه إلى NFC، ويطوي
محارف التحكم والمسافات البيضاء، ويقصره على 500 نقطة ترميز Unicode. تؤدي النتيجة الفارغة
إلى الرجوع إلى موجّه `full` نفسه تمامًا. يُسلسل التلميح القابل للاستخدام بصيغة JSON
في كتلة مخصصة لسياق مستخدم غير موثوق، ولا يجوز له إلا إعطاء الأولوية للتفاصيل القابلة للملاحظة؛
ولا يمكنه تجاوز التحذير المنفصل من اتباع التعليمات المرئية أو المسموعة في الوسائط.
لا يستنتج التركيز النصي `start`/`end` مطلقًا ولا يغيّر آلية أخذ العينات الزمنية.

#### FU-07 أدلة المقاطع البنيوية

يستخدم `segment_aware` تمريرة تحليل مسبق واحدة محدودة على تدفق الفيديو المحلي الذي جرى التحقق منه بالفعل. تبدأ سلسلة المرشحات الثابتة بتغيير الحجم إلى عرض لا يتجاوز 320 بكسل، ثم تكتشف تغيّرات المشهد والفترات المتجمدة، وبعد ذلك تأخذ عينة بمعدل إطار واحد في الثانية لقياس التمويه، ومتوسط السطوع، والمعلومات المكانية/الزمنية. تقتصر التمريرة على 600 عينة بنيوية، وخيط FFmpeg/مرشح واحد، وقوائم السماح نفسها الخاصة بالبروتوكول `file` فقط والحاويات، وحد أقصى قدره 1 MiB لمخرجات العملية، ومدة لا تتجاوز 30 ثانية ضمن الإلغاء/الموعد النهائي المشترك للوسيط. ولا تقبل مطلقًا أمرًا أو مرشحًا أو مسارًا أو URL من الطلب.

القيم البنيوية هي أدلة أخذ عينات حتمية، وليست فهمًا دلاليًا للفيديو. فهي لا تستنتج الموضوعات أو الأفعال أو التسميات التوضيحية أو الكلام أو مقصد المستخدم. تشكّل حدود المشاهد والتجمّد مقاطع؛ ولا تؤثر تغطية التجمّد والتمويه والتعرض والتفاصيل المكانية والتغير الزمني إلا في كيفية تخصيص ميزانية الإطارات الحالية البالغة 1–16 إطارًا. يُحدد حد أقصى مقداره إطار واحد للمقطع المتجمد بالكامل، بينما تتنافس المقاطع غير المتجمدة على الميزانية المتبقية. عندما يفوق عدد الحدود عدد الإطارات، تُحافَظ على تغطية موحّدة للمخطط الزمني بحيث لا تتمكن القطوع السريعة المبكرة من إخفاء مقطع ختامي طويل. تُدمج حدود المشاهد التي تقع ضمن دقة التحليل البالغة ثانية واحدة من حد تجمّد.

يؤدي غياب المرشحات، أو الأدلة التالفة/الفارغة، أو خطأ في الكاشف، أو انتهاء مهلة التحليل المسبق المحدود إلى السماح بالمتابعة باستخدام سياسة نقاط المنتصف الموحّدة نفسها تمامًا. أما إلغاء المستدعي أو بلوغ الموعد النهائي للوسيط فلا يسمحان بالمتابعة: إذ يؤديان إلى إنهاء العملية الفرعية الجارية، ومنع استخراج الإطارات لاحقًا، وإزالة شجرة الملفات المؤقتة الخاصة في `finally`.

ينشئ `scripts/perf/video-bridge-fu07-eval.ts` تجهيزات FFmpeg حقيقية وحتمية لقياس وفورات استدعاءات إنشاء التسميات التوضيحية بعد إزالة التكرار، وتخصيص الميزانية للحركة الكثيفة، وأدلة التمويه/التعرض/SI-TI، والقطوع السريعة ذات الذيل الطويل، والنتائج الإيجابية الكاذبة للتلاشي التدريجي. ويسجّل مدة التحليل المسبق الفعلية، وكذلك استخدام المعالج للعملية الفرعية وذروة RSS عندما يكون `/usr/bin/time` متاحًا. لا تعدو فحوصات الجودة فيه كونها مراجع بنيوية. وتظل جودة نموذج التسميات التوضيحية الحقيقي عند `HOLD` لأن أداة الاختبار هذه لا تملك نقطة نهاية مصرّحًا بها أو مُحكّمًا ثابتًا. كما تظل الوفورات المالية عند `HOLD` ما لم يوفّر `--caption-cost-per-call-usd` تقديرًا صريحًا وموجبًا لتكلفة كل استدعاء؛ ولا يختلق السكربت أيًا من النتيجتين.

يقتصر حجم كل إطار على 4 MiB، ويقتصر الحجم الإجمالي لجميع الإطارات الخام على 23 MiB، وتقتصر استجابة الوسيط المتسلسلة على 32 MiB. ويُزال دليل مؤقت خاص في `finally`. لا تضمّن OmniRoute برنامج FFmpeg، ولا تقبل مسارًا مخصصًا للملف التنفيذي. قبل إنشاء التسميات التوضيحية، يطبق الجسر تمريرة محافظة لإزالة التكرار المرئي: إذ يُختزل كل ملف JPEG إلى مخزن مؤقت بتدرج رمادي بحجم 16×16، ولا يُقارن إلا بآخر إطار جرى الاحتفاظ به. عندما تكون ميزانية التسميات التوضيحية المطلوبة أكبر من إطار واحد، يوفّر الاستخراج مجموعة مرشحين محدودة تصل إلى ضعفي تلك الميزانية، ولا تتجاوز مطلقًا 16 إطارًا. لا يُطبّق الحد الأقصى المطلوب إلا بعد إزالة التكرار، مع الحفاظ على المرشحَين الأول والأخير المحددَين أثناء التقليص النهائي عندما تكون الميزانية إطارين على الأقل. تستخدم السياسة ذات الإصدار
`grayscale-16x16-mean-cells-v2` القيمة الأكبر بين متوسط فرق السطوع ونسبة خلايا الصورة المصغرة التي لا يقل فرقها المطبّع عن 0.05. عتبة التكرار هي الثابت 0.04، وقد اختيرت لإمكانية التنبؤ بدلًا من إتاحتها كإعداد أثناء التشغيل. تحافظ إشارة التباين العالي الثانوية هذه على الحركات الصغيرة وتغيّرات النص المرئي التي قد تخفيها مقارنة تعتمد على المتوسط وحده. تؤدي أخطاء المقارن أو مفكك الترميز إلى السماح بالمتابعة والحفاظ على التغطية. تفصل بيانات المخرجات الوصفية بين المرشحين المستخرجين، والإطارات المستخدمة بنجاح، والتكرارات المرئية المستبعَدة.

يمكن لجزء فيديو معلَّم صراحةً أن يطلب ورقة صور مصغرة ذات طوابع زمنية. ينشئ الجسر شبكة JPEG تضم 4 أعمدة و16 إطارًا بحد أقصى. وتطبع كل خلية بحجم 512 بكسل الطابع الزمني لمصدرها داخل شريط سفلي عالي التباين، بينما تظل الطوابع الزمنية نفسها موجودة في البيانات الوصفية النصية للربط والتدقيق في المراحل اللاحقة. يظل حجم ملف JPEG الكامل محدودًا بـ 32 MiB. إذا تعذّر على `sharp` فك ترميز الشبكة أو تركيبها، يعود الجسر إلى إطارات JPEG المنفردة؛ ويظل إلغاء العميل منتشرًا عبر عملية ورقة الصور.

تُفصل أدلة الترقية عمدًا عن المعيار المصغر الاصطناعي للتركيب. يعرّف `scripts/perf/video-bridge-contact-sheet-eval.ts` أداة اختبار A/B ذات مخطط محدد الإصدار لنماذج الرؤية الحقيقية المتوافقة مع OpenAI. وتقيس الرموز التي أبلغ عنها المزوّد، وزمن الاستجابة الفعلي من البداية إلى النهاية بما يشمل تركيب ورقة الصور، وعدد استدعاءات النموذج، والاحتفاظ بالحقائق المحددة في البيان. لا تُكتب استجابات النموذج الخام في التقرير؛ بل لا يُحتفظ إلا بملخصات SHA-256 ومعرّفات الحقائق المطابقة. لا تجري أداة الاختبار أي اتصال شبكي أو استدعاء مدفوع لنموذج ما لم يُمرَّر `--execute-real` وتُضبط `--model` و`OMNIROUTE_BASE_URL` و`OMNIROUTE_API_KEY`. من دون هذا التشغيل الحقيقي الصريح، تظل النتيجة القابلة للقراءة آليًا عند `HOLD`؛ فقياسات الحمولة الاصطناعية/عدد الاستدعاءات وحدها لا تُعد دليلًا للترقية.

يمكن للمستدعين إرفاق مصفوفة `transcript.cues` اختيارية بجزء فيديو مدعوم عندما يكون لديهم نص متزامن بالفعل. يجب أن يتضمن كل دليل `text`، وفاصلًا زمنيًا محدودًا من `start`/`end` يقع ضمن المدة التي جرى فحصها، وقيمة `source` مدرجة في قائمة السماح (`client` أو `embedded` أو `audio-bridge`)؛ وتكون القيمة الافتراضية لـ`confidence` هي `1` ويجب أن تظل بين `0` و`1`. تُدمج الأدلة المتطابقة تمامًا. لا تبدأ OmniRoute مطلقًا عملية نسخ صوتي انطلاقًا من هذه البيانات الوصفية: إذ تُنسخ الأدلة التي جرى التحقق منها إلى النتيجة الموصوفة مع المصدر والثقة والفاصل الزمني، وتُعرض كملاحظات غير موثوق بها إلى جانب التسميات التوضيحية للإطارات. يُرفض النص غير الصالح أو الواقع خارج النطاق أو المفتقر إلى مصدر بدلًا من دمجه في تدفق التسميات التوضيحية. تقوم قناتا النص المنسوخ في متن الطلب بتطبيع المصدر المقدم إلى `client`، بما في ذلك تسميات `embedded` أو `audio-bridge` التي يصرّح بها صاحب الطلب بنفسه. لا يستطيع تعيين هذه التسميات الموثوق بها عبر الوسيطة البرمجية فقط `trustedSource` إلا محوّل مملوك للخادم؛ ولا يمكن لحقل JSON في الطلب الوصول إلى تلك الوسيطة. يظل نص النسخ الصوتي محتوى غير موثوق به مستمدًا من الوسائط، بصرف النظر عن مصدره، ويجب ألا يحدد التفويض مطلقًا.

قد يوفّر مستدعٍ متقدم مسار `audioTranscript` للفيديو نفسه؛
ويُعامل كنص مقدَّم من العميل، وليس كدليل على إجراء الخادم لعملية النسخ.
يشغّل موضع الدمج الملاحظات المرئية والصوتية ضمن
مهلة نهائية واحدة وإشارة إلغاء واحدة، ويرتّبها على خط زمني مشترك، ويدمج
النسخ المتطابقة تمامًا، ويُبلغ عن نتيجة جزئية عندما ينجح جانب واحد فقط.
يؤدي `audioTranscript` غير الصالح إلى خفض النتيجة إلى تلك النتيجة الجزئية — إذ يُحتفظ
بالوصف المرئي ويسجّل فرع الصوت رمز فشل منقّحًا —
بدلًا من إفشال الفيديو بأكمله. يُحتفظ بتوفّر كل فرع، وعلامة النتيجة الجزئية،
ورموز الفشل المنقّحة في النتيجة الموصوفة، وفي
بيانات حواجز الأمان الوصفية (`audioFusionRuns`/`audioFusionPartials`/
`audioFusionFailureCodes`)، وفي بيانات ذاكرة النتائج المؤقتة الوصفية، وفي عدّادات
الدمج الخاصة بالجسر. لا يستدعي مسار Video Bridge الافتراضي تحويل الكلام إلى نص،
ولا ينزّل نسخة وسائط ثانية؛ ومن دون ذلك المسار الصريح، يظل
خاصًا بالفيديو فقط.

**الاحتفاظ بالنص المنسوخ (#12150 P1).** ينطبق هذا تلقائيًا متى عرض
Video Bridge (الذي يتطلب التفعيل بدوره) إشارة نص منسوخ — ولا توجد
علامة احتفاظ منفصلة. عندما يعرض طلبٌ أي إشارة نص منسوخ (سواء `transcript`
صرّح به المستدعي أو `audioTranscript` مدمجًا)، يضع حاجز الأمان عليه علامة
`videoBridgeObserved` وينشئ نسخة ظل منقّحة من وصف الفيديو —
عرضًا مطابقًا يُستبدل فيه نص كل إشارة الحر بـ
`[redacted-video-transcript]`، وذلك عبر استبدال حقل الإشارة المنظّم
قبل تجميع السلسلة النصية (وليس أبدًا عبر تحليل النص المسطّح، بحيث لا يمكن لأي محتوى
إشارة — عدائيًا كان أو عاديًا، بما في ذلك الأجسام التي تحتوي على `]` مثل
`[inaudible]`/`[music]` — أن يبقى). يستبدل جسم الطلب المحفوظ في سجل الاستدعاءات
كل جزء نصي مشتق من الفيديو بنسخة الظل المنقّحة تلك، مع المطابقة حسب تطابق
المحتوى؛ ويُعاد قراءة مرساة `fullText` من حمولة حاجز الأمان المكتملة السابقة للاستدعاء،
بحيث تظل المطابقة ناجحة بعد أن تعيد حواجز الأمان اللاحقة في السلسلة (أداتا إخفاء
معلومات التعريف الشخصية وبيانات الاعتماد، بالأولويتين 10/95) كتابة نص الوصف في موضعه،
وبعد أن تعيد إضافة موجّه النظام/التسليم/الذاكرة تشكيل مصفوفة الرسائل. يظل
الجسم المرسل إلى النموذج دون تغيير. كما أن الطلب المرصود لا يملأ
أي Memory دائمة (إذ يُتخطى الاستخراج المشتق من كل من الطلب والاستجابة)،
لذلك لا يمكن لرد النموذج نفسه تكرار نص النسخ داخل Memory.

**حقول الفيديو الخام (#12430).** عندما يكون الجسر مفعّلًا وكان دعم الفيديو الأصلي مجهولًا أو غير متاح، فإن حقول `transcript`/`audioTranscript` المعرّفة تفعّل أيضًا `videoBridgeObserved`، حتى بعد فشل الوصف أو بلوغ حد `maxVideos`. تُحتسب `null` والسلاسل الفارغة؛ أما الحقول الغائبة والبيانات الوصفية غير الخاصة بالفيديو فلا تُحتسب. تنقّح النسخ المحتفظ بها هذه الحقول أو تحذف الطلب، كما يجري تجاوز ذاكرات التخزين المؤقت وMemory.

في مسارات الرجوع تلك، تتحول إشارات المستدعي الصالحة إلى أجزاء `text`/`input_text`
مدعومة بدلًا من حقول المزوّد غير القياسية. يظل كلا المسارين المقدّمين في الطلب
ملاحظات `client` غير موثوق بها، مع تحذير صريح بأن الفيديو
لم يُوصَف وأن الطوابع الزمنية لم تُتحقق مقابل الوسائط. تنطبق
ميزانية 256 إشارة/64-KiB الإجمالية وميزانيات كل إشارة الحالية على المسارين معًا؛
ويجب أن تندرج الطوابع الزمنية ضمن سقف الوسيط البالغ 600 ثانية وأي نافذة تركيز
مقدّمة. تُستبعد المسارات غير الصالحة، ولا تُمرر كنص اعتباطي؛ وقد يظل من الممكن
استخدام مسار شقيق صالح ما لم تُتجاوز ميزانيتهما المجمّعة. لا تضيف الحقول الفارغة أو
ذات القيمة Null أي نص. لا يضيف مسار الرجوع هذا أي جلب للوسائط أو نسخ.
تُزال حقول امتداد النص المنسوخ من حامل فيديو الرجوع ومن كائني
`video_url`/`source` الخاصين به. تظل قائمة السماح السلكية الخاصة بـ OpenAI صارمة؛
وتظل حوامل الفيديو ذات الدعم الأصلي المجهول متاحة، بينما تحتفظ الأهداف المعروفة بأنها
نصية فقط بعلامات آمنة. تحمي ظلال التنقيح المنظّمة نص النسخ الملحق، بينما يظل
الطلب الأصلي المملوك للمستدعي دون تغيير. تحتفظ الأهداف ذات الدعم الأصلي والجسور
المعطّلة بسلوك التجاوز الحالي لديها.

تستخدم النسخ الإضافية المحتفظ بها إشارة الطلب المرصود نفسها. تستبدل لقطة
طلب العميل الخام السابقة لحاجز الأمان، والطلب المعلّق في الذاكرة، وسجل
الطلبات المرفوضة مبكرًا، حقول النص المنسوخ في أجزاء الفيديو بنيويًا؛
وتُنقّح الموجّهات النصية التي تنشئها مراحل خط الأنابيب وتسليم السياق
عند نقطة تجميع جسم الطلب المحفوظ. تجعل علامة `video_content_removed`
المحفوظة متابعة `previous_response_id` تفشل بصورة مغلقة بدلًا من إعادة بناء
نص جرى التخلص منه عمدًا. إذا فقد طلب مرصود
ظل التنقيح الخاص بكل جزء قبل التسجيل، أو إذا فشل ظل واحد فقط من بين عدة ظلال
فيديو في المطابقة بعد تعديلات الطلب اللاحقة، يُحذف جسم الطلب المحتفظ به
بالكامل بدلًا من الاحتفاظ بنص منسوخ منقّح جزئيًا.

بالنسبة إلى طلب مرصود، قد تقتبس استجابة النموذج أي جزء من
النص المنسوخ دون حد منظّم لإشارة. لذلك يُستبدل `responseBody`
المحفوظ في سجل الاستدعاءات بعلامة حذف؛ ولا يُحتفظ بأثر
خط الأنابيب التفصيلي (الذي قد يتضمن أجسامًا من المنبع/العميل ومقاطع البث).
تتجاوز ذاكرات التخزين المؤقت الدلالية، والخاصة بثبات النتائج، والخاصة بإعادة تشغيل
الاستدلال، عمليات القراءة والكتابة لذلك الطلب. يظل طلب المزوّد والاستجابة
المرئية للعميل دون تغيير. تُصرّف بايتات إبقاء الاتصال المبكرة من المخزن المؤقت
عندما يُحذف الأثر التفصيلي. لا يبلّغ تحذير EventStream المشوّه في Kiro إلا عن
عدد بايتات الحمولة، ولا يبلّغ أبدًا عن محتوياتها أو عن الخطأ الخام لمحلّل JSON.
ولا يعني هذا الادعاء أن كل تشخيص غير ذي صلة صادر عن مزوّد/مكوّن إضافي قد خضع
للتدقيق؛ إذ يجري تتبع المسح الأوسع لنقاط تجميع البيانات المحتفظ بها في #11658.

تُعد دورة حياة `/api/modality-bridge/video/drilldown` الداخلية ركيزة تخزين مؤقت منفصلة، تتم المصادقة عليها عبر loopback/token. وتتطلب كل عملية أيضًا معرّف principal مبهمًا وقياسيًا. قبل تمكين أي مستدعٍ في بيئة الإنتاج، يجب عليه اشتقاق ذلك المعرّف من المستأجر المُصادَق عليه، ويجب ألا يمرّر مطلقًا قيمة يختارها العميل. تربط مفاتيح التخزين المؤقت ذلك الـ principal بمعرّفات الجلسة ومراجع الفيديو القياسية، ولا تخزّن سوى مفاتيحها المشتقة باستخدام SHA-256، كما تحصر عمليات القراءة والحذف في الـ principal نفسه. يخزّن التخزين المؤقت بحد أقصى 16 إطار JPEG مشتقًا لكل إدخال، وتنتهي صلاحيتها بعد عشر دقائق، ويدعم عمليات قراءة محدودة عبر `start`/`end` أو حذفًا صريحًا للجلسة.

يقتصر كل principal على 16 إدخالًا و64 MiB من بيانات JPEG القياسية. وتكون هذه الحدود مستقلة عن السقف الإجمالي البالغ 64 إدخالًا/256 MiB: يؤدي ضغط حصة principal إلى إخلاء إدخالات ذلك الـ principal الأقل استخدامًا مؤخرًا فقط قبل النظر في الإخلاء العام وفق LRU. تُزال الإدخالات منتهية الصلاحية من حسابات كل من الـ principal والحسابات العامة عند حدوث نشاط في التخزين المؤقت، بينما لا يؤدي الإلغاء أو فشل التحقق إلى تثبيت استبدال جزئي.

يرفض التخزين المؤقت Base64 غير القياسي، والحشو الزائد، والوسائط غير JPEG، وملفات JPEG المشوّهة أو المبتورة، وملفات JPEG التي تنتج تحذيرًا أثناء فك ترميز كامل ومحدود للصورة باستخدام `sharp`. ويعيد ترميز كل صورة مقبولة بصيغة JPEG قياسية، ويشتق العرض والارتفاع من البايتات المفكوكة بدلًا من الوثوق بحقول المستدعي، ويتخلص من أي بايتات polyglot لاحقة بدلًا من الاحتفاظ بها. ولا تُحتسب ضمن كلتا الحصتين إلا الذاكرة المؤقتة المضغوطة القياسية والمحدودة. يشمل حد JSON المنقول الزيادة الناتجة عن Base64 لسقف الإدخال المفكوك البالغ 32 MiB. يسجّل كل اشتقاق مخزّن تنسيق JPEG ودقته بعد التحقق، وسياسة أخذ العينات، وإصدار الاشتقاق، ووقت الإنشاء، وتجزئة المحتوى المحسوبة من الخادم، ومرجع الأصل المجزّأ بالإضافة إلى تجزئة محتوى الأصل الواردة من المستدعي الموثوق. يُتحقق من الإلغاء بين مراحل فك الترميز/التجزئة غير المتزامنة وقبل التثبيت الذري في التخزين المؤقت.

لا تربط هذه الدفعة حتى الآن منتِجًا للإنتاج بالمسار، ولا توفّر اختيار متغيرات متعددة الدقة. ولذلك لا يضيف مسار طلب Video Bridge الشفاف أي عمل إضافي، بينما يظل اشتقاق الـ principal المرتبط بالمستأجر ودورة حياة FU-08 الكاملة متعددة الدقة عملًا لاحقًا صريحًا، بدلًا من توثيقهما كسلوك مكتمل.

تُضاف تسميات توضيحية إلى الإطارات بالتتابع باستخدام نموذج Video المُهيأ. يرث تجاوز Video الفارغ إعداد Vision؛ وإذا كان كلاهما فارغًا، يختار الموجّه التلقائي لـ Vision النموذج الفعّال القادر على معالجة الرؤية. تستبدل التسميات التوضيحية الناجحة الجزء الأصلي ببادئة ثابتة `[Video description:`، تشير أيضًا إلى أن النص ملاحظة غير موثوقة مشتقة من الوسائط، وتوجّه النماذج اللاحقة إلى عدم اتباع التعليمات الموجودة في الوسائط. تتضمن مفاتيح التخزين المؤقت لتسميات الإطارات بايتات JPEG، والموجّه، والطابع الزمني، والنموذج الفعّال؛ ولا تُخزّن مؤقتًا إلا التسميات التوضيحية الناجحة. تحتفظ إدخالات التخزين المؤقت بنموذج المُنتِج الفعلي الناجح، بما في ذلك نموذج احتياطي؛ ويبلغ الجسر عن `mixed` عندما تكون الإطارات المختلفة قد أُنتجت بواسطة نماذج مختلفة. تعيد إصابة التخزين المؤقت استخدام هوية ذلك المُنتِج بدلًا من إعادة تسميته وفق خطة التوجيه المطلوبة. يعتمد مفتاح التخزين المؤقت لنتيجة الفيديو بالكامل على كل مُدخل يغيّر الناتج — الموجّه، والنموذج الفعّال، وسياسة أخذ العينات، وعدد الإطارات، ووضع التحليل الدلالي، وبصمة SHA-256 لتلميح التركيز المُطبّع، ونافذة التركيز، و`transcript`، و`audioTranscript`، وعلامة ورقة جهات الاتصال — ولذلك يؤدي تغيير أي من هذه الأبعاد إلى فقدان في التخزين المؤقت، وليس إلى إعادة استخدام قديمة مطلقًا. كما تكون نسخة سياسة إزالة التكرار المرئي، والعتبة، والعدد المحدود للإطارات المرشحة صريحة في مفتاح التخزين المؤقت للنتيجة وبياناته الوصفية؛ ولذلك لا يمكن لتغيير السياسة إعادة استخدام وصف قديم للفيديو بالكامل. تحتفظ البيانات الوصفية للإصدار v4 من ذاكرة تخزين النتائج بالوضع والبصمة، ولا تحتفظ مطلقًا بمهمة المستخدم الخام. تعرض البيانات الوصفية لآلية الحماية وضعي التحليل المطلوب والفعّال؛ ويُبلّغ عن وضع `focused` مطلوب من دون نص مستخدم صالح باعتباره `full` فعليًا.

تستخرج آلية الحماية كل جزء فيديو مدعوم، لكنها لا تصف أكثر من `modalityBridgeVideoMaxVideos`. بالنسبة إلى هدف ثبت أن لديه `supportsVideo === false`، تصبح مقاطع الفيديو الفاشلة والمتجاوزة للحد علامات نصية آمنة وصريحة، بحيث لا تبقى أي وسائط فيديو خام. عندما تكون الإمكانية غير معروفة، تحتفظ تلك الأجزاء بحامل الفيديو الخاص بها؛ ويتبع أي نص احتياطي التحويل النصي المحدود أعلاه. تتجاوز الأهداف التي لديها `supportsVideo === true` الجسر. تنتشر إشارة إلغاء طلب العميل عبر التنزيل، وطابور الوسيط، والعمليات الفرعية، واستدعاءات التسميات التوضيحية؛ وتؤدي عمليات الإلغاء إلى التوقف بين مقاطع الفيديو، ولا تفشل مطلقًا بطريقة تسمح بمرور الوسائط الخام.

تكون إعدادات وقت التشغيل مدعومة بقاعدة البيانات وخاضعة للتحقق باستخدام Zod:

| المفتاح                             | القيمة الافتراضية | النطاق / السلوك                                                                                                 |
| ----------------------------------- | ----------------- | --------------------------------------------------------------------------------------------------------------- |
| `modalityBridgeVideoEnabled`        | `false`           | بيئة تشغيل اختيارية، تتطلب الاشتراك صراحةً                                                                      |
| `modalityBridgeVideoAnalysisMode`   | `"full"`          | يحافظ `full` على التسميات التوضيحية العامة؛ ويستخدم `focused` سياقًا محدودًا وغير موثوق لأحدث رسالة من المستخدم |
| `modalityBridgeVideoModel`          | `""`              | يرث نموذج Vision Bridge                                                                                         |
| `modalityBridgeVideoFrameCount`     | `8`               | 1–16                                                                                                            |
| `modalityBridgeVideoSamplingPolicy` | `"uniform"`       | `uniform` أو `scene_aware` أو `segment_aware` التناسبي؛ ويؤدي فشل الكاشف إلى الرجوع إلى `uniform`               |
| `modalityBridgeVideoMaxVideos`      | `1`               | 1–4                                                                                                             |
| `modalityBridgeVideoTimeout`        | `120000`          | 1000–120000 مللي ثانية                                                                                          |

تُقيَّد قيم مهلة الفيديو القديمة المحفوظة التي تتجاوز 120 ثانية بالموعد
النهائي للوسيط؛ وتُرفض عمليات كتابة الإعدادات الجديدة التي تتجاوز ذلك الحد.
يتطلب `GET /api/modality-bridge/video/runtime` موقع loopback موثوقًا ومختومًا
قبل المصادقة أو فحص بيئة التشغيل، ثم يتطلب مصادقة إدارية.
ولا يعيد سوى `available` وإصدارات FFmpeg/ffprobe المنقّحة وسببًا ثابتًا
عندما تكون بيئة التشغيل غير متاحة. نقطة نهاية الاستخراج الداخلية ليست
واجهة API عامة للرفع: يؤدي تشبّع قائمة الانتظار إلى إرجاع `503` مع `Retry-After`،
ويؤدي قطع اتصال المستدعي إلى إرجاع `499`، بينما يؤدي بلوغ الموعد النهائي الثابت
للوسيط إلى إرجاع `504`. تضيف الاستجابات المحوّلة
`video->text;model=<visionModel>;parts=<videos>` إلى ترويسة
`x-omniroute-modality-bridge` المركزية من دون إزالة مقاطع Vision أو Audio.

### أداة إخفاء معلومات التعريف الشخصية (`piiMasker.ts`)

تعمل في **كلتا** المرحلتين.

- تنشئ **`preCall`** نسخة من الحمولة، وتجتاز `system` و`messages` و`input` و
  `prompt` (بما في ذلك عناصر السلاسل النصية العادية)، وتطبّق `processPII()` (من
  `@/shared/utils/inputSanitizer`) على حقول `content`/`text` النصية. عندما تكون
  `PII_REDACTION_ENABLED=true`، تُحجب معلومات التعريف الشخصية المكتشفة في
  الحمولة الصادرة. ويكون ذلك مستقلًا عن `INPUT_SANITIZER_MODE` (الذي يتحكم
  فقط في سياسة حقن المطالبات). عندما يكون الحجب معطلًا، تسجل المكالمة أعداد
  الاكتشافات من دون إعادة كتابة المحتوى.
- تنشئ **`postCall`** نسخة عميقة من الاستجابة، وتشغّل `sanitizePIIResponse()` إلى جانب
  أداة الإخفاء الخاصة ببنية Responses API‏ (`maskResponsesOutput` — التي تغطي
  `output_text` و`output[].content[].text`). إذا حدث أي حجب، تحل الاستجابة
  المعدّلة محل الاستجابة الأصلية.

لا يحظر حاجز الحماية أي طلب؛ بل يضيف تعليقات توضيحية فقط (`meta.detections`،
`meta.redacted`) أو يعيد الكتابة.

### حقن المطالبات (`promptInjection.ts`)

يكتشف البنى العدائية في المحتوى المقدّم من المستخدم ويفرض السياسة
المُعدّة. تحدد متغيرات البيئة وخيارات المُنشئ السلوك:

| الإعداد  | متغير البيئة                                                                                                | القيمة الافتراضية | التأثير                                                                                                                                                                                             |
| -------- | ----------------------------------------------------------------------------------------------------------- | ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| التمكين  | `INPUT_SANITIZER_ENABLED`                                                                                   | `true`            | عندما تكون القيمة `false`، ينهي حاجز الحماية التنفيذ مبكرًا.                                                                                                                                        |
| الوضع    | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                             | `warn`            | سياسة الحقن: `block` أو `warn` أو `log`. (تُقبل `redact` للتوافق مع الإصدارات السابقة، لكنها **لا** تزيل نص الحقن؛ تتحكم `PII_REDACTION_ENABLED` في إعادة كتابة معلومات التعريف الشخصية ضمن الطلب.) |
| حد الحظر | خيار `blockThreshold` / ‏`INPUT_SANITIZER_BLOCK_THRESHOLD` (الاسم البديل `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`            | الحد الأدنى من الخطورة المطلوب للحظر. تكون الخطورة المتوسطة للمراقبة فقط وفق الإعداد الافتراضي.                                                                                                     |

**أسبقية الوضع** (`getMode`): ‏`options.mode` الخاص بالمستدعي ←
تجاوز علامة الميزة في قاعدة البيانات لـ `INJECTION_GUARD_MODE` (**لوحة المعلومات → الإعدادات →
علامات الميزات**) ← متغير البيئة `INJECTION_GUARD_MODE` ← متغير البيئة
`INPUT_SANITIZER_MODE` ← ‏`warn`. ولذلك تكون لتجاوز لوحة المعلومات أسبقية على
متغيرات البيئة، بحيث تتحكم واجهة علامات الميزات في حاجز الحماية أثناء التشغيل
(من دون إعادة تشغيل). قراءة قاعدة البيانات آمنة عند الفشل: إذا حدث خطأ، يعود
حاجز الحماية إلى السلوك المستند إلى متغيرات البيئة، وعندما لا يكون هناك تجاوز
مُعيّن، يكون السلوك مطابقًا تمامًا للحل المعتمد على متغيرات البيئة فقط.

مصادر الاكتشاف:

1. ‏`sanitizeRequest()` من `@/shared/utils/inputSanitizer` (مجموعة الكواشف
   المشتركة المستخدمة في مواضع أخرى من مسار المعالجة).
2. ‏`DEFAULT_GUARD_PATTERNS` المضمّنة (حاليًا `system_override_inline` و
   `markdown_system_block`، وكلاهما بخطورة `high`).
3. ‏`customPatterns` اختيارية تُمرر عبر خيارات المُنشئ (سلاسل نصية أو تعبيرات
   نمطية أو سجلات `{ name, pattern, severity }`).

عندما يكون `mode === "block"` **و** يطابق اكتشاف واحد على الأقل حد الخطورة، تُرجع `preCall` القيمة `{ block: true, message: "Request rejected:
suspicious content detected" }`. في وضعي `warn`/`log`، يسجّل حاجز الحماية الحدث ولكنه
يسمح بالاستدعاء. كما تُصدَّر الدالة المساعدة المشتركة `evaluatePromptInjection()`
للمستدعين الذين يحتاجون إلى تقييم المطالبات دون المرور عبر السجل.

**حد الفحص (v3.8.20):** لا يفحص الكاشف سوى **أول 16 KB** من
نص المطالبة المضموم — `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 بايت) في
`src/shared/utils/inputSanitizer.ts`. تنفّذ كل من `detectInjection()` و
`evaluatePromptInjection()` العملية `slice(0, MAX_INJECTION_SCAN_BYTES)` قبل تشغيل
حلقة الأنماط. تقع توجيهات الحقن بالقرب من بداية الإدخال، ولذلك يحد هذا
من استهلاك CPU/GC للتعبيرات النمطية مع الحمولات التي يبلغ حجمها مئات KB دون إضعاف الاكتشاف (راجع
#3932، #4041).

### أداة إخفاء بيانات الاعتماد (`credentialMasker.ts`)

تعمل في **كلتا** المرحلتين، وتأتي أخيرًا في السلسلة الافتراضية (الأولوية `95`). تُخفي
أنماط مفاتيح API / الرموز السرية المعروفة جيدًا من الحمولة الصادرة (محتوى
الرسالة، ووسائط استدعاء الأدوات، ونتائج الأدوات) **وكذلك** من استجابة المزوّد، بحيث لا
تتسرب بيانات اعتماد ملصقة في مطالبة (أو يعيدها ناتج أداة) إلى
المزوّد الخارجي أو إلى العميل.

- **تفعيل اختياري فقط**، وفقًا للنهج نفسه المتّبع لتنقيح PII (بالقرب من القاعدة الصارمة #20):
  تكون معطّلة ما لم تكن `settings.credentialRedactionEnabled === true` **أو**
  `CREDENTIAL_REDACTION_ENABLED=true`. عندما تكون معطّلة، لا ينفّذ حاجز الحماية أي إجراء —
  فلا يحظر أبدًا ولا يعيد الكتابة أبدًا.
- تجتاز `redactCredentials()` شجرة الحمولة/الاستجابة كاملةً (`walkValue()`،
  بطريقة آمنة من تلوث النماذج الأولية، وآمنة من الدورات عبر `WeakSet`) وتستبدل التطابقات
  بعنصر نائب `[REDACTED:<type>]`، مع استنساخ الفروع التي تغيّرت فعليًا فقط.
- تغطي `CREDENTIAL_PATTERNS` مفاتيح مزوّدي LLM (OpenAI، OpenAI-proj،
  Anthropic، Google، Hugging Face، Replicate)، ورموز VCS/SaaS (GitHub، Slack،
  Linear، Notion، npm، Postman، Discord)، ومفاتيح الدفع (Stripe، Square)، ومفاتيح
  الخدمات السحابية (مفتاح وصول AWS، Twilio، SendGrid، Mailgun)، والمفاتيح الخاصة / رموز JWT،
  وسلاسل الاتصال التي تحتوي على بيانات اعتماد (`mongodb://user:pass@...`، إلخ)،
  ونمطًا عامًا لقيمة ترويسات `Authorization`/`x-api-key`/`api-key`/`apikey`.
  تُنقّح المفاتيح ذات شكل الترويسات (`authorization`، و`x-api-key`، و`api-key`،
  و`apikey`) بنيويًا (القيمة فقط، مع الحفاظ على بادئة النظام مثل
  `Bearer `/`Basic `) بدلًا من استخدام التعبير النمطي النصي العام.
- لا يحظر حاجز الحماية أبدًا؛ بل يعيد الكتابة فقط (`modifiedPayload` /
  `modifiedResponse`) ويضيف بيانات وصفية (`meta.credentialsRedacted`، و`meta.count`).

حاجز منع الانحدار: `tests/unit/credential-masker-guardrail.test.ts`.

## العقد الأساسي (`base.ts`)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // تؤدي القيمة true إلى إيقاف السلسلة فورًا
  message?: string; // تظهر عند الحظر
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // تُرجعها preCall لإعادة كتابة الطلب
  modifiedResponse?: TValue; // تُرجعها postCall لإعادة كتابة الاستجابة
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

يشير حاجز الحماية إلى «عدم وجود تغيير» عبر إرجاع `void` أو `{}` أو
`{ block: false }`. يؤدي إرجاع `modifiedPayload`/`modifiedResponse` إلى استبدال
القيمة المتدفقة عبر السلسلة لحواجز الحماية اللاحقة.
يحمل `signal?: AbortSignal` دورة حياة المستدعي إلى حواجز الحماية. يُعد إلغاء الطلب استثناءً مقصودًا يسمح بالمتابعة عند الفشل: إذ تتوقف جسور الوسائط عن العمل وتُجري التنظيف دون استعادة الوسائط الخام إلى هدف معروف بأنه لا يدعمها.

## السجل (`registry.ts`)

يكشف `guardrailRegistry` الأحادي عن:

- `register(guardrail)` — يضيف (أو يستبدل بالاسم المعياري) حاجزًا و
  يعيد الترتيب حسب `priority` التصاعدي.
- `clear()` / `list()` — مساعدات إدارية.
- `runPreCallHooks(payload, context)` — يكرر الحواجز النشطة، يمرر
  الحمولة عبر `modifiedPayload`، ويتوقف عند أول `block: true`.
- `runPostCallHooks(response, context)` — نفس التدفق على جانب الاستجابة.
- `resetGuardrailsForTests({ registerDefaults })` — يمسح الحالة و
  يعيد تسجيل الإعدادات الافتراضية اختياريًا لعزل الاختبار النظيف.

يعيد كل من المشغلين `{ blocked, payload|response, results, guardrail?, message? }`
حيث `results` هي مصفوفة من سجلات `GuardrailExecutionResult` التي تتضمن
حقول `blocked`, `skipped`, `modified`, `error`, و `meta` لكل حاجز،
مفيدة للتتبع.

### تعطيل الحواجز لكل طلب

يقوم `resolveDisabledGuardrails({ apiKeyInfo, body, headers })` بتجميع قائمة
غير مكررة لأسماء الحواجز التي يجب تخطيها للطلب الحالي. المصادر (جميعها اختيارية، وجميعها مدمجة):

- `apiKeyInfo.disabledGuardrails`
- نص الطلب `disabledGuardrails` (على المستوى الأعلى)
- نص الطلب `metadata.disabledGuardrails`
- الرأس `x-omniroute-disabled-guardrails` (أو القديم
  `x-disabled-guardrails`)

يمكن أن تكون القيم مصفوفات من السلاسل أو سلسلة مفصولة بفاصلة؛ يتم
تطبيع الأسماء إلى صيغة kebab-case بالأحرف الصغيرة (`pii_masker` ← `pii-masker`).
يتم تمرير النتيجة عبر `context.disabledGuardrails` إلى السجل، الذي يتخطى
الحواجز المطابقة (`skipped: true` في `results`).

## ترتيب التنفيذ

لكل طلب يمر عبر `src/sse/handlers/chat.ts` و `open-sse/handlers/chatCore.ts`:

1.  يقوم `resolveDisabledGuardrails(...)` بإنشاء قائمة التخطي من مفتاح API، والنص الأساسي، والرؤوس.
2.  يقوم `guardrailRegistry.runPreCallHooks(body, ctx)` بتشغيل الحواجز الأمنية بترتيب تصاعدي للأولوية:
    - يتم تسجيل الحواجز الأمنية المعطلة على أنها `skipped`.
    - قد يقوم `preCall` لكل حاجز أمني بإعادة كتابة الحمولة عبر `modifiedPayload`.
    - أول `block: true` يقطع السلسلة ويعيد المعالج استجابة رفض الحاجز الأمني.
3.  تتدفق الحمولة (التي قد تكون أعيدت كتابتها) إلى توجيه التحرير والسرد والإرسال الأولي.
4.  بعد تجميع الاستجابة، يقوم `guardrailRegistry.runPostCallHooks(...)` بتشغيل نفس السلسلة على الاستجابة. `block: true` هنا يسقط الاستجابة الأولية.

يتم تسجيل الحواجز الأمنية التي تثير خطأ بـ `error: <message>` ويتم تسجيلها عبر `logger.warn`، لكن السلسلة تستمر — تصميم يسمح بالفشل المفتوح.

## التكوين

متغيرات البيئة التي تقرأها الحواجز الأمنية المدمجة:

| المتغير | يستخدم بواسطة | التأثير |
| `INPUT_SANITIZER_ENABLED` | `prompt-injection` | تعيين `false` لتعطيل الكشف بالكامل. |
| `INPUT_SANITIZER_MODE` | `prompt-injection` | سياسة الحقن: `warn` (تحذير)، `block` (حظر)، أو `log` (تسجيل). القيمة القديمة `redact` لا تعيد كتابة نص الحقن. |
| `INJECTION_GUARD_MODE` | `prompt-injection` | وضع حماية الحقن؛ وهو أيضًا علامة ميزة قاعدة بيانات **تتجاوز** متغيرات البيئة (قاعدة البيانات > البيئة). |
| `INPUT_SANITIZER_BLOCK_THRESHOLD` | `prompt-injection` | الحد الأدنى للخطورة الذي يرفضه `MODE=block`: `high` (مرتفع، افتراضي)، `medium` (متوسط)، أو `low` (منخفض). |
| `INJECTION_GUARD_BLOCK_THRESHOLD` | `prompt-injection` | اسم مستعار قديم لـ `INPUT_SANITIZER_BLOCK_THRESHOLD`. |
| `PII_REDACTION_ENABLED` | `pii-masker` | عندما يكون `true`، يتم تنقيح معلومات التعريف الشخصية (PII) للطلب (بصرف النظر عن وضع الحقن). |
| `PII_RESPONSE_SANITIZATION` / `_MODE` | `pii-masker` (downstream) | يتحكم في سلوك قناع الاستجابة. |

تقرأ الحواجز الأمنية لـ Modality Bridge التكوين في وقت التشغيل من مخزن الإعدادات المدعوم بقاعدة البيانات (`getSettings()`)، وليس من متغيرات البيئة. المفاتيح الأساسية لـ Vision هي `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, و `modalityBridgeCacheMaxEntries`. يتم قبول المفاتيح القديمة `visionBridge*` فقط كخيار احتياطي للقراءة لمرة واحدة كما هو موثق؛ تستخدم عمليات الكتابة في لوحة التحكم المفاتيح الأساسية. توجد القيم الافتراضية ومحلل الاحتياطي في `src/shared/constants/modalityBridgeDefaults.ts`، مع الاحتفاظ بالثوابت القديمة في `src/shared/constants/visionBridgeDefaults.ts`.

يستخدم الصوت `modalityBridgeAudioEnabled`, `modalityBridgeAudioModel`, `modalityBridgeAudioTimeout`, و `modalityBridgeAudioMaxClips`, بالإضافة إلى إعدادات `modalityBridgeCache*` المشتركة. لا يحتوي الصوت على خيار احتياطي للمفاتيح القديمة لأن هذه المفاتيح تم تقديمها مع مخطط Modality Bridge.

يستخدم الفيديو `modalityBridgeVideoEnabled`, `modalityBridgeVideoAnalysisMode`, `modalityBridgeVideoModel`, `modalityBridgeVideoFrameCount`, `modalityBridgeVideoSamplingPolicy`, `modalityBridgeVideoMaxVideos`, و `modalityBridgeVideoTimeout`, بالإضافة إلى إعدادات `modalityBridgeCache*` المشتركة. يتم تعطيله افتراضيًا لأن FFmpeg/ffprobe هي تبعيات تشغيلية اختيارية، وإضافة تسميات الإطارات تزيد من زمن الاستجابة وتكلفة النموذج.

## حواجز حماية مخصصة

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

الخطوات:

1.  أنشئ `src/lib/guardrails/myGuardrail.ts` يوسع `BaseGuardrail`.
2.  نفّذ `preCall` و/أو `postCall`.
3.  سجّل إما وقت الاستيراد (ادفع من `registerDefaultGuardrails`) أو
    استدعِ `guardrailRegistry.register(...)` في وقت التشغيل — يحل السجل محل
    أي حاجز حماية سابق بنفس الاسم المعياري.
4.  أضف اختبارات تحت `tests/unit/` (أمثلة موجودة:
    `tests/unit/guardrails-registry.test.ts`,
    `tests/unit/prompt-injection-guard.test.ts`,
    `tests/unit/guardrails/visionBridge.test.ts`).

## الاختبار

استخدم `resetGuardrailsForTests()` بين الاختبارات للبدء من حالة معروفة.
مرر `{ registerDefaults: false }` للبدء بسجل فارغ و
تسجيل حواجز الحماية قيد الاختبار فقط. يقبل Vision Bridge حقن التبعية
(`deps.getSettings`, `deps.callVisionModel`)؛ يعرض Audio Bridge
الوصلات المكافئة للإعدادات، والقدرات، واختيار نموذج STT، وفحوصات الاعتماد،
والنسخ. وبالتالي يمكن للاختبارات ممارسة كلا التدفقين بدون قاعدة بيانات
أو الوصول إلى الشبكة.

## تغطية مسار حماية الحقن والاختبار الأحمر (المرحلة 8 · الكتلة D)

يغطي حارس الحقن (`createInjectionGuard` / `withInjectionGuard`) جميع المسارات
التي تقبل مطالبات المستخدم. وهو يحترم `INJECTION_GUARD_MODE` (الافتراضي `warn` = تسجيل فقط؛
`block` = يعيد HTTP 400 `SECURITY_001`).

| النوع      | المسارات                                                                                                                                             | الوضع الافتراضي |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- |
| نص (موجود) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                              | warn            |
| توليدي     | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn            |
| بيانات     | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                                      | warn            |

تغطية استخراج النص (`extractMessageContents`) تشمل `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system`.

**الفريق الأحمر (ليلي، `nightly-llm-security.yml`):** يتحقق promptfoo من أن كل مسار يحظر
مجموعة OWASP-LLM في `INJECTION_GUARD_MODE=block`؛ يقوم garak بتشغيل الفحوصات (يتخطى بدون سر).
يتم تضمين `moderations` من أجل الاتساق — يمكن للمشغلين في وضع الحظر إعفائها عبر
`resolveDisabledGuardrails`.

يحتوي سير العمل الليلي (`.github/workflows/nightly-llm-security.yml`، cron +
التشغيل اليدوي) على وظيفتين:

- **`promptfoo-guard` (حظر)** — يشغل `promptfoo eval -c promptfooconfig.yaml`
  مع `INJECTION_GUARD_MODE=block`. تؤكد كل حالة عدائية (مثل "تجاهل جميع
  التعليمات السابقة..."، اختراقات على غرار DAN) أن الاستجابة تحمل
  `error.code === "SECURITY_001"`، أي أن الحارس رفض الطلب بالفعل.
- **`garak` (استشاري)** — يشغل garak `--probes promptinject,dan,leakreplay`
  مقابل مثيل OmniRoute محلي (`http://localhost:20128/v1`). يتم التحكم فيه بواسطة
  سر مزود (`PROMPTFOO_PROVIDER_KEY`)؛ يتخطى بأمان ويتم إلحاقه بـ
  `|| true`، لذلك يتم الإبلاغ عنه دون فشل CI.

تغطية مساعد الحارس (`createInjectionGuard` / `withInjectionGuard`)
تمتد عبر كل مسار `/v1` يحمل مطالبة؛ يتم سحب نص المطالبة من
`messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` بواسطة
`extractMessageContents()` في `src/shared/utils/inputSanitizer.ts`.
