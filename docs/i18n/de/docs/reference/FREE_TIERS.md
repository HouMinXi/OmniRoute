## TL;DR — wie viel kostenlose Inferenz bündelt OmniRoute tatsächlich?

Diese Zahlen beschreiben separate Konten bei Drittanbietern sowie die jeweiligen Teilnahmevoraussetzungen im gesamten Katalog. OmniRoute stellt dieses Budget nicht bereit: Sie müssen die erforderlichen Konten oder Zugangsdaten selbst beschaffen, berechtigte Anbieter verbinden und deren Limits einhalten. Die tatsächlich nutzbare Kapazität kann geringer sein — bis hin zu null bei einer Neuinstallation ohne zulässige Route. Mit `tos: avoid` gekennzeichnete Anbieter sind standardmäßig vom automatischen Routing ausgeschlossen.

**Geprüft am 2026-10-08:** [Cerebras](https://www.cerebras.ai/pricing) bietet ein einmaliges Aktionsguthaben von $5, für das eine Zahlungsmethode erforderlich ist und das nach 30 Tagen verfällt. [Gemini](https://ai.google.dev/gemini-api/docs/rate-limits) veröffentlicht Ratenlimits nach Projekt, Modell und Tarif; der Anbieter bleibt außerhalb der quantifizierten monatlichen Hauptangabe.

| Kennzahl                                               | Token / Monat           | Bedeutung                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------------------------------ | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Dokumentiertes wiederkehrendes Kontingent**          | **~1.62B**              | **Pools** kostenloser Tarife (Katalog pro Modell), wobei jeder gemeinsam genutzte Pool nur **einmal** gezählt wird. Die aktuelle Datenquelle hinter `/api/free-tier/summary` und der Seite „Free-Tier Budget“ im Dashboard. **Verwenden Sie diese Zahl.**                                                                                       |

| **+ dauerhaft kostenlos, ohne veröffentlichtes Limit** | _nicht quantifizierbar_ | `siliconflow`, `glm-cn` (GLM-4-Flash), `tencent`, `baidu`, `kilo-gateway`, `opencode-zen`, `gemini`, `ollama-cloud` — echter wiederkehrender Zugriff, durch Rate und Parallelität begrenzt, aber **ohne zählbares Token-Limit**. Aufgeführt, jedoch nie summiert (eine Berechnung als `RPM×24/7` wäre genau jene Aufblähung, die wir ablehnen). |

Die Komprimierung durch RTK + Caveman (15–95 % Token-Einsparung) steigert die Reichweite zusätzlich._

## 2026-10-15 Korrektur zu Bytez und Nous

Die [Bytez-Abrechnung](https://docs.bytez.com/model-api/docs/billing) begrenzt die offenen Modelle des kostenlosen Tarifs
auf 7B Parameter. Die Einträge mit 70B und 72B erfordern eine Freischaltung
durch gekauftes Guthaben und wurden entfernt. Mistral-7B bleibt `recurring-credit`: Das Guthaben
wird alle vier Wochen erneuert, die Abrechnung erfolgt jedoch pro Inferenzsekunde, und es wird kein Token-
Kontingent veröffentlicht. Die Token-Zähler stehen auf null, um eine unbekannte
Menge darzustellen, und ersetzen damit die unbelegte Schätzung von 1M Token; dies bedeutet nicht, dass
kein kostenloses Guthaben vorhanden ist. Die Änderungen zu Nous werden im nachstehenden Anbieterhinweis ausführlich beschrieben.

## Zwei Regime — Zählen vs. Entscheiden

OmniRoute beantwortet die Frage „Ist es kostenlos?“ anhand zweier Regime, die bewusst
unterschiedliche Quellen heranziehen:

| Regime                | Maßgebliche Quelle                                                                                                                                                                    | Einsatzbereiche                                                                                                                    |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **Zählen / Anzeigen** | Aufgelöster Katalog — die ausgelieferte Basis, überlagert durch den Radar-Feed (`getRadarCatalog`)                                                                                    | Gesamtsummen des kostenlosen Kontingents, Budgetkarte, Dashboards                                                                  |
| **Entscheiden**       | Nur der ausgelieferte Katalog (`FREE_MODEL_BUDGETS` in `open-sse/config/freeModelCatalog.data.ts`) sowie die lokalen Heuristiken (Suffix `:free`, Preis von null, `grantsFreeAccess`) | Alle Verbraucher von `src/shared/utils/freeModels.ts`: Modellimport, `auto/*`-Routing, `GET /v1/models` und die Browser-Vorschauen |

Die Zählung kann verbessert werden, sobald ein Feed verfügbar ist. Das Entscheiden bleibt an das
Release-Artefakt gebunden, sodass die Antwort im Browser und auf dem Server identisch,
offline reproduzierbar und ohne Datenbank testbar ist. Würde die Browser-
Vorschau eine andere Quelle verwenden als der Serverimport, könnte die
Vorschau dem widersprechen, was beim Klicken tatsächlich geschieht — diese Trennung wird
bewusst beibehalten.

## Methodik & Einschränkungen

- Die Zahlen sind **Obergrenzenschätzungen**, die auf den von den jeweiligen Anbietern dokumentierten Limits der kostenlosen Kontingente mit Stand vom **2026-06-17** beruhen und durch Webrecherche ermittelt wurden. Kostenlose Kontingente ändern sich laufend — überprüfen Sie die Angaben erneut, bevor Sie sich auf eine Zahl verlassen.
- **Wofür ein Eintrag tatsächlich bürgt.** Kein Eintrag verfügt über eine individuelle Vertrauensbewertung, und die API liefert ebenfalls keine — behandeln Sie jede obige Zahl als Schätzung derselben, nicht näher angegebenen Qualität. Zwei Fakten unterscheiden sich davon, weil sie manuell gepflegt und nicht abgeleitet werden: 44 Einträge enthalten eine unabhängig dokumentierte harte Obergrenze (39 davon sind die xKiro-Zeilen, die alle dasselbe tägliche Kontingent verwenden), und 13 Einträge enthalten einen Hinweis zur Verwendung von Prompts für das Training. `hardStopGuaranteed` wird nur gesetzt, wenn laut den eigenen Bedingungen des Anbieters bei Überschreitung des kostenlosen Kontingents die Anfrage abgelehnt wird, anstatt stillschweigend eine Abrechnung zu beginnen; die Quelle steht in einem Kommentar neben dem Eintrag. Der Wert wird niemals standardmäßig auf `true` gesetzt, und bei einem Eintrag, den noch niemand überprüft hat, bleibt er ungesetzt. Ein fehlendes Hard-Stop-Flag bedeutet daher „nicht nachgewiesen“ und nicht „es ist bekannt, dass Kosten berechnet werden“. Der **STRICT-Modus** (die optionale Routing-Schutzvorrichtung `freeAccessPolicy=strict`) vertraut ausschließlich Einträgen, die dieses Flag enthalten; jedes andere kostenlose Kontingent wird als `no-hard-stop` ausgeschlossen (siehe `open-sse/services/autoCombo/strictZeroCostFilter.ts`). Wenn die Schutzvorrichtung einen Pool filtert, meldet das für den Betreiber sichtbare Protokoll sowohl die Anzahl der Ausschlüsse als auch deren Anteil mit `no-hard-stop`.
- `estMonthlyFreeTokens` = ausschließlich monatlich wiederkehrende Tokens. **Einmalige Startguthaben wiederholen sich nicht** und zählen als 0. Eingestellte Kontingente zählen ebenfalls als 0.
- Tägliches Token-Limit → `monthly = daily × 30`. Wenn nur RPD dokumentiert ist → `RPD × ~800 output tokens × 30`. Wenn nur RPM/TPM (kein tägliches Limit) dokumentiert ist → **unbegrenzt** (siehe unten).
- **Dauerhaft kostenlos, jedoch ohne veröffentlichtes Token-Limit** (`siliconflow`, `glm-cn`, `tencent`, `baidu`, `kilo-gateway`, `opencode-zen`, `gemini`, `ollama-cloud`): Hierbei handelt es sich um echten, wiederkehrenden kostenlosen Zugang, der durch Raten- bzw. Parallelitätslimits begrenzt ist. Wir klassifizieren ihn als `recurring-uncapped` und **summieren ihn niemals** — eine Multiplikation von `RPM × 24/7 × 30d` würde eine unrealistische Obergrenze ergeben (genau die Art von Aufblähung, die wir ablehnen). Diese Angebote werden aufgeführt, damit ihre Existenz bekannt ist.
- **Freischaltungsbonus durch Einzahlung:** eine kleine, einmalige Aufladung, die ein kostenloses Kontingent dauerhaft erhöht (OpenRouter: $10 → 1000 Anfragen/Tag ≈ +24 Mio./Monat). Wird als separate Zahl ausgewiesen und nicht in die dauerhaft verfügbare Hauptkennzahl einbezogen.
- **An Voraussetzungen gebundene Kontingente** (`eligibilityGate: "regional-identity"`): ein echtes, wiederkehrendes Kontingent, das erst nach einer regionsgebundenen Identitätsprüfung freigeschaltet wird (derzeit eine chinesische Klarnamenverifizierung für Festlandchina). Wird nach derselben Pool-Deduplizierungsregel in eine separate Zahl (`gatedRecurringTokens`) eingerechnet, jedoch niemals in die dauerhaft verfügbare Hauptkennzahl. Das Regime (`freeType`) bleibt unverändert, sodass auch das Routing unverändert bleibt.
- **Evidenzklassen.** Die Regel lautet: Eine Zahl im Katalog nennt ihre Quelle in einem `// evidence:`-Kommentar neben dem Eintrag — `public-page` (eine öffentlich zugängliche Anbieterseite), `api-public` (ein nicht authentifizierter Endpunkt des Anbieters, z. B. der öffentliche Tarifendpunkt von NaraRouter unter router.bynara.id) oder `console-verified <date> por <who>` (die Zahl ist nur innerhalb einer Kontokonsole sichtbar; der Kommentar hält fest, wer sie wann gesehen hat, sowie die öffentliche Seite, die bestätigt, dass das Limit existiert). Aktueller Stand: Die fünf am 2026-09-02 erneut geprüften Blöcke enthalten diese Angabe (`gemini`, `groq`, `mistral`, `ollama-cloud`, `nara`); Einträge, die vor der erneuten Prüfung am 2026-09-02 entstanden sind, übernehmen bis zu ihrer nächsten Bearbeitung den Stand der früheren Recherche; jede **neue oder geänderte** Zahl ohne Evidenzkommentar ist ein Fehler. Derzeit ist nur `mistral` konsolenverifiziert.

## Warum unsere Zahl kleiner ist als die anderer Aggregatoren

Die meisten Angaben zu „kostenlosen Tokens pro Monat“ in diesem Bereich sind Summen der Angaben pro Modell. Unsere ist das bewusst nicht:

- **Jeder gemeinsam genutzte Pool wird nur einmal gezählt.** Der kostenlose Tarif von Mistral umfasst ein Kontingent von 1B/Monat pro Organisation; ihn unter fünf Modellen aufzuführen, macht daraus nicht 5B. Pro Modell summiert würde unser eigener Katalog **~7.4B** ausweisen (neu berechnet am 2026-09-03; diese Zahl wird nicht durch CI geprüft — berechnen Sie sie erneut, wenn sich der Katalog ändert) — in der Überschrift steht **~1.47B**, weil dies der Betrag ist, den jeweils ein Konto jedes Anbieters tatsächlich nutzen kann.
- **Tageslimits werden umgerechnet, Ratenlimits nicht.** Ein dokumentiertes Limit von Tokens/Tag wird zu `× 30`; ein dokumentiertes Limit von Anfragen/Tag wird zu `RPD × ~800 Tokens × 30`; ein Anbieter, der nur Anfragen pro Minute veröffentlicht, erhält **keine** Monatsangabe und wird als _unbegrenzt_ aufgeführt, aber niemals zur Summe addiert. Ein Ratenlimit auf einen 24/7-Betrieb hochzurechnen, ist genau die Aufblähung, die wir ablehnen.
- **Kontingente, die eine regionale Identitätsprüfung voraussetzen, werden separat ausgewiesen** (`+~6M nach regionaler Identitätsprüfung`), da die meisten Leser sie nicht nutzen können.
- **Guthaben für die Registrierung gilt nur für den ersten Monat** und wird als zweite Zahl angegeben, niemals mit dem dauerhaften Wert vermischt.
- **Die Zahl wird durch CI erzwungen.** `npm run check:docs-counts` berechnet die Summen aus dem Katalog neu und lässt den Build fehlschlagen, wenn diese Datei, die README oder die Budgetkarte davon abweichen.

## Glossar

| Begriff                       | Bedeutung                                                                                         |
| ----------------------------- | ------------------------------------------------------------------------------------------------- |
| **RPM / RPD / RPH**           | Anfragen pro Minute / Tag / Stunde                                                                |
| **TPM / TPD**                 | Token pro Minute / Tag                                                                            |
| **Dokumentiertes Kontingent** | Der Anbieter veröffentlicht ein explizites tägliches/monatliches Token-Limit (belastbares Budget) |
| **Theoretische Obergrenze**   | `rate-limit × 24/7 × 30d` — ein Maximum, kein gewährtes Budget                                    |
| **Neuron**                    | Cloudflare-Recheneinheit (~1 Ausgabe-Token)                                                       |
