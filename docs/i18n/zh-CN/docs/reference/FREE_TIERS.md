## TL;DR — OmniRoute 实际汇总了多少免费推理额度？

## 两种机制——统计与判定

OmniRoute 通过两种机制回答“它是否免费？”，这两种机制有意读取不同的数据源：

| 机制            | 事实来源                                                                                                                                                 | 适用界面                                                                                              |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| **统计 / 展示** | 解析后的目录——发布时的基线数据叠加 Radar 数据源（`getRadarCatalog`）                                                                                     | 免费层总量、预算卡片、仪表板                                                                          |
| **判定**        | 仅使用发布时的目录（`open-sse/config/freeModelCatalog.data.ts` 中的 `FREE_MODEL_BUDGETS`）以及本地启发式规则（`:free` 后缀、零定价、`grantsFreeAccess`） | `src/shared/utils/freeModels.ts` 的所有使用方：模型导入、`auto/*` 路由、`GET /v1/models` 和浏览器预览 |

只要数据源可用，统计结果就可以得到改进。判定则始终基于发布产物，因此浏览器与服务器上的答案完全一致，可在离线环境中复现，也可在没有数据库的情况下测试。如果让浏览器预览读取一个数据源，而服务器导入读取另一个数据源，就会导致预览结果与点击后实际发生的情况不一致——这种划分是有意保留的。

## 方法与注意事项

- 这些数字是根据各提供者截至 **2026-06-17** 公布的免费层限制，通过网络调研得出的**上限估算值**。免费层经常变化——在依赖任何数字之前，请重新核实。
- **每个条目实际担保的内容。** 各条目都没有逐行置信度评级，API 也不提供此类评级——应将上面的每个数字都视为具有相同但未明确说明质量水平的估算值。有两类事实有所不同，因为它们是人工整理的，而不是推断得出的：44 个条目带有独立记录的硬性停止机制（其中 39 个是 xKiro 条目，它们都共享同一个每日额度），另有 13 个条目带有提示词训练披露。仅当提供者自己的条款明确说明，超出免费额度后会拒绝请求，而不是在无提示的情况下开始计费时，才会设置 `hardStopGuaranteed`；其来源会写在该条目旁边的注释中。它绝不会默认设置为 `true`，而且无人核实过的条目会保持未设置状态。因此，缺少硬性停止标记意味着“尚未确认”，而不是“已知会向你收费”。**STRICT 模式**（选择启用的 `freeAccessPolicy=strict` 路由防护）只信任带有该标记的条目；所有其他免费层都会以 `no-hard-stop` 为由被排除（参见 `open-sse/services/autoCombo/strictZeroCostFilter.ts`）。当该防护对候选池进行过滤时，面向运维人员的日志会同时报告排除数量以及其中 `no-hard-stop` 所占的比例。
- `estMonthlyFreeTokens` = 仅计算每月重复提供的 token。**一次性注册赠送额度不会重复发放**，因此按 0 计算。已停止提供的层级同样按 0 计算。
- 每日 token 上限 → `monthly = daily × 30`。如果只公布了 RPD → `RPD × ~800 个输出 token × 30`。如果只公布了 RPM/TPM（没有每日上限）→ **无上限**（见下文）。
- **永久免费，但未公布 token 上限**（`siliconflow`、`glm-cn`、`tencent`、`baidu`、`kilo-gateway`、`opencode-zen`、`gemini`、`ollama-cloud`）：这些都是真实、持续提供的免费访问，但受到速率或并发限制。我们将它们归类为 `recurring-uncapped`，并且**绝不计入总和**——用 `RPM × 24/7 × 30d` 相乘会得出一个不切实际的理论上限（我们拒绝这种夸大方式）。将它们列出是为了让你知道它们确实存在。
- **充值解锁增益：** 一次性小额充值可永久提高免费配额（OpenRouter：$10 → 1000 次请求/天 ≈ 每月增加 24M）。该数字单独报告，不计入稳定额度的标题数字。
- **受资格限制的配额**（`eligibilityGate: "regional-identity"`）：真实且持续提供的配额，但只有通过与地区绑定的身份验证后才会开放（目前为中国大陆实名认证）。按照相同的池去重规则计入单独的数字（`gatedRecurringTokens`），绝不计入稳定额度的标题数字。其机制（`freeType`）保持不变，因此路由行为也不会改变。
- **证据类别。** 规则是：目录中的数字必须在条目旁边的 `// evidence:` 注释中引用其来源——`public-page`（任何人都能访问的提供者页面）、`api-public`（提供者无需身份验证即可访问的端点，例如 NaraRouter 位于 router.bynara.id 的公开套餐端点），或 `console-verified <date> por <who>`（该数字只能在账户控制台中看到；注释会记录查看者和查看时间，以及说明该上限存在的公开页面）。当前状态：在 2026-09-02 重新审核的五个区块都带有此信息（`gemini`、`groq`、`mistral`、`ollama-cloud`、`nara`）；早于 2026-09-02 重新审核的条目在被修改前继续沿用此前的调研结果；任何没有证据注释的**新增或变更**数字都属于 bug。目前只有 `mistral` 经控制台验证。

## 为什么我们的数字小于其他聚合器的数字

该领域大多数“每月免费 token”数字，都是将各模型标注的额度相加得出的。我们的数字并非如此，这是有意为之：

- **每个共享额度池只计算一次。** Mistral 的免费计划为每个组织提供每月 1B 的统一额度；将其列在五个模型下并不会使其变成 5B。如果按模型相加，我们自己的目录将显示 **~7.4B**（于 2026-09-03 重新计算；此数字不受 CI 检查约束——每当目录发生变化时都应重新测算）——标题显示 **~1.47B**，因为这才是每个提供者各一个账户实际可用的额度。
- **每日上限会被换算，速率限制不会。** 已记录的 tokens/day 上限会换算为 `× 30`；已记录的 requests/day 上限会换算为 `RPD × ~800 tokens × 30`；如果提供者只公布 requests-per-minute，则**不会**给出月度数字，而是标记为_无上限_，且绝不会计入总和。将速率限制按 24/7 全天候运行来计算，正是我们拒绝采用的夸大方式。
- **需要区域身份验证才能使用的配额会单独列出**（`+~6M behind regional identity verification`），因为大多数读者无法使用这些配额。
- **注册赠送额度仅适用于首月**，并作为第二个数字报告，绝不会混入稳定的月度数字中。
- **该数字由 CI 强制校验。** `npm run check:docs-counts` 会根据目录重新计算总额；当本文件、README 或预算卡片中的数字与计算结果不一致时，构建将失败。

## 术语表

| 术语                | 含义                                                   |
| ------------------- | ------------------------------------------------------ |
| **RPM / RPD / RPH** | 每分钟 / 每天 / 每小时的请求数                         |
| **TPM / TPD**       | 每分钟 / 每天的 token 数                               |
| **明确授予额度**    | 提供者公布的明确每日/每月 token 上限（可作为预算依据） |
| **理论上限**        | `rate-limit × 24/7 × 30d` — 最大值，并非授予的预算     |
| **Neuron**          | Cloudflare 计算单位（约等于 1 个输出 token）           |
