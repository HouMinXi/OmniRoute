## TL;DR — OmniRouteが実際に集約する無料推論量はどのくらいですか？

これらの数値は、カタログ全体にわたる個別のサードパーティーアカウントと利用資格条件を示しています。OmniRoute自体がこの予算を付与するわけではありません。必要なアカウントまたは認証情報を取得し、利用資格のあるプロバイダーを接続して、それぞれの制限を遵守する必要があります。実際に利用可能な容量はこれより少ない場合があり、利用可能なルートがない新規インストールではゼロになることもあります。`tos: avoid`と指定されたプロバイダーは、デフォルトでは自動ルーティングから除外されます。

**2026-10-08確認済み:** [Cerebras](https://www.cerebras.ai/pricing)は、支払い方法の登録が必要で、30日後に失効する1回限りの$5プロモーションクレジットを提供しています。[Gemini](https://ai.google.dev/gemini-api/docs/rate-limits)は、プロジェクト／モデル／ティアごとのレート制限を公開していますが、引き続き月間合計の定量値には含めていません。

| 指標                                            | トークン/月  | 意味                                                                                                                                                                                                                                                                                                                                          |
| ----------------------------------------------- | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **文書化された継続的な付与量（定常時）**        | **~1.62B**   | 無料枠の**プール**（モデルごとのカタログ）で、共有プールはそれぞれ**1回のみ**計上しています。`/api/free-tier/summary`とダッシュボードの無料枠予算ページが参照するライブソースです。**この数値を使用してください。**                                                                                                                           |
| **+ 登録クレジットを含む初月**                  | **~2.22B**   | 定常時の付与量＋1回限りの登録クレジット（Z.AI 20M、DeepSeek 5M、…）で、アカウントごとに重複排除済みです。**初月のみ**で、継続的には付与されません。                                                                                                                                                                                           |
| **+ 恒久的に無料、公開上限なし**                | _定量化不能_ | `siliconflow`、`glm-cn`（GLM-4-Flash）、`tencent`、`baidu`、`kilo-gateway`、`opencode-zen`、`gemini`、`ollama-cloud` — 実際に継続利用でき、レート／同時実行数の制限はありますが、**計上可能なトークン上限はありません**。一覧には掲載しますが、合計には一切加算しません（`RPM×24/7`で計算することは、ここで排除している水増しに当たります）。 |
| **+ 入金による上限引き上げ**                    | **+~24M**    | OpenRouterに1回限りの**$10**の追加入金を行うと、無料プールが1日50リクエストから1000リクエストに引き上げられます。定常時の数値を水増ししないよう、別途報告しています。                                                                                                                                                                         |
| **+ 地域別の本人確認が必要な枠**                | **+~6M**     | `modelscope`（Alibaba Cloudとの連携＋中国本土での実名認証）。実在する継続クォータで、`gatedRecurringTokens` / `gatedProviders`およびダッシュボードに表示されます。主要な合計値には一切加算しません。地域別の本人確認を行うことで+~6Mを利用できます。                                                                                          |
| 理論上の上限（すべてのレート制限、24時間365日） | ~10B         | すべてのプロバイダーのレート制限を休みなく利用した場合に外挿した合計です。**保証値ではありません**。主要な数値として掲げないでください。                                                                                                                                                                                                      |

**誠実な要約:** _OmniRouteは、34の無料枠プール全体で、文書化された無料トークンを**月間~1.62B**集約します（登録クレジットを含む初月は最大~2.22B）。さらに、恒久的に無料で上限が公開されていない多数のプロバイダーも利用でき、RTK + Caveman圧縮（15～95%のトークン削減）によってさらに利用量を伸ばせます。_

>
> **v3.8.42でさらに約1.37Bへ修正：** `longcat` は、無料プレビュー終了後、継続付与される150M/月から、1回限りの10Mサインアップクレジットへ再分類されました。同じ正確性の原則に基づくものであり、誤って削除されたプロバイダーはありません。
>
> **Felo Webの廃止後、2026-08-26に更新：** Felo Webは、GPL由来の来歴・ライセンスが保留中であるため除外されています。当時、ソースでは38個のプールキーが報告されていました。プール数はライブであり、CIによって検証されています（上記の数値が`computeFreeModelTotals()`と一致しなくなると、`check:docs-counts`がビルドを失敗させます）。

> **2026-09-02にプロバイダー自身のページに基づいて再監査済み**（出典：`open-sse/config/freeModelCatalog.data.ts`内で、再監査された各エントリの横にある`// evidence:`コメント）：`gemini`と`ollama-cloud`はトークン数を公開しなくなりました（Googleは2025-12-23にモデル別の無料枠テーブルを削除し、OllamaのFreeプランは「starter usage credits」とされています）。そのため現在は**上限なし**として掲載され、合計には一切含まれません（−80M）。`groq`には、5つの**モデル別**200K TPD上限（各6M、+15M）があり、廃止された3つのIDは削除されました。`nara`は1日あたり7Mの単一バケットです（+60M、210M）。`mistral`の1Bはアカウントコンソール内でのみ確認できます。方法論の_Evidence classes_を参照してください。

**文書で確認できる**最大のコントリビューター：`mistral` 1.00B、`nara` 210M、`llm7` 150M、`xkiro` 150M、`groq` 30M（5つのモデル別上限）、`cloudflare-ai` 30M、`api-airforce` 24M。（`longcat`は除外されています。その10MのLongCat-2.0付与枠は、継続的な月間予算ではなく、KYCが必要な1回限りのサインアップクレジットです。）

> ⚠️ 理論上の上限（約10B）は、**公開されたトークン上限がない**レート制限のみのプロバイダー（`tencent`、`siliconflow`、`nvidia`、`baidu`、`glm-cn`、`sparkdesk`）によって水増しされています。これらの数値は`RPM/TPM × 24/7 × 30d`で算出されますが、これは単一のアカウントでは維持できない理論上の最大値です。そのため、根拠をもって説明可能な数値からは**除外**されています（代わりに「永続無料、上限なし」の行に表示されます）。これは、競合他社による数十億規模の主張を信頼できなくしている水増しと同じものです。

## 2026-10-15 BytezおよびNousの修正

[Bytezの請求体系](https://docs.bytez.com/model-api/docs/billing)では、Freeプランの
オープンモデルはパラメータ数7Bまでに制限されています。70Bおよび72Bのエントリは購入済みクレジットによる
アンロックが必要なため、削除されました。Mistral-7Bは引き続き `recurring-credit` です。クレジットは
4週間ごとに更新されますが、課金は推論秒単位であり、トークン許容量は
公開されていません。トークンカウンターは、裏付けのない1Mトークンという推定値の代わりに、数量不明を示すゼロに設定されています。これは無料
クレジットがゼロであることを意味しません。Nousに関する変更の詳細は、下記のプロバイダー注記に記載されています。

## 2つのレジーム — 集計と判定

OmniRoute は、「無料か？」という問いに対し、意図的に異なるソースを参照する2つのレジームで回答します。

| レジーム        | 信頼できる情報源                                                                                                                                                               | 対象                                                                                                                                 |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| **集計 / 表示** | 解決済みカタログ — 出荷時のベースラインに Radar フィードを重ねたもの（`getRadarCatalog`）                                                                                      | 無料枠の合計、予算カード、ダッシュボード                                                                                             |
| **判定**        | 出荷時のカタログのみ（`open-sse/config/freeModelCatalog.data.ts` 内の `FREE_MODEL_BUDGETS`）とローカルヒューリスティック（`:free` サフィックス、ゼロ価格、`grantsFreeAccess`） | `src/shared/utils/freeModels.ts` のすべての利用箇所：モデルのインポート、`auto/*` ルーティング、`GET /v1/models`、ブラウザプレビュー |

フィードを利用できる場合、集計結果は随時改善できます。一方、判定はリリース成果物に固定されているため、ブラウザとサーバーで結果が同一になり、オフラインでも再現可能で、データベースなしでテストできます。ブラウザプレビューとサーバー側のインポートが別々のソースを参照すると、プレビューとクリック後の実際の動作が一致しなくなります。そのため、この分離は意図的に維持されています。

## 方法論と注意事項

- 数値は、**2026-06-17** 時点で各プロバイダーが文書化していた無料枠の上限に基づき、Web 調査によって収集した**上限推定値**です。無料枠は頻繁に変更されるため、数値に依存する前に再確認してください。
- **各エントリが実際に保証する内容。** 行ごとの信頼度評価を持つエントリはなく、API もそのような評価を提供しません。上記のすべての数値は、明示されていない同一水準の推定値として扱ってください。ただし、推論ではなく手作業でキュレーションされているため、2つの事実は異なります。44件のエントリには、独立して文書化されたハードストップがあります（そのうち39件は xKiro の行で、すべて同一の日次許容量を共有しています）。また、13件のエントリにはプロンプト学習に関する開示があります。`hardStopGuaranteed` は、無料許容量を超えた場合、プロバイダー自身の規約において、暗黙に課金を開始するのではなくリクエストを拒否すると記載されている場合にのみ設定され、出典はエントリの隣のコメントに記載されます。デフォルトで `true` に設定されることはなく、誰も検証していないエントリでは未設定のままです。したがって、ハードストップフラグがないことは「確認されていない」ことを意味し、「課金されることが判明している」という意味ではありません。**STRICT モード**（オプトインの `freeAccessPolicy=strict` ルーティングガード）は、このフラグを持つエントリのみを信頼します。それ以外の無料枠はすべて `no-hard-stop` として除外されます（`open-sse/services/autoCombo/strictZeroCostFilter.ts` を参照）。ガードがプールをフィルタリングすると、運用者向けのログには、除外数とそのうち `no-hard-stop` が占める割合の両方が記録されます。
- `estMonthlyFreeTokens` = 毎月繰り返し付与されるトークンのみ。**初回登録時の1回限りのクレジットは繰り返し付与されない**ため、0として数えます。廃止された無料枠も0です。
- 日次トークン上限 → `monthly = daily × 30`。RPD のみが文書化されている場合 → `RPD × ~800 output tokens × 30`。RPM/TPM のみで日次上限がない場合 → **上限なし**（下記参照）。
- **恒久的に無料だが、公開されたトークン上限がないもの**（`siliconflow`、`glm-cn`、`tencent`、`baidu`、`kilo-gateway`、`opencode-zen`、`gemini`、`ollama-cloud`）：これらは、レートまたは同時実行数に制限のある、実在する継続的な無料アクセスです。これらを `recurring-uncapped` に分類し、**合計には絶対に含めません**。`RPM × 24/7 × 30d` を計算すると、非現実的な上限値になるためです（当方が排除している水増し方法です）。これらは、その存在を知らせるために掲載されています。
- **入金によるアンロック増量：** 1回限りの少額入金によって無料クォータが恒久的に増えるものです（OpenRouter：$10 → 1000 req/day ≈ +24M/mo）。通常時の主要数値には含めず、別の数値として報告します。
- **資格条件付きクォータ**（`eligibilityGate: "regional-identity"`）：地域に紐づく本人確認（現時点では中国本土の実名認証）の後でのみ利用可能になる、実在する継続的クォータです。同じプール重複排除ルールを適用して別の数値（`gatedRecurringTokens`）に集計し、通常時の主要数値には決して含めません。レジーム（`freeType`）は変わらないため、ルーティングも変わりません。
- **エビデンス区分。** ルール：カタログ内の数値は、エントリの隣にある `// evidence:` コメントで出典を引用します。区分は、`public-page`（誰でも閲覧できるプロバイダーのページ）、`api-public`（プロバイダーの認証不要エンドポイント。例：router.bynara.id にある NaraRouter の公開プランエンドポイント）、`console-verified <date> por <who>`（数値がアカウントコンソール内でのみ確認できる場合。コメントには、誰がいつ確認したか、および上限の存在を示す公開ページを記録）です。現状：2026-09-02 に再監査された5つのブロック（`gemini`、`groq`、`mistral`、`ollama-cloud`、`nara`）には、このコメントがあります。2026-09-02 の再監査より前から存在するエントリは、変更されるまでは以前の調査結果を継承します。エビデンスコメントのない**新規または変更された**数値はバグです。現時点で console-verified なのは `mistral` のみです。

## 当社の数値が他のアグリゲーターより小さい理由

この分野で示される「1か月あたりの無料トークン」の数値は、ほとんどの場合、モデルごとの表示値を合計したものです。当社では、意図的にそのような計算をしていません。

- **各共有プールは1回だけ計上します。** Mistralの無料プランは、組織ごとに月間10億トークンの枠が1つ提供されるものです。これを5つのモデルの下に記載しても、50億にはなりません。モデルごとに合計すれば、当社のカタログも **約74億**（2026-09-03に再計算。この数値はCIによるチェック対象ではありません。カタログが変更されるたびに再計測してください）となりますが、見出しでは **約14.7億** としています。これは、各プロバイダーにつき1つのアカウントで実際に利用できる量だからです。
- **1日あたりの上限は換算しますが、レート制限は換算しません。** 文書化された1日あたりのトークン上限は `× 30`、文書化された1日あたりのリクエスト上限は `RPD × 約800トークン × 30` として換算します。1分あたりのリクエスト数しか公開していないプロバイダーには月間値を設定せず、合計には含めずに _上限なし_ と記載します。レート制限を24時間365日で乗算するような水増しは行いません。
- **地域限定の本人確認が必要なクォータは別に表示します**（`+地域限定の本人確認が必要な約600万`）。ほとんどの読者は利用できないためです。
- **サインアップクレジットは初月限定**であり、継続的な数値に混ぜることなく、2つ目の数値として報告します。
- **この数値はCIによって検証されます。** `npm run check:docs-counts` はカタログから合計を再計算し、このファイル、README、または予算カードの数値に差異がある場合、ビルドを失敗させます。

## 用語集

| 用語                     | 意味                                                                                           |
| ------------------------ | ---------------------------------------------------------------------------------------------- |
| **RPM / RPD / RPH**      | 1 分あたり / 1 日あたり / 1 時間あたりのリクエスト数                                           |
| **TPM / TPD**            | 1 分あたり / 1 日あたりのトークン数                                                            |
| **文書化された割り当て** | プロバイダーが明示的な 1 日 / 1 か月あたりのトークン上限を公開しているもの（根拠を示せる予算） |
| **理論上の上限**         | `rate-limit × 24/7 × 30d` — 付与された予算ではなく、最大値                                     |
| **Neuron**               | Cloudflare のコンピューティング単位（約 1 出力トークン）                                       |

> 2026-06-05 に実施したプロバイダーごとの調査から生成されています。更新するには、調査ワークフロー（`_tasks/features-v3.8.12` を参照）を再実行してください。
