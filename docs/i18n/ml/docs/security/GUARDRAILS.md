> **അവസാനം അപ്ഡേറ്റ് ചെയ്തത്:** 2026-08-29 — v3.8.51 (വീഡിയോ ബ്രിഡ്ജ് ട്രാൻസ്ക്രിപ്റ്റ് പ്രൂവനെൻസ് കോളർ-പ്രഖ്യാപിച്ചതാണ്,
> ഇതുവരെ സെർവർ-പരിശോധിച്ചിട്ടില്ല — #11661 അനുസരിച്ച് വ്യക്തമാക്കിയത്)

OmniRoute-നും അപ്സ്ട്രീം പ്രൊവൈഡർമാർക്കും ഇടയിലുള്ള അതിർത്തിയിൽ സുരക്ഷ, നയം, ഉള്ളടക്ക പരിവർത്തനങ്ങൾ എന്നിവ ഗാർഡ്റെയിലുകൾ നടപ്പിലാക്കുന്നു. ഓരോ ഗാർഡ്റെയിലിനും അഭ്യർത്ഥന പേലോഡുകളും (`preCall`) അപ്സ്ട്രീം പ്രതികരണങ്ങളും (`postCall`) പരിശോധിക്കാൻ (ഓപ്ഷണലായി നിരസിക്കുകയോ, രൂപാന്തരപ്പെടുത്തുകയോ, വ്യാഖ്യാനിക്കുകയോ ചെയ്യാം) കഴിയും.

സിസ്റ്റം **ഫെയിൽ-ഓപ്പൺ** ആണ്: ഒരു ഗാർഡ്റെയിൽ പ്രവർത്തിക്കുമ്പോൾ പിശക് സംഭവിച്ചാൽ, രജിസ്ട്രി പിശക് രേഖപ്പെടുത്തുകയും അഭ്യർത്ഥന പരാജയപ്പെടുത്തുന്നതിന് പകരം അടുത്ത ഗാർഡ്റെയിലുമായി മുന്നോട്ട് പോകുകയും ചെയ്യുന്നു. തടയുന്നത് ഒരു വ്യക്തമായ തീരുമാനമാണ് (`block: true`), ഒരിക്കലും ഒരു അപകടമല്ല.

## ബിൽറ്റ്-ഇൻ ഗാർഡ്റെയിലുകൾ

ഇംപോർട്ട് ചെയ്യുമ്പോൾ രജിസ്ട്രി മുൻഗണനാക്രമത്തിൽ ആറ് ഗാർഡ്റെയിലുകൾ സ്വയമേവ ലോഡ് ചെയ്യുന്നു
(`registry.ts` → `registerDefaultGuardrails()` കാണുക):

| മുൻഗണന | പേര്                | ഘട്ടം(ങ്ങൾ)    | ഫയൽ                   |
| ------ | ------------------- | -------------- | --------------------- |
| `5`    | `vision-bridge`     | `preCall`      | `visionBridge.ts`     |
| `6`    | `audio-bridge`      | `preCall`      | `audioBridge.ts`      |
| `7`    | `video-bridge`      | `preCall`      | `videoBridge.ts`      |
| `10`   | `pii-masker`        | `pre` + `post` | `piiMasker.ts`        |
| `20`   | `prompt-injection`  | `preCall`      | `promptInjection.ts`  |
| `95`   | `credential-masker` | `pre` + `post` | `credentialMasker.ts` |

കുറഞ്ഞ മുൻഗണനാ സംഖ്യകളുള്ളവ **ആദ്യം** പ്രവർത്തിക്കുന്നു.

### വിഷൻ ബ്രിഡ്ജ് (`visionBridge.ts`) — മോഡാലിറ്റി ബ്രിഡ്ജ് PR-1

**വിഷൻ പിന്തുണയില്ലാത്ത മോഡലുകളെ** ലക്ഷ്യമിട്ടുള്ള, ചിത്രങ്ങൾ ഉൾക്കൊള്ളുന്ന അഭ്യർത്ഥനകളെ തടഞ്ഞുപിടിച്ച്, മുഴുവൻ അഭ്യർത്ഥനയും വിഷൻ പിന്തുണയുള്ള ഒരു മോഡലിലേക്ക് തിരിച്ചുവിടുകയോ, അപ്സ്ട്രീം കോളിന് മുമ്പ് ചിത്രഭാഗങ്ങളെ കോൺഫിഗർ ചെയ്യാവുന്ന ഒരു വിഷൻ മോഡൽ സൃഷ്ടിച്ച ടെക്സ്റ്റ് വിവരണങ്ങൾകൊണ്ട് മാറ്റിസ്ഥാപിക്കുകയോ ചെയ്യുന്നു. ഇതിലൂടെ ടെക്സ്റ്റ് മാത്രം പിന്തുണയ്ക്കുന്ന പ്രൊവൈഡർമാർക്ക് മൾട്ടിമോഡൽ പേലോഡുകൾ സുതാര്യമായി കൈകാര്യം ചെയ്യാനാകും.

പ്രവാഹം:

1. ലക്ഷ്യ മോഡൽ ഇതിനകം വിഷൻ പിന്തുണയ്ക്കുന്നുവെങ്കിൽ ഒഴിവാക്കുക (അത് നിർബന്ധിത-ബ്രിഡ്ജ് ലിസ്റ്റായ `isVisionBridgeForcedModel`-ൽ ഉൾപ്പെട്ടിട്ടില്ലെങ്കിൽ).
2. `extractImageParts(messages)` വഴി ചിത്രഭാഗങ്ങൾ എക്സ്ട്രാക്റ്റ് ചെയ്യുക
   (`visionBridgeHelpers.ts`); ഇത് `open-sse/utils/mediaParts.ts`-ലെ **ഏകീകൃത മീഡിയ
   ഡിറ്റക്ടർ** ആയ `detectMediaParts()`-ലേക്ക് ചുമതല കൈമാറുന്നു — കോംബോ കോംപാറ്റിബിലിറ്റി ഫിൽട്ടറുമായി പങ്കിടുന്ന
   ഏക ആധികാരിക സ്രോതസ്സ്. `replaceImageParts`-ന് തിരികെ ചേർക്കാൻ കഴിയുന്ന ആകൃതികളിലുള്ള
   ടോപ്പ്-ലെവൽ ഭാഗങ്ങൾക്ക് മാത്രമായി എക്സ്ട്രാക്ഷൻ അനുവദിച്ചിരിക്കുന്നു (extract↔replace കരാർ): OpenAI
   `image_url`, Anthropic base64 `source.type:"base64"`, Anthropic URL
   `source.type:"url"`, Responses API `input_image`. നെസ്റ്റഡ് പൊരുത്തങ്ങളും
   ഇൻഡിക്കേറ്റർ-മാത്രമുള്ള ആകൃതികളും കോംബോ-ഫിൽട്ടറിനുള്ളവയാണ്; അവ ഒരിക്കലും എക്സ്ട്രാക്റ്റ് ചെയ്യില്ല.
   ഒന്നും കണ്ടെത്തിയില്ലെങ്കിൽ ഒഴിവാക്കുക.
3. `resolveVisionBridgeRuntimeSettings()` വഴി റൺടൈം കോൺഫിഗ് നിർണ്ണയിക്കുക
   (`src/shared/constants/modalityBridgeDefaults.ts`): പുതിയ `modalityBridge*`
   ക്രമീകരണ കീകൾക്കാണ് മുൻഗണന; പഴയ `visionBridge*` കീകൾ **ഒരു സൈക്കിൾ
   ഫാൾബാക്കായി** (റോൾബാക്ക് വിൻഡോ) തുടരുന്നു. ബ്രിഡ്ജ് പ്രവർത്തനരഹിതമാണെങ്കിൽ ഏതെങ്കിലും
   മീഡിയ ട്രാവേഴ്സലിന് മുമ്പ് ഒഴിവാക്കുക.
4. മോഡ് സെലക്ടർ (`modalityBridgeVisionMode`, താഴെയുള്ള പട്ടിക കാണുക)
   റീറൂട്ട് ചെയ്യണമോ വിവരിക്കണമോ എന്ന് തീരുമാനിക്കുന്നു. റീറൂട്ട് `model` മാത്രം
   മാറ്റിയ `modifiedPayload`, കൂടാതെ `{ rerouted, fromModel, toModel, imagesKept }` മെറ്റാ എന്നിവ മടക്കിനൽകുന്നു.
5. വിവരണ പാത: ചിത്രങ്ങളുടെ എണ്ണം `maxImages` ആയി പരിമിതപ്പെടുത്തുക, ടാസ്ക്-അവബോധമുള്ള പ്രോംപ്റ്റ് തയ്യാറാക്കുക,
   വിവരണ കാഷ് പരിശോധിക്കുക, വിഷൻ മോഡലിനെ **സമാന്തരമായി**
   (`Promise.allSettled`) വിളിക്കുക, തുടർന്ന് അവയുടെ സ്ഥാനത്ത് `[Image N]: <description>` ടെക്സ്റ്റ് ഭാഗങ്ങൾ
   ഉൾപ്പെടുത്തുക. പരാജയപ്പെട്ട വിവരണം `null` നൽകുകയും യഥാർത്ഥ ചിത്രഭാഗം
   **നിലനിർത്തുകയും** ചെയ്യുന്നു (#4012) — എന്നാൽ കോംബോ വിവരണ പാതയിൽ എല്ലാ
   വിവരണങ്ങളും പരാജയപ്പെടുകയും അപ്സ്ട്രീം വിഷൻ പിന്തുണയ്ക്കുന്നില്ലെന്ന് സ്ഥിരീകരിക്കപ്പെടുകയും ചെയ്താൽ,
   പകരം അതിന് `(ലഭ്യമല്ല — വിഷൻ പിന്തുണയുള്ള പ്രൊവൈഡറൊന്നും കണക്റ്റ് ചെയ്തിട്ടില്ല)` എന്ന സ്റ്റബ് നൽകുന്നു (#8430).
6. `modifiedPayload` + മെറ്റാ (`imagesProcessed`, `descriptions`,
   `processingTimeMs`, `visionModel`) മടക്കിനൽകുക.

#### API-കീ സ്കോപ്പ് (`visionBridgeKeyScope.ts`)

കണക്ഷനുകളിൽ, കീയ്ക്ക് ഉപയോഗിക്കാൻ അനുവാദമുള്ള റീറൂട്ട്, വിവരണ മോഡലുകൾ മാത്രമേ ബ്രിഡ്ജ്
തിരഞ്ഞെടുക്കൂ. തുടർന്ന് വിവരണ കോൾ എല്ലായ്പ്പോഴും
`x-omniroute-self-loop-key-id` ഹെഡറോടുകൂടിയ OmniRoute സെൽഫ്-ലൂപ്പിലൂടെ കടന്നുപോകുന്നു; അതിനാൽ സ്വീകരിക്കുന്ന ചാറ്റ് അഭ്യർത്ഥന
ആ കീയുടെ കണക്ഷൻ, മോഡൽ നയങ്ങൾ വീണ്ടും നടപ്പിലാക്കുന്നു. `enforceApiKeyPolicy()`
ആ ഹെഡർ സെൽഫ്-ലൂപ്പ് ബെയററിനൊപ്പം ഉള്ളപ്പോൾ മാത്രമേ അംഗീകരിക്കൂ; അതിനാൽ അതിന്
ആക്സസ് കൂടുതൽ പരിമിതപ്പെടുത്താൻ മാത്രമേ കഴിയൂ, കൂടാതെ റിസോൾവ് ചെയ്യാനാകാത്ത ഒരു id നിരസിക്കപ്പെടും.

കീയ്ക്ക് അനുവദനീയമായ വിഷൻ മോഡലൊന്നും ഇല്ലെങ്കിൽ, വിവരണ പാത മാറിനിൽക്കുകയും
അഭ്യർത്ഥന മാറ്റമില്ലാതെ കടന്നുപോകുകയും ചെയ്യുന്നു; പ്രവർത്തനരഹിതമായ
ഗാർഡ്റെയിലിന്റെ അതേ fail-open പെരുമാറ്റമാണിത് (മെറ്റാ `{ skipped: true, reason: "no_permitted_vision_model" }`).
കീയില്ലാത്ത അഭ്യർത്ഥനകളും ഈ നിയന്ത്രണങ്ങളില്ലാത്ത കീകളും മുമ്പത്തെപ്പോലെ തന്നെ
പെരുമാറുന്നു.

#### ടാസ്ക്-അവബോധമുള്ള വിവരണ പ്രോംപ്റ്റ് (`modalityBridgeVisionTaskAware`)

Describe self-loop-ന്റെ സ്വന്തം OpenAI-അനുയോജ്യ അഭ്യർത്ഥന (`callVisionModelSingle()`

നിയന്ത്രിക്കപ്പെടുന്നില്ല. ഈ പ്രോംപ്റ്റ് ആവശ്യപ്പെടുന്ന ടെക്സ്റ്റ്-പകർത്തിയെഴുത്ത് ടാസ്കിന്

മാറ്റുന്നില്ല — ആ സ്ഥിരസ്ഥിതി വേറെയായി പ്രയോഗിക്കപ്പെടുന്നു, അതും കണ്ടെത്തിയ OpenCode

അതിനാൽ രണ്ട് സ്ഥിരസ്ഥിതികളും അതിനെ ബാധിക്കില്ല.

#### Describe ഔട്ട്പുട്ട് പരിധി (`modalityBridgeVisionMaxChars`)

| കീ                             | സ്ഥിരസ്ഥിതി | പരിധി                    |
| ------------------------------ | ----------- | ------------------------ |
| `modalityBridgeVisionMaxChars` | `0`         | `0` അല്ലെങ്കിൽ 100–50000 |

`0` (സ്ഥിരസ്ഥിതി) എന്നത് **പരിധിയില്ല** എന്നാണ് — `callVisionModel()` തിരികെ നൽകുന്ന
വിവരണം മാറ്റങ്ങളൊന്നുമില്ലാതെ കടത്തിവിടുന്നു, അതുവഴി നിലവിലുള്ള പ്രവർത്തനരീതി
നിലനിർത്തുന്നു. 100–50000 പരിധിയിലുള്ള ഏത് മൂല്യവും വിവരണം വീണ്ടും
`[Image N]: <description>` ആയി ചേർക്കുന്നതിന് മുമ്പ് `…` സഫിക്സ് ഉപയോഗിച്ച്
ചുരുക്കുന്നു (`VisionBridgeGuardrail.preCall()` in `src/lib/guardrails/visionBridge.ts`).
താഴേക്കുള്ള മോഡലിന് പൂർണ്ണമായ പകർത്തിയെഴുത്ത് ആവശ്യമായ, വിശദാംശങ്ങൾ കൂടുതലുള്ള OCR
ടാസ്കുകൾക്കായി ഈ മൂല്യം ഉയർത്തുക; കൂടുതൽ വാചാലമായ വിഷൻ മോഡലുകളുടെ ടോക്കൺ ഉപയോഗം
പരിമിതപ്പെടുത്താൻ ഇത് കുറയ്ക്കുക. ഡാഷ്ബോർഡ് ഫീൽഡ് Vision ടാബിലെ Advanced പാനലിലാണ്
(`modality-bridge-max-chars` in `ModalityBridgeVisionTab.tsx`); വ്യക്തമായി നൽകിയ `0`
മാറ്റമില്ലാതെ നിലനിർത്തിക്കൊണ്ട്, 1-നും 99-നും ഇടയിലുള്ള ഏത് മൂല്യവും ഇത് ഏറ്റവും കുറഞ്ഞ
പരിധിയായ 100-ലേക്ക് ഉയർത്തുന്നു — `0` എന്നത് വെറും "unset" സ്ഥിരസ്ഥിതിയല്ല, അതിന്റെ
സ്വന്തം നിലയിൽ സാധുവായ Zod മൂല്യമാണ്
(`z.union([z.literal(0), z.number().int().min(100).max(50000)])`).

#### റിമോട്ട് ഇമേജ് നോർമലൈസേഷൻ (self-loop describe/base64 fetch)

ബ്രിഡ്ജ് ഒരു **റിമോട്ട്** ഇമേജ് സ്വയം fetch ചെയ്യുമ്പോൾ — Anthropic describe
self-call-ഉം claude-wire-format base64 പരിവർത്തനവും

ഉൾച്ചേർക്കുന്നതിന് മുമ്പ് `normalizeDataUri()`
(`open-sse/utils/imageNormalize.ts`) വഴി കടത്തിവിടുന്നു. അമിത വലുപ്പമുള്ള ഇമേജുകൾ
**2048px നീളമുള്ള അരികിലേക്ക്** downscale ചെയ്യുന്നു (OpenAI/Anthropic ഇതിനകം
server-side-ൽ പ്രയോഗിക്കുന്ന resize പരിധിയുമായി പൊരുത്തപ്പെടുന്നു); വിഷൻ മോഡൽ
കാണുന്നതിൽ മാറ്റം വരുത്താതെ ഇത് upload bytes/latency കുറയ്ക്കുന്നു. Resizing-നായി
dynamic import വഴി ലോഡ് ചെയ്യുന്ന `sharp` ഉപയോഗിക്കുന്നു: അതിന്റെ native binary

   അത് നീക്കം ചെയ്യില്ല. വർക്ക് `modalityBridgeAudioMaxClips` ഉപയോഗിച്ച്
   പരിമിതപ്പെടുത്തുന്നു; പിന്നീടുള്ള ഭാഗങ്ങൾ മാറ്റമില്ലാതെ തുടരും.
3. കോൺഫിഗർ ചെയ്ത `provider/model` മാനിക്കുക, അല്ലെങ്കിൽ
   `selectAudioBridgeModel()`-നെ സ്ഥിരമായ കാറ്റലോഗ് ക്രമത്തിൽ
   `AUDIO_TRANSCRIPTION_PROVIDERS` പരിശോധിച്ച് ഉപയോഗയോഗ്യമായ സജീവ പ്രൊവൈഡർ
   ക്രെഡൻഷ്യലുള്ള ആദ്യ മോഡൽ തിരഞ്ഞെടുക്കാൻ അനുവദിക്കുക.
4. `callAudioTranscription()` base64/data-URI ഓഡിയോയെ ഒരു മൾട്ടിപാർട്ട് `file`
   ആയി പരിവർത്തനം ചെയ്യുന്നു, അല്ലെങ്കിൽ DNS പിന്നിംഗും 25 MB പരിധിയുമുള്ള
   പബ്ലിക്-ഒൺലി ഔട്ട്ബൗണ്ട് ഗാർഡ് വഴി റിമോട്ട് `audio_url` ഡൗൺലോഡ് ചെയ്യുന്നു.
   തുടർന്ന് `resolveSelfLoopBearer()` ഉപയോഗിച്ച് ഓതന്റിക്കേറ്റ് ചെയ്ത്, ലോക്കൽ
   `/v1/audio/transcriptions` സെൽഫ്-ലൂപ്പിലേക്ക് ഫയലും തിരഞ്ഞെടുത്ത മോഡലും POST
   ചെയ്യുന്നു. നിലവിലുള്ള ട്രാൻസ്ക്രിപ്ഷൻ റൂട്ട് സാധാരണ ക്രെഡൻഷ്യൽ ലുക്കപ്പ്,
   കൂൾഡൗൺ/റേറ്റ്-ലിമിറ്റ് കൈകാര്യംചെയ്യൽ, പ്രൊവൈഡർ ഡിസ്പാച്ച് എന്നിവ നിർവഹിക്കുന്നു.
5. വിജയകരമായ കോളുകൾ അവയുടെ ഭാഗങ്ങളെ `[Audio N]: <transcript>` കൊണ്ട്
   മാറ്റിസ്ഥാപിക്കുന്നു. കോളുകൾ `Promise.allSettled` ഉപയോഗിച്ച് പ്രവർത്തിക്കുന്നു:
   ഒറ്റപ്പെട്ട ഒരു പരാജയം ആ യഥാർഥ ഓഡിയോ ഭാഗം നിലനിർത്തുന്നു (#4012 കരാർ). എല്ലാ
   കോളുകളും പരാജയപ്പെടുകയും ടാർഗറ്റിന് `supportsAudio === false` ആണെന്ന്
   തെളിയിക്കപ്പെടുകയും ചെയ്താൽ, ഭാഗങ്ങൾ
   `[Audio N]: (unavailable — no STT provider connected)` ആയി മാറുന്നു (#8430
   കരാർ). അറിയാത്ത ഒരു ടാർഗറ്റിന് (`null`), എല്ലാം പരാജയപ്പെട്ട ഫലം മാറ്റമില്ലാതെ
   തുടരും. ഉപയോഗയോഗ്യമായ STT ക്രെഡൻഷ്യൽ ഇല്ലാത്ത, ടെക്സ്റ്റ്-മാത്രമാണെന്ന്
   തെളിയിക്കപ്പെട്ട ടാർഗറ്റിന് നെറ്റ്വർക്ക് കോൾ നടത്താതെ അതേ വ്യക്തമായ സ്റ്റബ്
   ലഭിക്കും.

വിജയകരമായ ട്രാൻസ്ക്രിപ്റ്റുകൾ പ്രോസസ്-വ്യാപകമായ Modality Bridge LRU/TTL കാഷെ
ഉപയോഗിക്കുന്നു. ഓഡിയോ റഫറൻസ്, സ്ഥിരമായ `audio-transcription` ഓപ്പറേഷൻ ലേബൽ,
തിരഞ്ഞെടുത്ത STT മോഡൽ എന്നിവ സംയോജിപ്പിച്ചാണ് കീ രൂപപ്പെടുത്തുന്നത്; പരാജയങ്ങൾ
ഒരിക്കലും കാഷെ ചെയ്യില്ല. ഓഡിയോ ശ്രമങ്ങൾ പങ്കിട്ട `bridged`, `cacheHits`,
`failures`, `lastUsedAt` കൗണ്ടറുകൾ അപ്ഡേറ്റ് ചെയ്യുന്നു.
രൂപാന്തരപ്പെടുത്തിയ പ്രതികരണങ്ങളിൽ
`x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>` ഉണ്ടായിരിക്കും;
മാറ്റമില്ലാത്ത അഭ്യർത്ഥനകൾക്ക് Audio Bridge സെഗ്മെന്റ് ലഭിക്കില്ല.

റൺടൈം ക്രമീകരണങ്ങൾ DB-ബാക്ക്ഡ് ആയതും Zod ഉപയോഗിച്ച് വാലിഡേറ്റ് ചെയ്തതുമാണ്:

| കീ                            | ഡിഫോൾട്ട് | പരിധി                     |
| ----------------------------- | --------- | ------------------------- |
| `modalityBridgeAudioEnabled`  | `true`    | —                         |
| `modalityBridgeAudioModel`    | `""`      | സ്വയമേവ അല്ലെങ്കിൽ STT ID |
| `modalityBridgeAudioTimeout`  | `60000`   | 1000–300000               |
| `modalityBridgeAudioMaxClips` | `3`       | 1–10                      |

പങ്കിട്ട കാഷ് ഇപ്പോഴും `modalityBridgeCacheEnabled`,
`modalityBridgeCacheTtlMinutes`, `modalityBridgeCacheMaxEntries` എന്നിവയാൽ നിയന്ത്രിക്കപ്പെടുന്നു.

### വീഡിയോ ബ്രിഡ്ജ് (`videoBridge.ts`, `videoBridgePipeline.ts`)

നേറ്റീവ് വീഡിയോ പിന്തുണയുള്ളതായി അറിയപ്പെടാത്ത ഒരു ടാർഗെറ്റിനെ വിളിക്കുന്നതിന് മുമ്പ്, Chat Completions `messages`-ലെയും Responses
API `input`-ലെയും ടോപ്പ്-ലെവൽ വീഡിയോ ഭാഗങ്ങളെ തടഞ്ഞ് കൈകാര്യം ചെയ്യുന്നു.
പിന്തുണയ്ക്കുന്ന രൂപങ്ങൾ `input_video`, `video_url`, `video_source`, HTTPS URL-കൾ,
`data:video/*;base64,...` ഡാറ്റ URI-കൾ എന്നിവയാണ്. ടെക്സ്റ്റിലുള്ള സാധാരണ ഫയൽനാമങ്ങൾ വീഡിയോയായി പരിഗണിക്കില്ല.

`VideoBridgeGuardrail.preCall` (`videoBridge.ts`) റിക്വസ്റ്റ് ട്രാവേഴ്സൽ,
ശേഷി/നയ പരിശോധന, ഓരോ റിക്വസ്റ്റിനുമുള്ള അഗ്രിഗേഷൻ, റെസ്പോൺസ് പേലോഡ് എന്നിവ കൈകാര്യം ചെയ്യുന്നു.
ഓരോ വീഡിയോയ്ക്കുമുള്ള പ്രവർത്തനം — സമാഹരണം, പൂർണ്ണ ഫല കാഷ്, ഫ്രെയിം
സീക്വൻസിന്റെ വിവരണം (കോളർ പ്രഖ്യാപിച്ച ഏതെങ്കിലും ഓഡിയോ ട്രാൻസ്ക്രിപ്റ്റ് ഇതിൽ സംയോജിപ്പിക്കുന്നു), ഓരോ ശ്രമത്തിനുമുള്ള
മെട്രിക്സ്/അബോർട്ട്/ക്ലീനപ്പ് എന്നിവ — `videoBridgePipeline.ts`-ലെ
`processVideoPart`-ന് പിന്നിൽ മറച്ചിരിക്കുന്നു; `preCall`-ന്റെ ലൂപ്പിനുള്ളിൽ ഓരോ വീഡിയോ ഭാഗത്തിനും ഒരിക്കൽ വീതം ഇത് വിളിക്കപ്പെടുന്നു.
ആ മൊഡ്യൂൾ വ്യക്തമായ പോർട്ട് അതിരുകളായ `VideoMediaBrokerPort`
(ബൈറ്റുകൾ സമാഹരിക്കുകയും സാമ്പിൾ ചെയ്ത ഫ്രെയിമുകൾ എക്സ്ട്രാക്റ്റ് ചെയ്യുകയും ചെയ്യുന്നത്), `VideoAudioTranscriptionPort`
(കോളർ പ്രഖ്യാപിച്ച ഓഡിയോ ട്രാൻസ്ക്രിപ്റ്റ് സാമ്പിൾ ചെയ്ത ക്യാപ്ഷനുകളുമായി സംയോജിപ്പിക്കുന്നത്),
`VideoDrilldownPort` (ഫ്രെയിം ഡ്രിൽ-ഡൗൺ പെർസിസ്റ്റൻസ് അതിര്; ഇതുവരെ
`processVideoPart`-ലേക്ക് വയർ ചെയ്തിട്ടില്ല — പ്രത്യേക `/api/modality-bridge/video/drilldown`
റൂട്ട് മാത്രമാണ് നിലവിൽ ഡ്രിൽ-ഡൗൺ എൻട്രികൾ എഴുതുന്നത്) എന്നിവയും നിർവചിക്കുന്നു.

പബ്ലിക് `/v1` റിക്വസ്റ്റ് പാത്ത് ഒരിക്കലും ഒരു സബ്പ്രോസസ് ഇമ്പോർട്ട് ചെയ്യുകയോ ഇൻവോക്ക് ചെയ്യുകയോ ചെയ്യുന്നില്ല. റിമോട്ട്
വീഡിയോകൾ 50 MiB പരിധിക്കുള്ളിൽ ഡൗൺലോഡ് ചെയ്യുന്നു; ഇൻലൈൻ base64 വീഡിയോകൾക്ക് ഓരോ വീഡിയോയ്ക്കും
യാഥാസ്ഥിതികമായ 36 MiB ഡീകോഡ് പരിധിയുണ്ട്, അതിനാൽ മോഡൽ/മെസേജുകൾ/ഫ്രെയിമിംഗ് എൻവലപ്പ്
50 MiB എന്ന പബ്ലിക് JSON റിക്വസ്റ്റ് അഡ്മിഷൻ പരിധിക്കുള്ളിൽ നിലനിർത്താം. അലോക്കേഷന് മുമ്പ് ഇൻലൈൻ
ദൈർഘ്യവും ഡീകോഡ് ചെയ്ത വലുപ്പത്തിന്റെ എസ്റ്റിമേറ്റുകളും പരിശോധിക്കുന്നു. പ്രാരംഭ റിമോട്ട് URL-ലും ഓരോ റീഡയറക്ടിലും
HTTPS ആവശ്യമാണ്; DNS പിന്നിംഗ് ഉള്ള നിലവിലുള്ള
പബ്ലിക്-ഒൺലി ഔട്ട്ബൗണ്ട് ഗാർഡ് ഇതിനായി ഉപയോഗിക്കുന്നു. തുടർന്ന് ബൈറ്റുകൾ കൃത്യമായ ഇന്റേണൽ
`POST /api/modality-bridge/video/extract` ബ്രോക്കർ അതിര് കടക്കുന്നു. ആ റൂട്ട്
`LOCAL_ONLY`, `SPAWN_CAPABLE` എന്നീ രണ്ടും ആണ്; ഓരോ പ്രോസസിനും ഓതന്റിക്കേറ്റ് ചെയ്ത,
വിശ്വസനീയമായ ലൂപ്പ്ബാക്ക് റിക്വസ്റ്റുകൾ മാത്രം സ്വീകരിക്കുന്നു; കൂടാതെ URL, ഫയൽസിസ്റ്റം പാത്ത്, എക്സിക്യൂട്ടബിൾ,
അല്ലെങ്കിൽ ആർഗ്യുമെന്റ് ലിസ്റ്റ് ഒരിക്കലും സ്വീകരിക്കുന്നില്ല. API ബോഡി-വലുപ്പ പൈപ്പ്ലൈനും ഹാൻഡ്ലറിന്റെ ഇൻക്രിമെന്റൽ ബോഡി
റീഡറും സ്വതന്ത്രമായി 50 MiB ബ്രോക്കർ ഇൻപുട്ട് പരിധി നടപ്പാക്കുന്നു. അതിന്റെ പരിധിയുള്ള ക്യൂ
ഒരു സമയം ഒരു എക്സ്ട്രാക്ഷൻ നടത്തുന്നു, തീർപ്പാക്കാത്ത നാല് ജോലികൾ അനുവദിക്കുന്നു, തീർപ്പാക്കാത്ത ഇൻപുട്ട്
100 MiB ആയി പരിമിതപ്പെടുത്തുന്നു.

ബ്രോക്കറിനുള്ളിൽ, `ffprobe` ഒരു സ്വകാര്യ ലോക്കൽ ഫയൽ വായിക്കുന്നു; സ്ഥിരമായ ഫോർമാറ്റ്
അനുവദനീയ ലിസ്റ്റ് പ്ലേലിസ്റ്റ്, മാനിഫെസ്റ്റ് ഫോർമാറ്റുകൾ ഒഴിവാക്കുന്നു. അനുവദനീയമായ MOV-കുടുംബ
കണ്ടെയ്നറുകൾക്ക്, എക്സ്റ്റേണൽ MOV ഡാറ്റ റഫറൻസുകൾ ഡിഫോൾട്ടായി പ്രവർത്തനരഹിതമായി തുടരുന്നു; സ്ഥിരമായ കമാൻഡ്
അവ പ്രവർത്തനക്ഷമമാക്കുന്നില്ല. `ffprobe`, `ffmpeg` എന്നിവ രണ്ടും `file`-മാത്രം പ്രോട്ടോക്കോൾ വൈറ്റ്ലിസ്റ്റും,

ഫിൽട്ടറുകൾ ലഭ്യമല്ലാത്തത്, തെറ്റായ രൂപത്തിലുള്ളതോ ശൂന്യമായതോ ആയ തെളിവ്, ഡിറ്റക്ടർ പിശക്, അല്ലെങ്കിൽ പരിധിയുള്ള മുൻകൂർ-വിശകലന ടൈംഔട്ട് എന്നിവ സംഭവിച്ചാൽ, കൃത്യമായ ഏകീകൃത മധ്യബിന്ദു നയത്തിലേക്ക് ഫെയിൽ-ഓപ്പൺ ചെയ്യുന്നു. കോളർ അബോർട്ടോ ബ്രോക്കർ ഡെഡ്ലൈനോ ഫെയിൽ-ഓപ്പൺ ചെയ്യില്ല: അത് പ്രവർത്തിച്ചുകൊണ്ടിരിക്കുന്ന സബ്പ്രോസസ് അവസാനിപ്പിക്കുകയും, തുടർന്നുള്ള ഫ്രെയിം എക്സ്ട്രാക്ഷൻ തടയുകയും, സ്വകാര്യ താൽക്കാലിക ട്രീ `finally`-യിൽ നീക്കം ചെയ്യുകയും ചെയ്യുന്നു.

`scripts/perf/video-bridge-fu07-eval.ts` ഡീഡ്യൂപ്ലിക്കേഷനുശേഷമുള്ള ക്യാപ്ഷൻ-കോൾ ലാഭം, സാന്ദ്രമായ ചലനത്തിനുള്ള ബജറ്റ് വകയിരുത്തൽ, മങ്ങൽ/എക്സ്പോഷർ/SI-TI തെളിവ്, ദൈർഘ്യമേറിയ അവസാന ഭാഗത്തോടുകൂടിയ വേഗത്തിലുള്ള കട്ടുകൾ, ക്രമാനുഗതമായ ഫേഡ് മൂലമുള്ള തെറ്റായ പോസിറ്റീവുകൾ എന്നിവയ്ക്കായി നിർണയാത്മകമായ യഥാർഥ FFmpeg ഫിക്സ്ചറുകൾ സൃഷ്ടിക്കുന്നു. ഇത് മുൻകൂർ-വിശകലനത്തിന്റെ വാൾ സമയം രേഖപ്പെടുത്തുകയും, `/usr/bin/time` ലഭ്യമായിടത്ത് ചൈൽഡ് CPU, പരമാവധി RSS എന്നിവയും രേഖപ്പെടുത്തുകയും ചെയ്യുന്നു. ഇതിന്റെ ഗുണനിലവാര പരിശോധനകൾ ഘടനാപരമായ ഓറക്കിളുകൾ മാത്രമാണ്. ഈ ഹാർനെസിന് അംഗീകൃത എൻഡ്പോയിന്റോ സ്ഥിരപ്പെടുത്തിയ ജഡ്ജോ ഇല്ലാത്തതിനാൽ, യഥാർഥ ക്യാപ്ഷൻ-മോഡൽ ഗുണനിലവാരം `HOLD` ആയി തുടരുന്നു. `--caption-cost-per-call-usd` വ്യക്തമായ പോസിറ്റീവ് കോൾ-പ്രതി ചെലവ് കണക്ക് നൽകുന്നില്ലെങ്കിൽ സാമ്പത്തിക ലാഭവും `HOLD` ആയി തുടരും; സ്ക്രിപ്റ്റ് ഈ ഫലങ്ങളിൽ ഒന്നും കെട്ടിച്ചമയ്ക്കുന്നില്ല.

ഓരോ ഫ്രെയിമും 4 MiB ആയി, എല്ലാ റോ ഫ്രെയിമുകളും ചേർന്ന് 23 MiB ആയി, സീരിയലൈസ് ചെയ്ത ബ്രോക്കർ പ്രതികരണം 32 MiB ആയി പരിമിതപ്പെടുത്തിയിരിക്കുന്നു. ഒരു സ്വകാര്യ താൽക്കാലിക ഡയറക്ടറി `finally`-യിൽ നീക്കം ചെയ്യുന്നു. OmniRoute FFmpeg ബണ്ടിൽ ചെയ്യുന്നില്ല, ഇഷ്ടാനുസൃത എക്സിക്യൂട്ടബിൾ പാത സ്വീകരിക്കുന്നുമില്ല. ക്യാപ്ഷനിംഗിന് മുമ്പ് ബ്രിഡ്ജ് സൂക്ഷ്മമായ ഒരു വിഷ്വൽ ഡീഡ്യൂപ്ലിക്കേഷൻ പാസ് പ്രയോഗിക്കുന്നു: ഓരോ JPEG-യും 16×16 ഗ്രേസ്കെയിൽ ബഫറായി ചുരുക്കി, അവസാനം നിലനിർത്തിയ ഫ്രെയിമുമായി മാത്രം താരതമ്യം ചെയ്യുന്നു. ഒരു ഫ്രെയിമിലധികമുള്ള അഭ്യർത്ഥിച്ച ക്യാപ്ഷൻ ബജറ്റിന്, എക്സ്ട്രാക്ഷൻ ആ ബജറ്റിന്റെ പരമാവധി ഇരട്ടി വരെയും ഒരിക്കലും 16 ഫ്രെയിമിൽ കൂടുതലാകാതെയും ഉള്ള പരിധിയുള്ള കാൻഡിഡേറ്റ് പൂൾ നൽകുന്നു. അഭ്യർത്ഥിച്ച പരമാവധി പരിധി ഡീഡ്യൂപ്ലിക്കേഷനുശേഷം മാത്രമാണ് പ്രയോഗിക്കുന്നത്; ബജറ്റ് കുറഞ്ഞത് രണ്ടെങ്കിലും ആണെങ്കിൽ അന്തിമമായി ചുരുക്കുമ്പോൾ ആദ്യം തിരഞ്ഞെടുത്തതും അവസാനം തിരഞ്ഞെടുത്തതുമായ കാൻഡിഡേറ്റുകൾ നിലനിർത്തുന്നു. പതിപ്പോടുകൂടിയ `grayscale-16x16-mean-cells-v2` നയം ശരാശരി ലൂമ ഡെൽറ്റയിലും നോർമലൈസ് ചെയ്ത ഡെൽറ്റ കുറഞ്ഞത് 0.05 ആയ തംബ്നെയിൽ സെല്ലുകളുടെ അനുപാതത്തിലും വലുതായ മൂല്യം ഉപയോഗിക്കുന്നു. ഡ്യൂപ്ലിക്കേറ്റ് ത്രെഷോൾഡ് സ്ഥിരാങ്കമായ 0.04 ആണ്; റൺടൈം ക്രമീകരണമായി തുറന്നുനൽകുന്നതിനുപകരം പ്രവചനക്ഷമതയ്ക്കായി ഇത് തിരഞ്ഞെടുത്തിരിക്കുന്നു. ഈ ദ്വിതീയ ഹൈ-കോൺട്രാസ്റ്റ് സിഗ്നൽ, ശരാശരി-മാത്രമുള്ള താരതമ്യം മറച്ചേക്കാവുന്ന ചെറിയ ചലനങ്ങളും ദൃശ്യമായ ടെക്സ്റ്റ് മാറ്റങ്ങളും സംരക്ഷിക്കുന്നു. കംപാരേറ്റർ അല്ലെങ്കിൽ ഡീകോഡർ പിശകുകൾ ഫെയിൽ-ഓപ്പൺ ചെയ്ത് കവറേജ് നിലനിർത്തുന്നു. ഔട്ട്പുട്ട് മെറ്റാഡാറ്റ എക്സ്ട്രാക്റ്റ് ചെയ്ത കാൻഡിഡേറ്റുകൾ, വിജയകരമായി ഉപയോഗിച്ച ഫ്രെയിമുകൾ, ഒഴിവാക്കിയ വിഷ്വൽ ഡ്യൂപ്ലിക്കേറ്റുകൾ എന്നിവ വേർതിരിച്ചുകാണിക്കുന്നു.

വ്യക്തമായി അടയാളപ്പെടുത്തിയ ഒരു വീഡിയോ പാർട്ടിന് ടൈംസ്റ്റാമ്പോടുകൂടിയ കോൺടാക്റ്റ് ഷീറ്റ് അഭ്യർത്ഥിക്കാം. ബ്രിഡ്ജ് പരമാവധി 4 കോളവും 16 ഫ്രെയിമും ഉള്ള JPEG ഗ്രിഡ് നിർമിക്കുന്നു. ഓരോ 512-പിക്സൽ സെല്ലും അതിന്റെ ഉറവിട ടൈംസ്റ്റാമ്പ് ഉയർന്ന കോൺട്രാസ്റ്റുള്ള താഴത്തെ ബാൻഡിൽ പതിപ്പിക്കുന്നു; അതേ ടൈംസ്റ്റാമ്പുകൾ തുടർഘട്ടത്തിലെ ബന്ധപ്പെടുത്തലിനും ഓഡിറ്റിനുമായി ടെക്സ്റ്റ് മെറ്റാഡാറ്റയിലും നിലനിർത്തുന്നു. പൂർണമായ JPEG 32 MiB ആയി പരിമിതപ്പെടുത്തിയിരിക്കുന്നു. `sharp`-ന് ഗ്രിഡ് ഡീകോഡ് ചെയ്യാനോ സംയോജിപ്പിക്കാനോ കഴിയുന്നില്ലെങ്കിൽ, ബ്രിഡ്ജ് വ്യക്തിഗത JPEG ഫ്രെയിമുകളിലേക്ക് ഫാൾബാക്ക് ചെയ്യുന്നു; ക്ലയന്റ് അബോർട്ട് ഷീറ്റ് പ്രവർത്തനത്തിലൂടെയും തുടർന്നും പ്രചരിക്കുന്നു.

പ്രമോഷൻ തെളിവുകൾ സിന്തറ്റിക് കോമ്പോസിഷൻ മൈക്രോബെഞ്ച്മാർക്കിൽ നിന്ന് മനഃപൂർവം വേർതിരിച്ചിരിക്കുന്നു. `scripts/perf/video-bridge-contact-sheet-eval.ts` യഥാർഥ OpenAI-അനുയോജ്യമായ വിഷൻ മോഡലുകൾക്കായി സ്കീമ-പതിപ്പോടുകൂടിയ A/B ഹാർനെസ് നിർവചിക്കുന്നു. ഇത് പ്രൊവൈഡർ റിപ്പോർട്ട് ചെയ്യുന്ന ടോക്കണുകൾ, എൻഡ്-ടു-എൻഡ് വാൾ ലേറ്റൻസി (ഷീറ്റ് കോമ്പോസിഷൻ ഉൾപ്പെടെ), മോഡൽ-കോൾ എണ്ണം, മാനിഫെസ്റ്റ് നിർവചിച്ച വസ്തുതാ നിലനിർത്തൽ എന്നിവ അളക്കുന്നു. അസംസ്കൃത മോഡൽ പ്രതികരണങ്ങൾ റിപ്പോർട്ടിൽ എഴുതുന്നില്ല; SHA-256 ഡൈജസ്റ്റുകളും പൊരുത്തപ്പെട്ട ഫാക്ട് ID-കളും മാത്രം നിലനിർത്തുന്നു. `--execute-real` നൽകുകയും `--model`, `OMNIROUTE_BASE_URL`, `OMNIROUTE_API_KEY` എന്നിവ കോൺഫിഗർ ചെയ്യുകയും ചെയ്തില്ലെങ്കിൽ ഹാർനെസ് നെറ്റ്വർക്ക് കോളോ പണം നൽകേണ്ട മോഡൽ കോളോ നടത്തുന്നില്ല. അത്തരം വ്യക്തമായ യഥാർഥ റൺ ഇല്ലെങ്കിൽ, മെഷീൻ വായിക്കാവുന്ന അതിന്റെ വിധി `HOLD` ആയി തുടരും; സിന്തറ്റിക് പേലോഡ്/കോൾ-എണ്ണ അളവുകൾ മാത്രം പ്രമോഷൻ തെളിവല്ല.

കോളർമാർക്ക് ഇതിനകം അലൈൻ ചെയ്ത ടെക്സ്റ്റ് ഉണ്ടെങ്കിൽ, പിന്തുണയ്ക്കുന്ന ഒരു വീഡിയോ പാർട്ടിലേക്ക് ഐച്ഛികമായ `transcript.cues` അറേ ചേർക്കാം. ഓരോ ക്യൂവിലും `text`, പ്രോബ് ചെയ്ത ദൈർഘ്യത്തിനുള്ളിലെ പരിധിയുള്ള `start`/`end` ഇടവേള, അനുവദനീയ-പട്ടികയിലുള്ള `source` (`client`, `embedded`, അല്ലെങ്കിൽ `audio-bridge`) എന്നിവ ഉണ്ടായിരിക്കണം; `confidence`-ന്റെ ഡിഫോൾട്ട് `1` ആണ്, അത് `0`-നും `1`-നും ഇടയിൽ തന്നെ തുടരേണ്ടതാണ്. കൃത്യമായി ആവർത്തിക്കുന്ന ക്യൂകൾ ഒന്നാക്കി ചുരുക്കുന്നു. ഈ മെറ്റാഡാറ്റയിൽ നിന്ന് OmniRoute ഒരിക്കലും ട്രാൻസ്ക്രിപ്ഷൻ ആരംഭിക്കില്ല: സാധൂകരിച്ച ക്യൂകൾ ഉറവിടം, കോൺഫിഡൻസ്, ഇടവേള എന്നിവ സഹിതം വിവരിച്ച ഫലത്തിലേക്ക് പകർത്തുകയും, ഫ്രെയിം ക്യാപ്ഷനുകൾക്കൊപ്പം വിശ്വസിക്കാനാകാത്ത നിരീക്ഷണങ്ങളായി റെൻഡർ ചെയ്യുകയും ചെയ്യുന്നു. അസാധുവായതോ പരിധിക്കു പുറത്തുള്ളതോ ഉറവിടസാക്ഷ്യമില്ലാത്തതോ ആയ ടെക്സ്റ്റ് ക്യാപ്ഷൻ സ്ട്രീമിലേക്ക് കലർത്തുന്നതിനുപകരം നിരസിക്കുന്നു. സ്വയം അവകാശപ്പെടുന്ന `embedded` അല്ലെങ്കിൽ `audio-bridge` ലേബലുകൾ ഉൾപ്പെടെ, രണ്ട് റിക്വസ്റ്റ്-ബോഡി ട്രാൻസ്ക്രിപ്റ്റ് ചാനലുകളും നൽകിയ ഉറവിടം `client` ആയി നോർമലൈസ് ചെയ്യുന്നു. സെർവറിന്റെ ഉടമസ്ഥതയിലുള്ള അഡാപ്റ്ററിന് മാത്രമേ കോഡ്-മാത്രമായ `trustedSource` ആർഗ്യുമെന്റിലൂടെ ആ വിശ്വസനീയ ലേബലുകൾ നൽകാനാകൂ; ഒരു റിക്വസ്റ്റ് JSON ഫീൽഡിനും ആ ആർഗ്യുമെന്റിൽ എത്താനാകില്ല. ഉറവിടം എന്തുതന്നെയായാലും, ട്രാൻസ്ക്രിപ്റ്റ് ടെക്സ്റ്റ് വിശ്വസിക്കാനാകാത്തതും മീഡിയയിൽ നിന്ന് ഉരുത്തിരിഞ്ഞതുമായ ഉള്ളടക്കമായി തുടരുന്നു; അത് ഒരിക്കലും ഓതറൈസേഷൻ നിർണയിക്കരുത്.

ഡൈമെൻഷനുകളിൽ ഏതെങ്കിലും മാറുന്നത് കാഷ് മിസ് ആണ്, ഒരിക്കലും പഴകിയ പുനരുപയോഗമല്ല. വിഷ്വൽ ഡീഡ്യൂപ്പ് പോളിസി
പതിപ്പ്, ത്രെഷോൾഡ്, പരിധിയുള്ള കാൻഡിഡേറ്റ്-ഫ്രെയിം എണ്ണം എന്നിവയും
റിസൾട്ട്-കാഷ് കീയിലും മെറ്റാഡാറ്റയിലും വ്യക്തമായി ഉൾപ്പെടുത്തിയിരിക്കുന്നു; അതിനാൽ ഒരു പോളിസി മാറ്റത്തിന് പഴകിയ
പൂർണ്ണ-വീഡിയോ വിവരണം പുനരുപയോഗിക്കാനാവില്ല. റിസൾട്ട്-കാഷ് v4 മെറ്റാഡാറ്റ മോഡും
ഫിംഗർപ്രിന്റും നിലനിർത്തുന്നു, അസംസ്കൃത ഉപയോക്തൃ ടാസ്ക് ഒരിക്കലും നിലനിർത്തുന്നില്ല. ഗാർഡ്റെയിൽ മെറ്റാഡാറ്റ അഭ്യർത്ഥിച്ചതും
ഫലപ്രദവുമായ അനാലിസിസ് മോഡുകൾ രണ്ടും റിപ്പോർട്ട് ചെയ്യുന്നു; ഉപയോഗപ്രദമായ ഉപയോക്തൃ ടെക്സ്റ്റില്ലാതെ അഭ്യർത്ഥിച്ച `focused` മോഡ്
ഫലപ്രദമായി `full` എന്ന് റിപ്പോർട്ട് ചെയ്യപ്പെടുന്നു.

ഗാർഡ്റെയിൽ പിന്തുണയ്ക്കുന്ന എല്ലാ വീഡിയോ പാർട്ടുകളും എക്സ്ട്രാക്റ്റ് ചെയ്യുന്നു, എന്നാൽ
`modalityBridgeVideoMaxVideos`-ൽ കൂടുതലിന് വിവരണം നൽകുന്നില്ല. ഒരു ടാർഗറ്റിന്
`supportsVideo === false` ആണെന്ന് തെളിയിക്കപ്പെട്ടാൽ, പരാജയപ്പെട്ടതും പരിധി കവിഞ്ഞതുമായ വീഡിയോകൾ വ്യക്തമായ സുരക്ഷിത
ടെക്സ്റ്റ് മാർക്കറുകളായി മാറുന്നു; അതിനാൽ അസംസ്കൃത വീഡിയോ ഒന്നും ശേഷിക്കില്ല. ശേഷി അജ്ഞാതമാണെങ്കിൽ, ആ പാർട്ടുകൾ
അവയുടെ വീഡിയോ കാരിയർ നിലനിർത്തുന്നു; ഏതെങ്കിലും ഫാൾബാക്ക് ട്രാൻസ്ക്രിപ്റ്റ് മുകളിലുള്ള പരിധിയുള്ള ടെക്സ്റ്റ്
പരിവർത്തനം പിന്തുടരുന്നു. `supportsVideo === true` ഉള്ള ടാർഗറ്റുകൾ ബ്രിഡ്ജിനെ ബൈപാസ് ചെയ്യുന്നു.
ക്ലയന്റ് അഭ്യർത്ഥനയുടെ അബോർട്ട് സിഗ്നൽ ഡൗൺലോഡ്, ബ്രോക്കർ ക്യൂ,
സബ്പ്രോസസുകൾ, ക്യാപ്ഷൻ കോളുകൾ എന്നിവയിലൂടെ പ്രചരിക്കുന്നു; അബോർട്ടുകൾ വീഡിയോകൾക്കിടയിൽ പ്രോസസ്സിംഗ് നിർത്തുകയും
ഒരിക്കലും അസംസ്കൃത മീഡിയയിലേക്ക് ഫെയിൽ ഓപ്പൺ ചെയ്യാതിരിക്കുകയും ചെയ്യുന്നു.

റൺടൈം ക്രമീകരണങ്ങൾ DB-ബാക്ക്ഡ്, Zod-വാലിഡേറ്റഡ് എന്നിവയാണ്:

| കീ                                  | ഡിഫോൾട്ട്   | പരിധി / പെരുമാറ്റം                                                                                                                          |
| ----------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `modalityBridgeVideoEnabled`        | `false`     | ഐച്ഛിക റൺടൈം, വ്യക്തമായി തിരഞ്ഞെടുക്കേണ്ടത്                                                                                                 |
| `modalityBridgeVideoAnalysisMode`   | `"full"`    | `full` പൊതുവായ അടിക്കുറിപ്പുകൾ നിലനിർത്തുന്നു; `focused` പരിധിയുള്ളതും വിശ്വസനീയമല്ലാത്തതുമായ ഏറ്റവും പുതിയ ഉപയോക്തൃ സന്ദർഭം ഉപയോഗിക്കുന്നു |
| `modalityBridgeVideoModel`          | `""`        | Vision Bridge മോഡൽ അനന്തരാവകാശമായി സ്വീകരിക്കുക                                                                                             |
| `modalityBridgeVideoFrameCount`     | `8`         | 1–16                                                                                                                                        |
| `modalityBridgeVideoSamplingPolicy` | `"uniform"` | `uniform`, `scene_aware`, അല്ലെങ്കിൽ ആനുപാതികമായ `segment_aware`; ഡിറ്റക്ടർ പരാജയപ്പെട്ടാൽ `uniform`-ലേക്ക് മടങ്ങും                         |
| `modalityBridgeVideoMaxVideos`      | `1`         | 1–4                                                                                                                                         |
| `modalityBridgeVideoTimeout`        | `120000`    | 1000–120000 ms                                                                                                                              |

മുമ്പ് നിലനിർത്തിയിട്ടുള്ള, 120 സെക്കൻഡിന് മുകളിലുള്ള Video ടൈംഔട്ട് മൂല്യങ്ങൾ
ബ്രോക്കർ സമയപരിധിയിലേക്ക് പരിമിതപ്പെടുത്തുന്നു; ആ പരിധിക്ക് മുകളിലുള്ള പുതിയ ക്രമീകരണ എഴുത്തുകൾ നിരസിക്കപ്പെടും.
`GET /api/modality-bridge/video/runtime`-ന് പ്രാമാണീകരണത്തിനോ റൺടൈം പരിശോധനയ്ക്കോ മുമ്പ്
വിശ്വസനീയമായി സ്റ്റാമ്പ് ചെയ്ത ലൂപ്പ്ബാക്ക് ലോക്കാലിറ്റി ആവശ്യമാണ്; തുടർന്ന് മാനേജ്മെന്റ്
പ്രാമാണീകരണവും ആവശ്യമാണ്. ഇത് `available`, ശുദ്ധീകരിച്ച FFmpeg/ffprobe പതിപ്പുകൾ, റൺടൈം
ലഭ്യമല്ലാത്തപ്പോൾ ഒരു സ്ഥിരമായ കാരണം എന്നിവ മാത്രമാണ് നൽകുന്നത്. ആന്തരിക എക്സ്ട്രാക്ഷൻ എൻഡ്പോയിന്റ്
ഒരു പൊതു അപ്ലോഡ് API അല്ല: ക്യൂ പൂർണ്ണമായാൽ `503`-ഉം `Retry-After`-ഉം നൽകും, കോളർ
വിച്ഛേദിച്ചാൽ `499` നൽകും, സ്ഥിരമായ ബ്രോക്കർ സമയപരിധി എത്തുമ്പോൾ `504` നൽകും. പരിവർത്തനം ചെയ്ത പ്രതികരണങ്ങൾ
Vision അല്ലെങ്കിൽ Audio സെഗ്മെന്റുകൾ നീക്കം ചെയ്യാതെ കേന്ദ്ര
`x-omniroute-modality-bridge` ഹെഡറിലേക്ക് `video->text;model=<visionModel>;parts=<videos>` ചേർക്കുന്നു.

### PII മാസ്കർ (`piiMasker.ts`)

**രണ്ട്** ഘട്ടങ്ങളിലും പ്രവർത്തിക്കുന്നു.

- **`preCall`** പേലോഡ് ക്ലോൺ ചെയ്യുകയും `system`, `messages`, `input`, `prompt`
  എന്നിവയിലൂടെ (സാധാരണ സ്ട്രിംഗ് ഇനങ്ങൾ ഉൾപ്പെടെ) സഞ്ചരിക്കുകയും സ്ട്രിംഗ്
  `content`/`text` ഫീൽഡുകളിൽ (`@/shared/utils/inputSanitizer`-ൽ നിന്നുള്ള)
  `processPII()` പ്രയോഗിക്കുകയും ചെയ്യുന്നു. `PII_REDACTION_ENABLED=true` ആയിരിക്കുമ്പോൾ,
  കണ്ടെത്തിയ PII ഔട്ട്ബൗണ്ട് പേലോഡിൽ മറയ്ക്കപ്പെടുന്നു. ഇത് `INPUT_SANITIZER_MODE`-ൽ നിന്ന്
  സ്വതന്ത്രമാണ് (അത് പ്രോംപ്റ്റ്-ഇൻജക്ഷൻ നയം മാത്രമാണ് നിയന്ത്രിക്കുന്നത്).
  മറയ്ക്കൽ ഓഫായിരിക്കുമ്പോൾ, ഉള്ളടക്കം തിരുത്താതെ കോൾ കണ്ടെത്തലുകളുടെ എണ്ണം രേഖപ്പെടുത്തുന്നു.
- **`postCall`** പ്രതികരണത്തിന്റെ ഡീപ് ക്ലോൺ സൃഷ്ടിച്ച് `sanitizePIIResponse()`-ഉം
  Responses-API രൂപത്തിനുള്ള മാസ്കറും (`maskResponsesOutput` — `output_text`,
  `output[].content[].text` എന്നിവ ഉൾക്കൊള്ളുന്നു) പ്രവർത്തിപ്പിക്കുന്നു. ഏതെങ്കിലും മറയ്ക്കൽ
  നടന്നാൽ, പരിഷ്കരിച്ച പ്രതികരണം യഥാർത്ഥ പ്രതികരണത്തെ മാറ്റിസ്ഥാപിക്കുന്നു.

ഗാർഡ്റെയിൽ ഒരിക്കലും തടയുന്നില്ല; അത് വ്യാഖ്യാനക്കുറിപ്പുകൾ ചേർക്കുക
(`meta.detections`, `meta.redacted`) അല്ലെങ്കിൽ തിരുത്തിയെഴുതുക മാത്രമാണ് ചെയ്യുന്നത്.

### പ്രോംപ്റ്റ് ഇൻജക്ഷൻ (`promptInjection.ts`)

ഉപയോക്താവ് നൽകിയ ഉള്ളടക്കത്തിലെ പ്രതികൂല ഘടനകൾ കണ്ടെത്തുകയും ക്രമീകരിച്ച
നയം നടപ്പാക്കുകയും ചെയ്യുന്നു. പരിസ്ഥിതി വേരിയബിളുകളും കൺസ്ട്രക്ടർ
ഓപ്ഷനുകളുമാണ് പെരുമാറ്റം നിയന്ത്രിക്കുന്നത്:

| ക്രമീകരണം      | എൻവ് വേരിയബിൾ                                                                                               | ഡിഫോൾട്ട് | പ്രഭാവം                                                                                                                                                                                                                               |
| -------------- | ----------------------------------------------------------------------------------------------------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| പ്രവർത്തനക്ഷമം | `INPUT_SANITIZER_ENABLED`                                                                                   | `true`    | `false` ആയിരിക്കുമ്പോൾ, ഗാർഡ്റെയിൽ തുടർനടപടികളില്ലാതെ ഉടൻ മടങ്ങുന്നു.                                                                                                                                                                 |
| മോഡ്           | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                             | `warn`    | ഇൻജക്ഷൻ നയം: `block`, `warn`, അല്ലെങ്കിൽ `log`. (`redact` പിന്നോട്ടുള്ള അനുയോജ്യതയ്ക്കായി സ്വീകരിക്കുന്നു, എന്നാൽ ഇൻജക്ഷൻ ടെക്സ്റ്റ് നീക്കം ചെയ്യില്ല; അഭ്യർത്ഥനയിലെ PII തിരുത്തിയെഴുത്ത് `PII_REDACTION_ENABLED` നിയന്ത്രിക്കുന്നു.) |
| തടയൽ പരിധി     | `blockThreshold` ഓപ്ഷൻ / `INPUT_SANITIZER_BLOCK_THRESHOLD` (`INJECTION_GUARD_BLOCK_THRESHOLD` എന്ന അപരനാമം) | `high`    | തടയുന്നതിന് ആവശ്യമായ ഏറ്റവും കുറഞ്ഞ തീവ്രത. ഡിഫോൾട്ടായി Medium നിരീക്ഷണത്തിന് മാത്രമുള്ളതാണ്.                                                                                                                                         |

**മോഡ് മുൻഗണന** (`getMode`): കോളറിന്റെ `options.mode` →
`INJECTION_GUARD_MODE` **DB ഫീച്ചർ-ഫ്ലാഗ് ഓവർറൈഡ്** (Dashboard → Settings →
Feature Flags) → `INJECTION_GUARD_MODE` എൻവ് → `INPUT_SANITIZER_MODE` എൻവ് →
`warn`. അതിനാൽ ഡാഷ്ബോർഡ് ഓവർറൈഡിന് എൻവ് വേരിയബിളുകളെക്കാൾ മുൻഗണനയുണ്ട്, അതുവഴി Feature
Flags UI പ്രവർത്തിച്ചുകൊണ്ടിരിക്കുന്ന ഗാർഡിനെ തത്സമയം നിയന്ത്രിക്കുന്നു (പുനരാരംഭിക്കേണ്ടതില്ല). DB റീഡ് പരാജയസുരക്ഷിതമാണ്:
അതിൽ പിശക് സംഭവിച്ചാൽ, ഗാർഡ് എൻവ് അധിഷ്ഠിത പെരുമാറ്റത്തിലേക്ക് മടങ്ങും; ഓവർറൈഡ് ഒന്നും
സജ്ജീകരിച്ചിട്ടില്ലെങ്കിൽ പെരുമാറ്റം എൻവ് മാത്രം അടിസ്ഥാനമാക്കിയുള്ള നിർണ്ണയത്തിന് സമാനമായിരിക്കും.

കണ്ടെത്തൽ ഉറവിടങ്ങൾ:

1. `@/shared/utils/inputSanitizer`-ൽ നിന്നുള്ള `sanitizeRequest()` (പൈപ്പ്ലൈനിൽ
   മറ്റിടങ്ങളിലും ഉപയോഗിക്കുന്ന പൊതുവായ ഡിറ്റക്ടർ സെറ്റ്).
2. ബിൽറ്റ്-ഇൻ `DEFAULT_GUARD_PATTERNS` (നിലവിൽ `system_override_inline`,
   `markdown_system_block` എന്നിവ; രണ്ടിനും `high` തീവ്രതയാണ്).
3. കൺസ്ട്രക്ടർ ഓപ്ഷനുകളിലൂടെ നൽകുന്ന ഐച്ഛിക `customPatterns` (സ്ട്രിംഗുകൾ, regex,
   അല്ലെങ്കിൽ `{ name, pattern, severity }` റെക്കോർഡുകൾ).

`mode === "block"` **ആയിരിക്കുകയും** കുറഞ്ഞത് ഒരു കണ്ടെത്തലെങ്കിലും തീവ്രതാ
പരിധി പാലിക്കുകയും ചെയ്യുമ്പോൾ, `preCall` `{ block: true, message: "Request rejected:
suspicious content detected" }` മടക്കിനൽകുന്നു. `warn`/`log` മോഡുകളിൽ ഗാർഡ്റെയിൽ ലോഗ്
ചെയ്യുമെങ്കിലും കോൾ അനുവദിക്കുന്നു. രജിസ്ട്രിയിലൂടെ കടന്നുപോകാതെ പ്രോംപ്റ്റുകൾ
വിലയിരുത്തേണ്ട കോളർമാർക്കായി പങ്കിട്ട ഹെൽപ്പറായ `evaluatePromptInjection()`-ഉം എക്സ്പോർട്ട്
ചെയ്യുന്നു.

**സ്കാൻ പരിധി (v3.8.20):** കൂട്ടിച്ചേർത്ത പ്രോംപ്റ്റ് ടെക്സ്റ്റിന്റെ **ആദ്യത്തെ 16 KB** മാത്രമാണ്
ഡിറ്റക്ടർ പരിശോധിക്കുന്നത് — `src/shared/utils/inputSanitizer.ts`-ൽ
`MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 ബൈറ്റുകൾ). പാറ്റേൺ ലൂപ്പ്
പ്രവർത്തിപ്പിക്കുന്നതിനുമുമ്പ് `detectInjection()`-ഉം `evaluatePromptInjection()`-ഉം
`slice(0, MAX_INJECTION_SCAN_BYTES)` ഉപയോഗിക്കുന്നു. ഇൻജക്ഷൻ നിർദ്ദേശങ്ങൾ ഇൻപുട്ടിന്റെ
തുടക്കത്തിനടുത്തായതിനാൽ, കണ്ടെത്തൽ ദുർബലമാക്കാതെ തന്നെ നൂറുകണക്കിന്-KB വലുപ്പമുള്ള
പേലോഡുകളിലെ regex CPU/GC ഉപയോഗം ഇത് പരിമിതപ്പെടുത്തുന്നു (cf.
#3932, #4041).

### ക്രെഡൻഷ്യൽ മാസ്കർ (`credentialMasker.ts`)

**രണ്ട്** ഘട്ടങ്ങളിലും പ്രവർത്തിക്കുന്നു; ഡിഫോൾട്ട് ചെയിനിൽ ഏറ്റവും അവസാനം (മുൻഗണന `95`).
ഔട്ട്ബൗണ്ട് പേലോഡിൽ (സന്ദേശ ഉള്ളടക്കം, ടൂൾ-കോൾ ആർഗ്യുമെന്റുകൾ, ടൂൾ ഫലങ്ങൾ)
**കൂടാതെ** പ്രൊവൈഡർ റെസ്പോൺസിലും അറിയപ്പെടുന്ന API-key / secret-token പാറ്റേണുകൾ
മറയ്ക്കുന്നു. അതിനാൽ ഒരു പ്രോംപ്റ്റിൽ പേസ്റ്റ് ചെയ്ത ക്രെഡൻഷ്യലോ (അല്ലെങ്കിൽ ഒരു ടൂൾ ഫലം
തിരികെ നൽകിയതോ) അപ്സ്ട്രീം പ്രൊവൈഡറിലേക്കോ ക്ലയന്റിലേക്കോ ചോരുകയില്ല.

- **ഓപ്റ്റ്-ഇൻ മാത്രം**, PII റിഡാക്ഷന്റെ അതേ രീതി (Hard Rule #20-നോട് ചേർന്നത്):
  `settings.credentialRedactionEnabled === true` **അല്ലെങ്കിൽ**
  `CREDENTIAL_REDACTION_ENABLED=true` അല്ലാത്തപക്ഷം പ്രവർത്തനരഹിതമാണ്. ഇത് ഓഫ്
  ആയിരിക്കുമ്പോൾ ഗാർഡ്റെയിൽ ഒരു no-op ആണ് — ഇത് ഒരിക്കലും തടയുകയോ മാറ്റിയെഴുതുകയോ
  ചെയ്യില്ല.
- `redactCredentials()` പൂർണ്ണ പേലോഡ്/റെസ്പോൺസ് ട്രീയിലൂടെ സഞ്ചരിക്കുകയും (`walkValue()`,
  prototype-pollution-സുരക്ഷിതം, `WeakSet` വഴി cycle-സുരക്ഷിതം) പൊരുത്തങ്ങളെ
  `[REDACTED:<type>]` പ്ലേസ്ഹോൾഡർ ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുകയും ചെയ്യുന്നു; യഥാർത്ഥത്തിൽ
  മാറ്റം വന്ന ബ്രാഞ്ചുകൾ മാത്രം ക്ലോൺ ചെയ്യുന്നു.
- `CREDENTIAL_PATTERNS` LLM പ്രൊവൈഡർ കീകൾ (OpenAI, OpenAI-proj,
  Anthropic, Google, Hugging Face, Replicate), VCS/SaaS ടോക്കണുകൾ (GitHub, Slack,
  Linear, Notion, npm, Postman, Discord), പേയ്മെന്റ് കീകൾ (Stripe, Square), ക്ലൗഡ്
  കീകൾ (AWS access key, Twilio, SendGrid, Mailgun), സ്വകാര്യ കീകൾ / JWT-കൾ,
  ക്രെഡൻഷ്യലുകൾ ഉൾക്കൊള്ളുന്ന കണക്ഷൻ സ്ട്രിങ്ങുകൾ (`mongodb://user:pass@...`, മുതലായവ), കൂടാതെ
  പൊതുവായ ഒരു `Authorization`/`x-api-key`/`api-key`/`apikey` ഹെഡർ-മൂല്യ
  പാറ്റേൺ എന്നിവ ഉൾക്കൊള്ളുന്നു. ഹെഡറിന്റെ രൂപത്തിലുള്ള കീകൾ (`authorization`, `x-api-key`, `api-key`,
  `apikey`) പൊതുവായ ടെക്സ്റ്റ് regex വഴിയല്ല, ഘടനാപരമായാണ് (മൂല്യം മാത്രം; `Bearer `/`Basic `
  പോലുള്ള സ്കീം പ്രിഫിക്സ് നിലനിർത്തിക്കൊണ്ട്) മറയ്ക്കുന്നത്.
- ഗാർഡ്റെയിൽ ഒരിക്കലും തടയില്ല; ഇത് മാറ്റിയെഴുതുകയും (`modifiedPayload` /
  `modifiedResponse`) അനോട്ടേറ്റ് ചെയ്യുകയും (`meta.credentialsRedacted`, `meta.count`)
  മാത്രമാണ് ചെയ്യുന്നത്.

റിഗ്രഷൻ ഗാർഡ്: `tests/unit/credential-masker-guardrail.test.ts`.

## അടിസ്ഥാന കരാർ (base.ts)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true short-circuits the chain
  message?: string; // തടയുമ്പോൾ ഇത് ദൃശ്യമാകും
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // അഭ്യർത്ഥന മാറ്റിയെഴുതാൻ preCall തിരികെ നൽകുന്നത്
  modifiedResponse?: TValue; // പ്രതികരണം മാറ്റിയെഴുതാൻ postCall തിരികെ നൽകുന്നത്
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

ഒരു ഗാർഡ്റെയിൽ "മാറ്റമില്ല" എന്ന് സൂചിപ്പിക്കുന്നത് ``void`, `{}`, അല്ലെങ്കിൽ `{ block: false }`തിരികെ നൽകിക്കൊണ്ടാണ്.`modifiedPayload`/`modifiedResponse`തിരികെ നൽകുന്നത്, താഴെയുള്ള ഗാർഡ്റെയിലുകൾക്കായി ചെയിനിലൂടെ ഒഴുകുന്ന മൂല്യത്തെ മാറ്റിസ്ഥാപിക്കുന്നു.`signal?: AbortSignal` കോളർ ലൈഫ്സൈക്കിളിനെ ഗാർഡ്റെയിലുകളിലേക്ക് എത്തിക്കുന്നു. ഒരു അഭ്യർത്ഥന റദ്ദാക്കൽ എന്നത് മനഃപൂർവമായ ഒരു ഫെയിൽ-ഓപ്പൺ അപവാദമാണ്: മീഡിയ ബ്രിഡ്ജുകൾ പ്രവർത്തിക്കുന്നത് നിർത്തുകയും, അസംസ്കൃത മീഡിയയെ പിന്തുണയ്ക്കാത്ത ഒരു ലക്ഷ്യസ്ഥാനത്തേക്ക് പുനഃസ്ഥാപിക്കാതെ വൃത്തിയാക്കുകയും ചെയ്യുന്നു.

## രജിസ്ട്രി (registry.ts)

സിംഗിൾട്ടൺ `guardrailRegistry` താഴെ പറയുന്നവ നൽകുന്നു:

- `register(guardrail)` — ഒരു ഗാർഡ്റെയിൽ ചേർക്കുന്നു (അല്ലെങ്കിൽ സാധാരണമാക്കിയ പേര് ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു) കൂടാതെ ആരോഹണ ക്രമത്തിൽ `priority` അനുസരിച്ച് വീണ്ടും ക്രമീകരിക്കുന്നു.
- `clear()` / `list()` — അഡ്മിനിസ്ട്രേറ്റീവ് സഹായികൾ.
- `runPreCallHooks(payload, context)` — സജീവ ഗാർഡ്റെയിലുകളിലൂടെ ആവർത്തിക്കുന്നു, `modifiedPayload` വഴി പേലോഡിനെ കടത്തിവിടുന്നു, കൂടാതെ ആദ്യത്തെ `block: true` വരുമ്പോൾ നിർത്തുന്നു.
- `runPostCallHooks(response, context)` — പ്രതികരണ ഭാഗത്തും ഇതേ പ്രവാഹം.
- `resetGuardrailsForTests({ registerDefaults })` — നിലവിലെ അവസ്ഥ മായ്ക്കുന്നു കൂടാതെ വൃത്തിയുള്ള ടെസ്റ്റ് ഐസൊലേഷനായി ഡിഫോൾട്ടുകൾ ഓപ്ഷണലായി വീണ്ടും രജിസ്റ്റർ ചെയ്യുന്നു.

രണ്ട് റണ്ണറുകളും `{ blocked, payload|response, results, guardrail?, message? }` തിരികെ നൽകുന്നു, ഇവിടെ `results` എന്നത് `GuardrailExecutionResult` റെക്കോർഡുകളുടെ ഒരു നിരയാണ്, അതിൽ ഓരോ ഗാർഡ്റെയിലിനുമുള്ള `blocked`, `skipped`, `modified`, `error`, `meta` ഫീൽഡുകൾ ഉൾപ്പെടുന്നു, ഇത് ട്രേസിംഗിന് ഉപയോഗപ്രദമാണ്.

### ഓരോ അഭ്യർത്ഥനയ്ക്കും ഗാർഡ്റെയിലുകൾ പ്രവർത്തനരഹിതമാക്കുന്നു

`resolveDisabledGuardrails({ apiKeyInfo, body, headers })` നിലവിലെ അഭ്യർത്ഥനയ്ക്കായി ഒഴിവാക്കേണ്ട ഗാർഡ്റെയിൽ പേരുകളുടെ ഡ്യൂപ്ലിക്കേഷൻ ഒഴിവാക്കിയ ഒരു ലിസ്റ്റ് ശേഖരിക്കുന്നു. ഉറവിടങ്ങൾ (എല്ലാം ഓപ്ഷണൽ, എല്ലാം ലയിപ്പിച്ചത്):

- `apiKeyInfo.disabledGuardrails`
- അഭ്യർത്ഥന ബോഡി `disabledGuardrails` (ടോപ്പ്-ലെവൽ)
- അഭ്യർത്ഥന ബോഡി `metadata.disabledGuardrails`
- ഹെഡർ `x-omniroute-disabled-guardrails` (അല്ലെങ്കിൽ പഴയ `x-disabled-guardrails`)

മൂല്യങ്ങൾ സ്ട്രിംഗുകളുടെ നിരകളോ കോമയാൽ വേർതിരിച്ച സ്ട്രിംഗോ ആകാം; പേരുകൾ ലോവർകേസ് കെബാബ്-കേസിലേക്ക് സാധാരണമാക്കുന്നു (`pii_masker` → `pii-masker`). ഫലം `context.disabledGuardrails` വഴി രജിസ്ട്രിയിലേക്ക് കൈമാറുന്നു, ഇത് പൊരുത്തപ്പെടുന്ന ഗാർഡ്റെയിലുകളെ ഒഴിവാക്കുന്നു (`results`-ൽ `skipped: true`).

## എക്സിക്യൂഷൻ ഓർഡർ

`src/sse/handlers/chat.ts`, `open-sse/handlers/chatCore.ts` എന്നിവയിലൂടെ ഒഴുകുന്ന ഓരോ അഭ്യർത്ഥനയ്ക്കും:

1. `resolveDisabledGuardrails(...)` API കീ, ബോഡി, ഹെഡറുകൾ എന്നിവയിൽ നിന്ന് സ്കിപ്പ് ലിസ്റ്റ് നിർമ്മിക്കുന്നു.
2. `guardrailRegistry.runPreCallHooks(body, ctx)` ഗാർഡ്റെയിലുകൾ ആരോഹണ മുൻഗണനാ ക്രമത്തിൽ പ്രവർത്തിപ്പിക്കുന്നു:
   - പ്രവർത്തനരഹിതമാക്കിയ ഗാർഡ്റെയിലുകൾ `skipped` എന്ന് രേഖപ്പെടുത്തുന്നു.
   - ഓരോ ഗാർഡ്റെയിലിന്റെയും `preCall` `modifiedPayload` വഴി പേലോഡ് മാറ്റിയെഴുതിയേക്കാം.
   - ആദ്യത്തെ `block: true` ചെയിൻ ചുരുക്കുകയും ഹാൻഡ്ലർ ഒരു ഗാർഡ്റെയിൽ നിരസിക്കൽ പ്രതികരണം നൽകുകയും ചെയ്യുന്നു.
3. (സാധ്യതയുള്ള മാറ്റിയെഴുതിയ) പേലോഡ് കോംബോ റൂട്ടിംഗിലേക്കും അപ്സ്ട്രീം ഡിസ്പാച്ചിലേക്കും ഒഴുകുന്നു.
4. പ്രതികരണം കൂട്ടിച്ചേർത്ത ശേഷം, `guardrailRegistry.runPostCallHooks(...)` പ്രതികരണത്തിൽ അതേ ചെയിൻ പ്രവർത്തിപ്പിക്കുന്നു. ഇവിടെ `block: true` അപ്സ്ട്രീം പ്രതികരണം ഒഴിവാക്കുന്നു.

തെറ്റ് വരുത്തുന്ന ഗാർഡ്റെയിലുകൾ `error: <message>` എന്ന് രേഖപ്പെടുത്തുകയും `logger.warn` വഴി ലോഗ് ചെയ്യുകയും ചെയ്യുന്നു, പക്ഷേ ചെയിൻ തുടരുന്നു — രൂപകൽപ്പന പ്രകാരം ഫെയിൽ-ഓപ്പൺ.

## കോൺഫിഗറേഷൻ

ബിൽറ്റ്-ഇൻ ഗാർഡ്റെയിലുകൾ വായിക്കുന്ന എൻവയോൺമെന്റ് വേരിയബിളുകൾ:

| വേരിയബിൾ                              | ഉപയോഗിക്കുന്നത്           | പ്രഭാവം                                                                                                             |
| ------------------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `INPUT_SANITIZER_ENABLED`             | `prompt-injection`        | കണ്ടെത്തൽ പൂർണ്ണമായും പ്രവർത്തനരഹിതമാക്കാൻ `false` എന്ന് സജ്ജമാക്കുക.                                               |
| `INPUT_SANITIZER_MODE`                | `prompt-injection`        | ഇൻജക്ഷൻ പോളിസി: `warn`, `block`, അല്ലെങ്കിൽ `log`. പഴയ മൂല്യം `redact` ഇൻജക്ഷൻ ടെക്സ്റ്റ് മാറ്റിയെഴുതുന്നില്ല.      |
| `INJECTION_GUARD_MODE`                | `prompt-injection`        | ഇൻജക്ഷൻ ഗാർഡിനായുള്ള മോഡ്; എൻവയോൺമെന്റ് വേരിയബിളുകളെ **അസാധുവാക്കുന്ന** ഒരു DB ഫീച്ചർ ഫ്ലാഗ് കൂടിയാണിത് (DB > ENV). |
| `INPUT_SANITIZER_BLOCK_THRESHOLD`     | `prompt-injection`        | `MODE=block` നിരസിക്കുന്ന ഏറ്റവും കുറഞ്ഞ തീവ്രത: `high` (സ്ഥിരസ്ഥിതി), `medium`, അല്ലെങ്കിൽ `low`.                  |
| `INJECTION_GUARD_BLOCK_THRESHOLD`     | `prompt-injection`        | `INPUT_SANITIZER_BLOCK_THRESHOLD` എന്നതിന്റെ പഴയ പേര്.                                                              |
| `PII_REDACTION_ENABLED`               | `pii-masker`              | `true` ആയിരിക്കുമ്പോൾ, അഭ്യർത്ഥന PII റെഡാക്ട് ചെയ്യപ്പെടുന്നു (ഇൻജക്ഷൻ മോഡിൽ നിന്ന് സ്വതന്ത്രമായി).                 |
| `PII_RESPONSE_SANITIZATION` / `_MODE` | `pii-masker` (ഡൗൺസ്ട്രീം) | പ്രതികരണ-വശത്തുള്ള മാസ്കർ സ്വഭാവം നിയന്ത്രിക്കുന്നു.                                                                |

മോഡാലിറ്റി ബ്രിഡ്ജ് ഗാർഡ്റെയിലുകൾ DB-ബാക്ക്ഡ് സെറ്റിംഗ്സ് സ്റ്റോറിൽ നിന്ന് (`getSettings()`) റൺടൈം കോൺഫിഗറേഷൻ വായിക്കുന്നു, എൻവയോൺമെന്റ് വേരിയബിളുകളിൽ നിന്നല്ല. വിഷന്റെ പ്രാഥമിക കീകൾ `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, `modalityBridgeCacheMaxEntries` എന്നിവയാണ്. പഴയ `visionBridge*` കീകൾ ഡോക്യുമെന്റ് ചെയ്ത വൺ-സൈക്കിൾ റീഡ് ഫാൾബാക്കായി മാത്രമേ സ്വീകരിക്കുകയുള്ളൂ; ഡാഷ്ബോർഡ് റൈറ്റുകൾ പ്രാഥമിക കീകൾ ഉപയോഗിക്കുന്നു. സ്ഥിരസ്ഥിതികളും ഫാൾബാക്ക് റെസല്യൂവറും `src/shared/constants/modalityBridgeDefaults.ts` എന്നതിലാണ്, പഴയ സ്ഥിരാങ്കങ്ങൾ `src/shared/constants/visionBridgeDefaults.ts` എന്നതിൽ നിലനിർത്തുന്നു.

ഓഡിയോ `modalityBridgeAudioEnabled`, `modalityBridgeAudioModel`, `modalityBridgeAudioTimeout`, `modalityBridgeAudioMaxClips` എന്നിവയും പങ്കിട്ട `modalityBridgeCache*` ക്രമീകരണങ്ങളും ഉപയോഗിക്കുന്നു. മോഡാലിറ്റി ബ്രിഡ്ജ് സ്കീമയോടൊപ്പം ഈ കീകൾ അവതരിപ്പിച്ചതിനാൽ ഓഡിയോയ്ക്ക് പഴയ-കീ ഫാൾബാക്ക് ഇല്ല.

വീഡിയോ `modalityBridgeVideoEnabled`, `modalityBridgeVideoAnalysisMode`, `modalityBridgeVideoModel`, `modalityBridgeVideoFrameCount`, `modalityBridgeVideoSamplingPolicy`, `modalityBridgeVideoMaxVideos`, `modalityBridgeVideoTimeout` എന്നിവയും പങ്കിട്ട `modalityBridgeCache*` ക്രമീകരണങ്ങളും ഉപയോഗിക്കുന്നു. FFmpeg/ffprobe ഓപ്ഷണൽ ഓപ്പറേഷണൽ ഡിപൻഡൻസികളും ഫ്രെയിം ക്യാപ്ഷനിംഗ് ലേറ്റൻസിയും മോഡൽ ചെലവും വർദ്ധിപ്പിക്കുന്നതിനാൽ ഇത് സ്ഥിരസ്ഥിതിയായി പ്രവർത്തനരഹിതമാക്കിയിരിക്കുന്നു.

## കസ്റ്റം ഗാർഡ്റെയിലുകൾ

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

ഘട്ടങ്ങൾ:

1.  `BaseGuardrail` വികസിപ്പിച്ച് `src/lib/guardrails/myGuardrail.ts` ഉണ്ടാക്കുക.
2.  `preCall`, `postCall` എന്നിവ നടപ്പിലാക്കുക.
3.  ഇറക്കുമതി ചെയ്യുന്ന സമയത്ത് ( `registerDefaultGuardrails` ൽ നിന്ന് പുഷ് ചെയ്യുക) അല്ലെങ്കിൽ റൺടൈമിൽ `guardrailRegistry.register(...)` വിളിക്കുക — രജിസ്ട്രി, അതേ സാധാരണവൽക്കരിച്ച പേരുള്ള മുൻ ഗാർഡ്റെയിലിനെ മാറ്റിസ്ഥാപിക്കും.
4.  `tests/unit/` ന് കീഴിൽ ടെസ്റ്റുകൾ ചേർക്കുക (നിലവിലുള്ള ഉദാഹരണങ്ങൾ: `tests/unit/guardrails-registry.test.ts`, `tests/unit/prompt-injection-guard.test.ts`, `tests/unit/guardrails/visionBridge.test.ts`).

## പരിശോധന

അറിയപ്പെടുന്ന അവസ്ഥയിൽ നിന്ന് ആരംഭിക്കാൻ ടെസ്റ്റുകൾക്കിടയിൽ `resetGuardrailsForTests()` ഉപയോഗിക്കുക. ശൂന്യമായ ഒരു രജിസ്ട്രിയിൽ നിന്ന് ആരംഭിച്ച്, പരിശോധനയിലുള്ള ഗാർഡ്റെയിലുകൾ മാത്രം രജിസ്റ്റർ ചെയ്യാൻ `{ registerDefaults: false }` നൽകുക. വിഷൻ ബ്രിഡ്ജ് ഡിപൻഡൻസി ഇൻജക്ഷൻ (`deps.getSettings`, `deps.callVisionModel`) സ്വീകരിക്കുന്നു; ഓഡിയോ ബ്രിഡ്ജ് ക്രമീകരണങ്ങൾ, കഴിവുകൾ, STT മോഡൽ തിരഞ്ഞെടുക്കൽ, ക്രെഡൻഷ്യൽ പരിശോധനകൾ, ട്രാൻസ്ക്രിപ്ഷൻ എന്നിവയ്ക്കായി സമാനമായ സീമുകൾ നൽകുന്നു. അതിനാൽ, ഡാറ്റാബേസ് അല്ലെങ്കിൽ നെറ്റ്വർക്ക് ആക്സസ് ഇല്ലാതെ തന്നെ ടെസ്റ്റുകൾക്ക് രണ്ട് ഫ്ലോകളും പ്രവർത്തിപ്പിക്കാൻ കഴിയും.

## ഇൻജക്ഷൻ-ഗാർഡ് റൂട്ട് കവറേജ് & റെഡ്-ടീം (ഘട്ടം 8 · ബ്ലോക്ക് D)

ഇൻജക്ഷൻ-ഗാർഡ് (`createInjectionGuard` / `withInjectionGuard`) ഉപയോക്തൃ പ്രോംപ്റ്റുകൾ സ്വീകരിക്കുന്ന എല്ലാ റൂട്ടുകളെയും ഉൾക്കൊള്ളുന്നു. ഇത് `INJECTION_GUARD_MODE` നെ മാനിക്കുന്നു (സ്ഥിരസ്ഥിതി `warn` = ലോഗ് മാത്രം; `block` = HTTP 400 `SECURITY_001` തിരികെ നൽകുന്നു).

| തരം             | റൂട്ടുകൾ                                                                                                                                      | സ്ഥിരസ്ഥിതി മോഡ് |
| :-------------- | :-------------------------------------------------------------------------------------------------------------------------------------------- | :--------------- |
| Text (existing) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                       | warn             |
| Generative      | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn             |
| Data            | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                               | warn             |

ടെക്സ്റ്റ് എക്സ്ട്രാക്ഷൻ (`extractMessageContents`) `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` എന്നിവയെ ഉൾക്കൊള്ളുന്നു.

**റെഡ്-ടീം (രാത്രികാല, `nightly-llm-security.yml`):** `INJECTION_GUARD_MODE=block` ആയിരിക്കുമ്പോൾ ഓരോ റൂട്ടും OWASP-LLM കോർപ്പസിനെ തടയുന്നുവെന്ന് promptfoo സാധൂകരിക്കുന്നു; garak പ്രോബുകൾ പ്രവർത്തിപ്പിക്കുന്നു (രഹസ്യമില്ലാതെ ഒഴിവാക്കുന്നു). സ്ഥിരതയ്ക്കായി `moderations` ഉൾപ്പെടുത്തിയിട്ടുണ്ട് — ബ്ലോക്ക്-മോഡിലുള്ള ഓപ്പറേറ്റർമാർക്ക് `resolveDisabledGuardrails` വഴി ഇതിനെ ഒഴിവാക്കാം.

രാത്രികാല വർക്ക്ഫ്ലോ (`.github/workflows/nightly-llm-security.yml`, cron + മാനുവൽ ഡിസ്പാച്ച്) ന് രണ്ട് ജോലികളുണ്ട്:

- **`promptfoo-guard` (തടയുന്നത്)** — `INJECTION_GUARD_MODE=block` ഉപയോഗിച്ച് `promptfoo eval -c promptfooconfig.yaml` പ്രവർത്തിപ്പിക്കുന്നു. ഓരോ പ്രതികൂല സാഹചര്യവും (ഉദാഹരണത്തിന്, "മുമ്പത്തെ എല്ലാ നിർദ്ദേശങ്ങളും അവഗണിക്കുക...", DAN-ശൈലിയിലുള്ള ജയിൽബ്രേക്കുകൾ) പ്രതികരണത്തിൽ `error.code === "SECURITY_001"` ഉണ്ടെന്ന് ഉറപ്പാക്കുന്നു, അതായത് ഗാർഡ് യഥാർത്ഥത്തിൽ അഭ്യർത്ഥന നിരസിച്ചു.
- **`garak` (ഉപദേശക)** — ഒരു പ്രാദേശിക OmniRoute ഇൻസ്റ്റൻസിനെതിരെ (`http://localhost:20128/v1`) garak `--probes promptinject,dan,leakreplay` പ്രവർത്തിപ്പിക്കുന്നു. ഒരു പ്രൊവൈഡർ രഹസ്യം (`PROMPTFOO_PROVIDER_KEY`) വഴി നിയന്ത്രിക്കപ്പെടുന്നു; ഇത് ഭംഗിയായി ഒഴിവാക്കുകയും `|| true` എന്ന് ചേർക്കുകയും ചെയ്യുന്നു, അതിനാൽ CI പരാജയപ്പെടാതെ റിപ്പോർട്ട് ചെയ്യുന്നു.

ഗാർഡ് ഹെൽപ്പറിന്റെ (`createInjectionGuard` / `withInjectionGuard`) കവറേജ് എല്ലാ പ്രോംപ്റ്റ്-ഉൾക്കൊള്ളുന്ന `/v1` റൂട്ടുകളിലും വ്യാപിക്കുന്നു; പ്രോംപ്റ്റ് ടെക്സ്റ്റ് `src/shared/utils/inputSanitizer.ts` ലെ `extractMessageContents()` വഴി `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` എന്നിവയിൽ നിന്ന് വലിച്ചെടുക്കുന്നു.
