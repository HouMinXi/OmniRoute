## TL;DR — OmniRoute 實際彙整了多少免費推論額度？

這些數字涵蓋目錄中各自獨立的第三方帳戶與資格條件。OmniRoute 本身不會授予這些額度：您必須取得所需的帳戶或憑證、連接符合資格的提供者，並遵守其限制。實際可用容量可能更低；若是全新安裝且沒有符合資格的路由，可用容量甚至可能為零。標記為 `tos: avoid` 的提供者預設不會納入自動路由。

**檢查日期：2026-10-08：** [Cerebras](https://www.cerebras.ai/pricing) 提供一次性的 $5 推廣抵用金，需綁定付款方式，並會在 30 天後到期。[Gemini](https://ai.google.dev/gemini-api/docs/rate-limits) 公布了專案／模型／方案層級的速率限制；它仍未納入量化後的每月主要數字。

## 兩種機制——計數與判定

OmniRoute 透過兩種刻意讀取不同來源的機制來回答「它是免費的嗎？」：

| 機制           | 真實資料來源                                                                                                                                             | 適用介面                                                                                                 |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| **計數／顯示** | 解析後的目錄——隨附的基準資料疊加 Radar 資料來源（`getRadarCatalog`）                                                                                     | 免費方案總量、預算卡片、儀表板                                                                           |
| **判定**       | 僅使用隨附目錄（`open-sse/config/freeModelCatalog.data.ts` 中的 `FREE_MODEL_BUDGETS`），再加上本機啟發式規則（`:free` 後綴、零定價、`grantsFreeAccess`） | `src/shared/utils/freeModels.ts` 的所有取用端：模型匯入、`auto/*` 路由、`GET /v1/models`，以及瀏覽器預覽 |

只要有可用的資料來源，計數結果便能持續改善。判定則維持使用
發行成品，因此瀏覽器與伺服器上的答案完全相同、
可離線重現，且無須資料庫即可測試。若讓瀏覽器
預覽讀取一個來源，而伺服器匯入讀取另一個來源，就會造成
預覽結果與點擊後實際發生的情況不一致——此區分是
刻意保留的。

## 方法與注意事項

- 這些數字是根據各提供者截至 **2026-06-17** 所記載的免費方案限制，透過網路研究整理出的**上限估計值**。免費方案經常變動——依賴任何數字之前，請重新核實。
- **每筆項目實際保證的內容。** 各列都沒有信心評等，API 也不提供——請將上述每個數字都視為品質相同但未明示的估計值。有兩類事實不同，因為它們是人工整理，而不是推論得出：44 筆項目具有獨立記載的硬性停止機制（其中 39 筆是 xKiro 項目，全部共用相同的每日額度），另有 13 筆項目附帶提示詞訓練揭露。只有當提供者自己的條款明確表示，超過免費額度後會拒絕請求，而不是悄悄開始計費時，才會設定 `hardStopGuaranteed`，且來源會寫在該項目旁的註解中；它絕不會預設為 `true`，尚未有人驗證的項目會維持未設定狀態。因此，缺少硬性停止旗標代表「尚未證實」，而不是「已知會向你收費」。**STRICT 模式**（選用的 `freeAccessPolicy=strict` 路由防護）只信任帶有該旗標的項目；其他所有免費方案都會以 `no-hard-stop` 為由排除（請參閱 `open-sse/services/autoCombo/strictZeroCostFilter.ts`）。當防護機制篩選資源池時，操作人員可見的記錄會同時回報排除數量，以及其中 `no-hard-stop` 所占的比例。
- `estMonthlyFreeTokens` = 僅計算每月週期性權杖。**一次性註冊點數不會重複發放**，因此計為 0。已停止的方案也計為 0。
- 每日權杖上限 → `monthly = daily × 30`。僅記載 RPD → `RPD × ~800 output tokens × 30`。僅有 RPM/TPM（沒有每日上限）→ **無上限**（見下文）。
- **永久免費，但沒有公布權杖上限**（`siliconflow`、`glm-cn`、`tencent`、`baidu`、`kilo-gateway`、`opencode-zen`、`gemini`、`ollama-cloud`）：這些確實是持續提供的免費存取，但受速率／並行數限制。我們將其歸類為 `recurring-uncapped`，並且**絕不加總**——用 `RPM × 24/7 × 30d` 相乘只會產生不切實際的理論上限（這正是我們拒絕的膨脹計算法）。列出它們是為了讓你知道這些方案存在。
- **儲值解鎖加成：** 一次性的小額儲值，可永久提高免費額度（OpenRouter：$10 → 每日 1000 次請求 ≈ 每月額外 +24M）。這會以獨立數字回報，不納入穩定額度的標題數字。
- **資格限制額度**（`eligibilityGate: "regional-identity"`）：確實存在的週期性額度，但只有在通過地區綁定的身分驗證後才會開放（目前為中國大陸實名驗證）。依照相同的資源池去重規則計入獨立數字（`gatedRecurringTokens`），絕不納入穩定額度的標題數字。機制（`freeType`）不變，因此路由行為也不變。
- **證據類別。** 規則如下：目錄中的數字會在項目旁的 `// evidence:` 註解中引用其來源——`public-page`（任何人都能閱讀的提供者頁面）、`api-public`（提供者無須驗證即可存取的端點，例如 NaraRouter 位於 router.bynara.id 的公開方案端點），或 `console-verified <date> por <who>`（該數字只能在帳戶主控台中查看；註解會記錄查看者與查看日期，以及指出該上限確實存在的公開頁面）。目前狀態：於 2026-09-02 重新稽核的五個區塊都帶有此資訊（`gemini`、`groq`、`mistral`、`ollama-cloud`、`nara`）；早於 2026-09-02 重新稽核的項目，在被修改前會沿用較早期的研究結果；任何**新增或變更**的數字若沒有證據註解，即屬錯誤。目前只有 `mistral` 經過主控台驗證。

## 為什麼我們的數字比其他彙整服務的小

這個領域中，大多數「每月免費 token」數字，都是將各模型標示的額度加總而成。我們刻意不這麼做：

- **每個共用額度池只計算一次。** Mistral 的免費方案是每個組織每月共用 1B 額度；將它列在五個模型下並不會使其變成 5B。若按模型加總，我們自己的目錄會顯示為 **~7.4B**（於 2026-09-03 重新計算；此數字不受 CI 檢查管控——每當目錄變更時都應重新測量）——標題顯示 **~1.47B**，因為這才是各提供者各一個帳號實際可使用的額度。
- **每日上限會換算，速率限制則不會。** 有明確文件記載的每日 token 上限會換算為 `× 30`；有明確文件記載的每日請求上限會換算為 `RPD × ~800 tokens × 30`；若提供者只公布每分鐘請求數，則**不會**計算每月數字，並會列為_無上限_，永不納入加總。將速率限制乘以 24/7，正是我們拒絕採用的灌水方式。
- **需要區域身分驗證才能取得的配額會另外顯示**（`+~6M behind regional identity verification`），因為大多數讀者無法使用這些配額。
- **註冊贈送額度僅適用於首月**，並會作為第二個數字回報，絕不與穩定的常態數字混合。
- **此數字由 CI 強制驗證。** `npm run check:docs-counts` 會根據目錄重新計算總額；當此檔案、README 或預算卡片中的數字與計算結果不一致時，建置便會失敗。

## 詞彙表

| 術語                    | 含義                                                          |
| ----------------------- | ------------------------------------------------------------- |
| **RPM / RPD / RPH**     | 每分鐘／每日／每小時的請求數                                  |
| **TPM / TPD**           | 每分鐘／每日的 Token 數                                       |
| **Documented grant**    | 提供者公布明確的每日／每月 Token 上限（可作為可靠依據的預算） |
| **Theoretical ceiling** | `rate-limit × 24/7 × 30d` — 最大值，而非獲授予的預算          |
| **Neuron**              | Cloudflare 運算單位（約等於 1 個輸出 Token）                  |
