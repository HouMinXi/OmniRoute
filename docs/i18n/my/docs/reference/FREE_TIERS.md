> **အသုံးပြုသူများအတွက်**: ရိုးရှင်းသော လမ်းညွှန်ကို ရှာနေပါသလား။ အခမဲ့ AI ရယူရန် အဆင့်ဆင့်ညွှန်ကြားချက်များအတွက် [အခမဲ့အဆင့်များ လမ်းညွှန်](../getting-started/FREE-TIERS-GUIDE.md) ကို ကြည့်ပါ။

> **နောက်ဆုံး သုတေသနပြုထားသည့်ရက်:** 2026-06-17 — ဝန်ဆောင်မှုပေးသူတစ်ခုချင်းအလိုက် ဝဘ်သုတေသန (တရားဝင်စာရွက်စာတမ်းများ + နောက်ဆုံး 7 ရက်အတွင်း သတင်းများ၊ ဆန့်ကျင်ဘက်မှ စစ်ဆေးအတည်ပြုသည့် 50-agent pass) ဖြင့် အခမဲ့အဆင့် quota နှင့် ToS အားလုံးကို ပြန်လည်မွမ်းမံထားသည်။ **တစ်စိတ်တစ်ပိုင်း ပြန်လည်စစ်ဆေးမှု 2026-09-02** (`gemini`, `ollama-cloud`, `groq`, `nara`, `mistral` — အောက်ပါ ရက်စွဲပါမှတ်ချက်ကို ကြည့်ပါ)။
> **အမှန်တကယ်အတည်ပြုရမည့် မူလရင်းမြစ် (catalog):** `open-sse/config/freeModelCatalog.ts` (MODEL တစ်ခုချင်းအလိုက် budget များ၊ pool အထပ်များကို ဖယ်ရှားထားသည်)။ အောက်ပါ token-budget ကိန်းဂဏန်းများသည် လက်ရှိ ဝဘ်သုတေသနမှ ရရှိထားပြီး **ခန့်မှန်းချက်** မျှသာဖြစ်သည် — [နည်းလမ်းနှင့် သတိပြုရန်အချက်များ](#methodology--caveats) ကို ကြည့်ပါ။

## TL;DR — OmniRoute သည် အမှန်တကယ် အခမဲ့ inference မည်မျှ စုစည်းပေးသနည်း။

ဤကိန်းဂဏန်းများသည် catalog တစ်လျှောက်ရှိ သီးခြား ပြင်ပအဖွဲ့အစည်း account များနှင့် အကျုံးဝင်မှုဆိုင်ရာ သတ်မှတ်ချက်များကို ဖော်ပြထားသည်။ OmniRoute က ဤ budget ကို ပေးအပ်ခြင်းမရှိပါ။ လိုအပ်သော account သို့မဟုတ် အထောက်အထားများကို သင်ကိုယ်တိုင် ရယူရမည်၊ အကျုံးဝင်သော ဝန်ဆောင်မှုပေးသူများကို ချိတ်ဆက်ရမည်ဖြစ်ပြီး ၎င်းတို့၏ ကန့်သတ်ချက်များကို လိုက်နာရမည်။ အကျုံးဝင်သော route မရှိသည့် အသစ်တပ်ဆင်ထားသော စနစ်တွင် သုညဖြစ်နိုင်ခြင်းအပါအဝင် အမှန်တကယ် အသုံးပြုနိုင်သော ပမာဏသည် ပိုနည်းနိုင်သည်။ `tos: avoid` ဟု သတ်မှတ်ထားသော ဝန်ဆောင်မှုပေးသူများကို ပုံသေသတ်မှတ်ချက်အရ အလိုအလျောက် routing မှ ဖယ်ထုတ်ထားသည်။

**2026-10-08 တွင် စစ်ဆေးထားသည်:** [Cerebras](https://www.cerebras.ai/pricing) သည် ငွေပေးချေမှုနည်းလမ်းတစ်ခု လိုအပ်ပြီး ရက် 30 အကြာတွင် သက်တမ်းကုန်ဆုံးမည့် တစ်ကြိမ်သုံး $5 ပရိုမိုးရှင်း credit ကို ပေးသည်။ [Gemini](https://ai.google.dev/gemini-api/docs/rate-limits) သည် project/model/tier အလိုက် rate limit များကို ထုတ်ပြန်ထားသော်လည်း ပမာဏတွက်ချက်ထားသည့် လစဉ်အဓိကကိန်းဂဏန်းတွင် မပါဝင်သေးပါ။

## နည်းလမ်းနှင့် သတိပြုရန်အချက်များ

- ကိန်းဂဏန်းများသည် **2026-06-17** ရက်နေ့အထိ provider တစ်ခုစီ၏ မှတ်တမ်းတင်ထားသော free-tier ကန့်သတ်ချက်များမှ web research ဖြင့် စုဆောင်းရရှိထားသည့် **အများဆုံးဖြစ်နိုင်ခြေ ခန့်မှန်းချက်များ** ဖြစ်ပါသည်။ Free tier များသည် အမြဲပြောင်းလဲနေသောကြောင့် ကိန်းဂဏန်းတစ်ခုကို အားကိုးမည်ဆိုပါက ဦးစွာ ပြန်လည်စစ်ဆေးပါ။
- **Entry တစ်ခုက အမှန်တကယ် အာမခံပေးသည့်အရာ။** Entry တစ်ခုချင်းစီတွင် confidence rating မပါဝင်သကဲ့သို့ API ကလည်း ထိုအချက်ကို မပေးပါ — အထက်ပါ ကိန်းဂဏန်းတိုင်းကို ဖော်ပြမထားသော တူညီသည့် အရည်အသွေးအဆင့်ရှိသော ခန့်မှန်းချက်အဖြစ် သတ်မှတ်ပါ။ သို့သော် အချက်နှစ်ချက်မှာ ခန့်မှန်းထားခြင်းမဟုတ်ဘဲ လူကိုယ်တိုင် စိစစ်ထည့်သွင်းထားသောကြောင့် ကွဲပြားပါသည်- entry 44 ခုတွင် သီးခြားမှတ်တမ်းတင်ထားသော hard stop ပါရှိပြီး (ထိုအထဲမှ 39 ခုသည် တစ်ရက်စာ allowance တစ်ခုတည်းကို မျှဝေသည့် xKiro row များဖြစ်သည်)၊ entry 13 ခုတွင် prompt-training disclosure ပါရှိပါသည်။ Provider ၏ ကိုယ်ပိုင်စည်းမျဉ်းများတွင် အခမဲ့ allowance ကို ကျော်လွန်ပါက အသံတိတ်၍ ငွေစတင်ကောက်ခံခြင်းအစား request ကို ငြင်းပယ်မည်ဟု ဖော်ပြထားသည့်အခါမှသာ `hardStopGuaranteed` ကို သတ်မှတ်ပြီး၊ entry ဘေးရှိ comment တွင် source ကို ထည့်သွင်းထားပါသည်။ ၎င်းကို `true` အဖြစ် မည်သည့်အခါမျှ default မသတ်မှတ်သကဲ့သို့ မည်သူမျှ အတည်မပြုရသေးသော entry သည်လည်း unset အဖြစ်သာ ရှိနေပါသည်။ ထို့ကြောင့် hard-stop flag မရှိခြင်းသည် "မသတ်မှတ်နိုင်သေး" ဟု ဆိုလိုခြင်းဖြစ်ပြီး "ငွေကောက်ခံမည်ဟု အတည်ပြုထား" ခြင်းမဟုတ်ပါ။ **STRICT mode** (ရွေးချယ်ဖွင့်ရသော `freeAccessPolicy=strict` routing guard) သည် flag ပါသော entry များကိုသာ ယုံကြည်ပါသည်။ အခြား free tier အားလုံးကို `no-hard-stop` အဖြစ် ဖယ်ထုတ်ပါသည် (`open-sse/services/autoCombo/strictZeroCostFilter.ts` ကို ကြည့်ပါ)။ Guard က pool တစ်ခုကို filter လုပ်သည့်အခါ operator မြင်နိုင်သော log တွင် ဖယ်ထုတ်ထားသည့် အရေအတွက်နှင့် ထိုအထဲမှ `no-hard-stop` ၏ အချိုးနှစ်မျိုးလုံးကို ဖော်ပြပါသည်။
- `estMonthlyFreeTokens` = လစဉ် ထပ်တလဲလဲ ရရှိသော token များသာ။ **တစ်ကြိမ်သာရသော signup credit များသည် ထပ်မံမရရှိသောကြောင့်** 0 အဖြစ် ရေတွက်ပါသည်။ ရပ်ဆိုင်းပြီးသော tier များကိုလည်း 0 အဖြစ် သတ်မှတ်ပါသည်။
- နေ့စဉ် token cap → `monthly = daily × 30`။ RPD ကိုသာ မှတ်တမ်းတင်ထားပါက → `RPD × ~800 output tokens × 30`။ RPM/TPM သာရှိပြီး နေ့စဉ် cap မရှိပါက → **ကန့်သတ်ချက်မရှိ** (အောက်တွင် ကြည့်ပါ)။
- **အမြဲတမ်းအခမဲ့ဖြစ်သော်လည်း ထုတ်ပြန်ထားသော token cap မရှိခြင်း** (`siliconflow`, `glm-cn`, `tencent`, `baidu`, `kilo-gateway`, `opencode-zen`, `gemini`, `ollama-cloud`)- ယင်းတို့သည် rate/concurrency ဖြင့် ကန့်သတ်ထားသော အမှန်တကယ် ထပ်တလဲလဲရရှိသည့် အခမဲ့ access များဖြစ်ပါသည်။ ၎င်းတို့ကို `recurring-uncapped` ဟု အမျိုးအစားသတ်မှတ်ပြီး **မည်သည့်အခါမျှ စုစုပေါင်းထဲ ထည့်မတွက်ပါ** — `RPM × 24/7 × 30d` ဟု မြှောက်ခြင်းသည် စိတ်ကူးယဉ် ceiling တစ်ခုကို ဖြစ်ပေါ်စေမည်ဖြစ်ပြီး ယင်းကဲ့သို့ ဖောင်းပွမှုကို ကျွန်ုပ်တို့ လက်မခံပါ။ ၎င်းတို့ အမှန်တကယ်ရှိကြောင်း သိနိုင်ရန် စာရင်းတွင် ထည့်သွင်းဖော်ပြထားပါသည်။
- **Deposit-unlock boost:** အခမဲ့ quota ကို အမြဲတမ်း တိုးမြှင့်ပေးသည့် တစ်ကြိမ်သာထည့်ရသော ပမာဏအနည်းငယ်ရှိသည့် top-up (OpenRouter: $10 → 1000 req/day ≈ +24M/mo)။ သီးခြားကိန်းဂဏန်းအဖြစ် အစီရင်ခံပြီး ပုံမှန်အဓိကကိန်းဂဏန်းတွင် မထည့်သွင်းပါ။
- **အရည်အချင်းပြည့်မီမှုဖြင့် ကန့်သတ်ထားသော quota များ** (`eligibilityGate: "regional-identity"`)- ဒေသနှင့် ချိတ်ဆက်ထားသော identity check ကို ပြီးမြောက်မှသာ ဖွင့်ပေးသည့် အမှန်တကယ် ထပ်တလဲလဲရရှိသော quota ဖြစ်ပါသည် (လက်ရှိတွင် တရုတ်ပြည်မကြီး real-name verification)။ တူညီသော pool-dedupe စည်းမျဉ်းဖြင့် သီးခြားကိန်းဂဏန်း (`gatedRecurringTokens`) ထဲသို့ ရေတွက်ပြီး ပုံမှန်အဓိကကိန်းဂဏန်းထဲသို့ မည်သည့်အခါမျှ မထည့်ပါ။ စနစ် (`freeType`) သည် မပြောင်းလဲသောကြောင့် routing လည်း မပြောင်းလဲပါ။
- **အထောက်အထား အမျိုးအစားများ။** စည်းမျဉ်းမှာ catalog ရှိ ကိန်းဂဏန်းတစ်ခုသည် entry ဘေးရှိ `// evidence:` comment တွင် ၎င်း၏ source ကို ကိုးကားရမည်ဖြစ်သည် — `public-page` (မည်သူမဆို ဖတ်ရှုနိုင်သည့် provider page)၊ `api-public` (provider ၏ authentication မလိုသော endpoint၊ ဥပမာ router.bynara.id ရှိ NaraRouter ၏ public plans endpoint)၊ သို့မဟုတ် `console-verified <date> por <who>` (ကိန်းဂဏန်းကို account console အတွင်း၌သာ မြင်နိုင်သည်၊ comment တွင် မည်သူက မည်သည့်အချိန်တွင် မြင်ခဲ့သည်ကို မှတ်တမ်းတင်ထားပြီး cap ရှိကြောင်း ဖော်ပြသည့် public page ကိုပါ ထည့်သွင်းထားသည်)။ လက်ရှိအခြေအနေမှာ 2026-09-02 တွင် ပြန်လည်စစ်ဆေးထားသော block ငါးခုတွင် ၎င်းပါရှိသည် (`gemini`, `groq`, `mistral`, `ollama-cloud`, `nara`)။ 2026-09-02 ပြန်လည်စစ်ဆေးမှုမတိုင်မီက entry များသည် ပြင်ဆင်မွမ်းမံသည့်အချိန်အထိ အစောပိုင်း research ကို ဆက်ခံပါသည်။ Evidence comment မပါသော **အသစ် သို့မဟုတ် ပြောင်းလဲထားသည့်** ကိန်းဂဏန်းမှန်သမျှသည် bug တစ်ခုဖြစ်ပါသည်။ လက်ရှိတွင် `mistral` တစ်ခုတည်းသာ console-verified ဖြစ်ပါသည်။

## ကျွန်ုပ်တို့၏ ကိန်းဂဏန်းသည် အခြား aggregator များ၏ ကိန်းဂဏန်းထက် အဘယ်ကြောင့် ပိုငယ်သနည်း

ဤနယ်ပယ်ရှိ "တစ်လလျှင် အခမဲ့ token များ" ဆိုသည့် ကိန်းဂဏန်းအများစုသည် model တစ်ခုချင်းစီအတွက် ဖော်ပြထားသော ပမာဏများကို ပေါင်းထားခြင်းဖြစ်သည်။ ကျွန်ုပ်တို့၏ ကိန်းဂဏန်းမှာမူ ရည်ရွယ်ချက်ရှိရှိ ထိုသို့ မလုပ်ထားပါ-

- **မျှဝေသုံးစွဲသည့် pool တစ်ခုစီကို တစ်ကြိမ်သာ ရေတွက်ထားသည်။** Mistral ၏ အခမဲ့အစီအစဉ်သည် organization တစ်ခုလျှင် တစ်လ 1B ခွင့်ပြုချက်တစ်ခုသာဖြစ်သည်။ ၎င်းကို model ငါးခုအောက်တွင် စာရင်းပြုစုခြင်းဖြင့် 5B ဖြစ်မသွားပါ။ model အလိုက် ပေါင်းလျှင် ကျွန်ုပ်တို့၏ကိုယ်ပိုင် catalog သည် **~7.4B** ဟု ဖော်ပြမည်ဖြစ်သည် (2026-09-03 တွင် ပြန်လည်တွက်ချက်ထားသည်။ ဤကိန်းဂဏန်းကို CI ဖြင့် ထိန်းချုပ်ထားခြင်းမရှိပါ — catalog ပြောင်းလဲသည့်အခါတိုင်း ပြန်လည်တိုင်းတာပါ) — headline တွင် **~1.47B** ဟု ဖော်ပြထားခြင်းမှာ provider တစ်ခုစီ၏ account တစ်ခုက အမှန်တကယ် သုံးစွဲနိုင်သည့်ပမာဏ ဖြစ်သောကြောင့်ဖြစ်သည်။
- **နေ့စဉ်ကန့်သတ်ချက်များကို ပြောင်းလဲတွက်ချက်ပြီး rate များကိုမူ မပြောင်းလဲပါ။** စာရွက်စာတမ်းတွင် ဖော်ပြထားသော tokens/day ကန့်သတ်ချက်ကို `× 30` အဖြစ် ပြောင်းလဲတွက်ချက်သည်။ စာရွက်စာတမ်းတွင် ဖော်ပြထားသော requests/day ကန့်သတ်ချက်ကို `RPD × ~800 tokens × 30` အဖြစ် ပြောင်းလဲတွက်ချက်သည်။ requests-per-minute သာ ထုတ်ပြန်ထားသည့် provider တွင် လစဉ်ကိန်းဂဏန်း **မရှိဘဲ** _uncapped_ ဟု စာရင်းပြုစုထားကာ ပေါင်းစုပမာဏထဲသို့ လုံးဝမထည့်ပါ။ rate limit ကို 24/7 ဖြင့် မြှောက်ခြင်းသည် ကျွန်ုပ်တို့ လက်မခံသော ကိန်းဂဏန်းဖောင်းပွမှုဖြစ်သည်။
- **ဒေသဆိုင်ရာ identity စစ်ဆေးမှုနောက်ကွယ်ရှိ quota များကို သီးခြားဖော်ပြထားသည်** (`+~6M behind regional identity verification`)၊ အကြောင်းမှာ စာဖတ်သူအများစုက ၎င်းတို့ကို အသုံးမပြုနိုင်သောကြောင့်ဖြစ်သည်။
- **Signup credit များသည် ပထမလအတွက်သာဖြစ်ပြီး** ဒုတိယကိန်းဂဏန်းအဖြစ် သီးခြားဖော်ပြထားကာ ပုံမှန်ဆက်လက်ရရှိမည့် ကိန်းဂဏန်းထဲသို့ လုံးဝရောမထည့်ပါ။
- **ဤကိန်းဂဏန်းကို CI ဖြင့် ထိန်းချုပ်ထားသည်။** `npm run check:docs-counts` သည် catalog မှ စုစုပေါင်းပမာဏများကို ပြန်လည်တွက်ချက်ပြီး ဤဖိုင်၊ README သို့မဟုတ် budget card တို့ရှိ ကိန်းဂဏန်းများနှင့် ကွဲလွဲပါက build ကို မအောင်မြင်စေပါ။

## ToS သတိပြုရန်ဇယား

> **ToS flag သည် အကြံပြုသတိပေးချက်သာဖြစ်ပြီး routing gate မဟုတ်ပါ။** `tos` ဟု သတ်မှတ်ထားသော provider များကို ပုံသေအားဖြင့် routing နှင့် combo/fallback တို့တွင် ဆက်လက်ထည့်သွင်းထားသည်။ flag ကို `/dashboard/free-tiers` နှင့် `/api/free-tier/summary` တို့တွင်သာ ဖော်ပြသည်။ `excludeTosAvoid` query parameter သည် summary view ကိုသာ သက်ရောက်ပြီး global routing ကို မသက်ရောက်ပါ။ သတ်မှတ်ချက်သည် `open-sse/config/freeTierCatalog.ts` တွင် ရှိသည် (အချက်အလက်ပေးရန်သာဖြစ်ပြီး routing engine များက မဖတ်ပါ)။

> self-hosted, single-user personal proxy တစ်ခုအတွက် provider တစ်ခုစီ၏ စည်းကမ်းချက်များကို အမြန်သုံးသပ်ထားခြင်းဖြစ်သည်။ `caution` = စစ်ဆေးသင့်သော ကိုယ်ရေးကိုယ်တာအသုံးပြုမှု သို့မဟုတ် proxy ဆိုင်ရာ အပိုဒ်တစ်ခုရှိခြင်း၊ `ambiguous` = မရှင်းလင်းခြင်း၊ `ok` = ပြတ်သားစွာ ခွင့်ပြုထားခြင်း။ အချက်အလက်ပေးရန်သာဖြစ်ပြီး ဥပဒေအကြံဉာဏ်မဟုတ်ပါ — သင်ကိုယ်တိုင် ဆုံးဖြတ်ရမည်။

### ⚠️ သတိပြုရန် — စစ်ဆေးသင့်သော ကိုယ်ရေးကိုယ်တာအသုံးပြုမှု / proxy ဆိုင်ရာ အပိုဒ်များ (16)
